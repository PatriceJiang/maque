## 2. 组件设计约定（所有类别必须遵守）

1. **反射 POD + 固定布局**：字段由 `schema/` 描述，`static_assert(sizeof==size)`（docs/06）。
2. **只放数据 + 句柄/引用**：
   - 引用一律用**句柄**：`entity_ref`、`asset_ref<T>`（存句柄，序列化为稳定 ID/路径）。
   - **禁止**裸指针、`std::` 容器、隐式所有权。
3. **字段属性（attrs）**：`transient`（不序列化、运行时派生）、`ref`（引用目标类型）、`range`、`unit`、`readonly`、`deprecated`。
4. **确定性**：不引入墙钟/系统熵；随机走引擎 RNG；字段更新顺序确定（docs/10）。
5. **单一职责 / 组合优于继承**：不同"能不能 2D/3D"由挂哪个组件决定，不由类型层级（docs/12 §3）。
6. **模块归属**：组件由对应模块解释（如 `Collider` 属 physics，`Sprite` 属 renderer），但**布局中立**、可被反射统一读写。

## 3. 每组件条目的记录格式

每个组件按如下结构设计：

- **归属模块 / 上游文档**
- **说明**（语义、何时挂、与谁配对）
- **依赖类型 / enum**
- **字段表**：`字段 | 类型 | 默认 | attrs | 说明`
- **句柄/引用**
- **生命周期 / 确定性**
- **序列化**（哪些 transient、稳定 ID 表示）

## 4. 依赖与配对关系（速览）

- `Sprite / MeshRenderer` 需要 `Transform2D / Transform3D`。
- `Collider / CharacterBody / Area / Joint` 需要 `RigidBody`（或静态体语义）。
- `Animator / Skeleton / TileMap` 需要对应**资产引用**（`asset_ref`）。
- `Script` 是**行为入口**，暴露属性经反射写入同级组件。
- `AudioListener / Camera` 为**全局/单例语义**（每实例建议唯一，由校验保证）。

## 画布与分辨率策略（`ui.Canvas`）

**问题**：同一份 UI 要跑在不同窗口尺寸、不同显示器（DPI/刘海）上，排版不能靠"窗口多大就画多大"。

**模型**（三段式，职责单一）：

```
设计分辨率（480x270，游戏/UI 的参考坐标系）
   │  ui.Canvas：fit_mode + align + 安全区 + 缩放限幅        ← 坐标映射（纯函数）
   ▼
屏幕 drawable（设备像素；HiDPI 下 > 逻辑尺寸）
   │  scn.Scene.render_scale（默认 1；MAQUE_RENDER_SCALE 覆盖）
   ▼
渲染目标（drawable × render_scale）
   │  同尺寸：直接写 swapchain；不同尺寸：条件 blit
   ▼
屏幕
```

| 字段 | 语义 |
|------|------|
| `design_width/height` | 设计分辨率（0 → 取场景 width/height，向后兼容） |
| `fit_mode` | `None`（1:1）· `FitWidth` · `FitHeight` · `ShowAll`（等比 + 留边，默认）· `NoBorder`（铺满 + 裁剪）· `Exact`（非等比拉伸） |
| `align` | 留边/裁剪时画布在绘制区中的对齐（Begin/Center/End） |
| `dpi_scale` | 是否让绘制区跟随显示器内容缩放（HiDPI；`SDL_WINDOW_ALLOW_HIGHDPI`） |
| `min_scale/max_scale` | 缩放限幅（0 = 不限；防极端 DPI 下 UI 过小/过大） |
| `render_scale` | 旧场景兼容入口；规范字段是 `scn.Scene.render_scale`，倍率相对屏幕设备像素，不相对设计尺寸 |
| `scale`/`scale_x/y`、`offset_x/y`、`viewport_w/h`、`window_w/h`、`device_scale`、`safe_*` | **解析结果（transient）**：每帧写回，脚本/控制面可读 |

**实现要点**：

- 策略数学在独立模块 `modules/ui/canvas`（`mq_canvas_resolve` 等**纯函数**，独立单测）：
  可用区 = 绘制区 − 安全区；`scale = policy(设计, 可用区)`；`offset` 由 align 决定；限幅后重新居中/对齐。
- **三方共用同一份映射**（否则必然错位）：
  1. **渲染**：Canvas 的 `(offset, viewport)` 转成目标像素 viewport/scissor；内容直接在正确屏幕位置光栅化；
  2. **输入**：窗口设备像素 → 设计坐标（`mq_canvas_window_to_design`，含留边与裁剪）→ 再翻 y 到世界坐标；
  3. **文字**：`device_scale = design→target` → 字形按目标设备字号栅格化（pixel-perfect，docs/13）。
- 主目标分辨率独立于 Canvas：窗口下为 `drawable × scn.Scene.render_scale`，默认倍率 1；无窗口时以设计尺寸
  作为虚拟屏幕。Camera viewport 只选择目标中的子矩形，不负责分配主目标。
- `Exact` 的 `scale_x/scale_y` 分别进入 2D view uniform；ShowAll/FitWidth/FitHeight/NoBorder 保持等比。
- **每帧解析**（纯函数开销可忽略）：脚本/控制面运行时改 `fit_mode`/`design_*`/安全区立即生效；
  窗口缩放、换显示器（`SDL_WINDOWEVENT_DISPLAY_CHANGED`）自然被覆盖。
- **无窗口（headless/CI）**：虚拟屏幕取设计尺寸（多视图横向并排）；`render_scale` 只改变实际输出像素数，不改变设计布局。

**脚本可见**：`screen_w()/screen_h()`（设计分辨率）、`window_w()/window_h()`（设备像素）、
`canvas_scale()/canvas_scale_x/y()`、`canvas_offset_x/y()`、`canvas_device_scale()`、`canvas_safe_area(edge)`。

**环境变量（宿主/CI）**：`MAQUE_DPI_SCALE=2`（模拟 HiDPI）、`MAQUE_SAFE_AREA="l,t,r,b"`（模拟刘海内缩）。

**验证**：`tests/canvas_e2e.sh` —— 4:3 窗口留边、2× 整数缩放无留边、竖屏大留边、
窗口点击 → 世界坐标（含留边与 y 翻转）命中按钮、安全区收缩、
运行中切换 fit（ShowAll→FitWidth→NoBorder）立即生效；策略数学另由 `ctest -R canvas` 覆盖。

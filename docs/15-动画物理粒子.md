# 15 · 动画 / 物理 / 粒子

> 上游：`12`（世界/双视图）、`10`（确定性）、`07`（内存/句柄）、`06`（反射）、`13`（渲染）。
> 三者均为**世界层模块**：运行在**模拟线程、固定步长、确定**前提下（ADR-0005/0018）。
> 权威数据在**节点树/组件**；世界层模块消费每帧展平出的实体视图（文档 12 §4）。

## 1. 共同约束

- **固定步长**：三者的推进都以模拟 dt 驱动（文档 10 D1）。
- **引擎 RNG**：随机只走实例 RNG（文档 10 D2），禁系统熵。
- **帧内无异步**：资源（骨骼/网格/贴图）经 VFS 预加载（文档 04）。
- **只读共享输入**：模拟 →（动画/物理/粒子）→ 提取 → 渲染，**渲染不回写**（文档 13 §8）。
- **组件化**：`Animator` / `RigidBody` / `Collider` / `ParticleEmitter` 均为**反射组件**（文档 06），挂在实体上。

## 2. 动画（Animation）

- **两类**：
  - **属性轨道（property tracks）**：对任意反射字段做关键帧（位置/颜色/自定义字段）。
  - **骨骼动画（skeletal）**：层级变换 + 蒙皮。
- **混合与状态**：状态机 / blend tree，**求值确定**（无时间依赖的随机混合）。
- **求值**：在模拟步内按 dt 采样，结果写回组件（确定）。
- **渲染插值**：渲染帧率 ≠ 模拟帧率时，对**只读快照**做插值（不污染模拟状态，文档 13 §8）。
- **资产**：关键帧/骨骼以**文本**入库（可 diff，文档 08）。

## 3. 物理（Physics）

- **确定性优先**：物理是回放最容易漂移的环节，规则最严（文档 10 §6）。
  - **固定步长** + 固定迭代次数 + **确定性求解器**；
  - **禁止**用非确定线程/非确定排序；接触求解按 **id 稳定排序**。
- **实现选择（ADR-0028）**：**集成 Rapier（Rust）**。
  - 经 **C ABI FFI** 封装为独立 `physics` 模块（文档 02 规则：只暴露 C ABI、句柄、分配者释放）。
  - **跨语言边界**：Rust↔C++ 只走 C ABI，不共享 C++ 类型；异常不得越界。
  - **确定性需实测**：Rapier 的求解顺序/浮点需在 L1（同构建同平台）下验证（文档 10 §6）；不达标则退化为自研求解器。
  - Rapier 有 **WASM 构建**，贴合 WASM 目标；嵌入式需评估体积。
- **数据**：刚体/碰撞体为**反射组件**（挂在节点上）；层级来自节点的 `parent`（文档 12）。
- **相位**：`physics_process(dt)` 独立于 `process(dt)`（文档 12 §6）。
- **渲染插值**：用前两物理状态插值（**只读**）。

### 3.1 坐标约定与重力符号（权威；2026-10 实测修订）

**一句话**：物理世界**就是**世界坐标 —— **y 向上**。所以"屏幕向下"= 世界 **−y** = 重力**取负**。

| 量 | 约定 | 屏幕含义 |
|----|------|----------|
| 节点/实体位置 y（`scn.Transform2D.y`、`node_set_position`、`entity_set_pos`、`spawn_ball`） | 世界坐标，**y 向上** | `y=0` = 屏幕**下沿**，`y=H` = 屏幕上沿 |
| 渲染映射 | `y_screen = H − y_world`（`H` = 渲染目标高；`runtime.cpp` 展平时翻一次） | 世界 y 变大 = 屏幕上移 |
| `scn.Scene.gravity_y` | 重力加速度的 **y 分量**（像素/秒²），**默认 −900** | **负 = 向下掉**；正 = 向上加速（反重力） |
| `mq_physics_config.gravity_y` | 同上；runtime **原样透传**（不取反） | 默认 −900 |
| `mq_physics_set_bounds(w, min_x, min_y, max_x, max_y)` | 四条静态平面；`min_y` = **y 小**的一侧 | `min_y` = 屏幕**下沿**，`max_y` = 屏幕上沿 |
| DYNAMIC 体活动范围 | `x ∈ [min_x+ext_x, max_x−ext_x]`，`y ∈ [min_y+ext_y, max_y−ext_y]`；`ext` = BALL 的 `radius` / CUBOID 的 `half_w`,`half_h` | 边界是**世界矩形**，不是"地面"：球停在 `y = radius`，不是 `y = 0` |
| runtime 装配 | `set_bounds(0, 0, W, H)`（W/H = 场景 `width`/`height`） | `y=0` 是地面线，`y=H` 是天顶 |
| 接触法线 | 恒为 **a → b**（`a_index < b_index`）；平面接触 `b_index = MQ_PHYSICS_PLANE_INDEX`，法线是**内向**的（把体推回世界内部） | `min_y` 平面 → `(0,−1)`；`max_y` → `(0,+1)`；`min_x` → `(−1,0)`；`max_x` → `(+1,0)` |

**"我要让一个物体在屏幕上往下掉"——确切写法**：

```jsonc
{
  "width": 320, "height": 240,
  // 省略 gravity_y 即默认 -900（向下掉）；要更重写 -1600，要反重力写 +900
  "entities": [
    // 地面放屏幕下沿：y 小 = 屏幕低处（中心 y=12、半高 12 → 占满 y∈[0,24] 那条带）
    { "name": "ground", "components": [
        { "type": "scn.Transform2D", "x": 160, "y": 12 },
        { "type": "scn.Sprite", "half_w": 160, "half_h": 12 },
        { "type": "physics.RigidBody", "body_type": "BodyType::Static" },
        { "type": "physics.Collider", "shape_type": "ShapeType::Box",
          "half_extents": { "x": 160.0, "y": 12.0, "z": 0.5 } } ] },
    // 物体放屏幕上方的位置：y 大 = 屏幕高处
    { "name": "bird", "components": [
        { "type": "scn.Transform2D", "x": 84, "y": 200 },
        { "type": "scn.Sprite", "radius": 9 },
        { "type": "physics.RigidBody", "body_type": "BodyType::Dynamic" },
        { "type": "physics.Collider", "shape_type": "ShapeType::Circle",
          "radius": 9.0, "restitution": 0.0 } ] }
  ]
}
```

- 脚本里同样：`entity_y(id)` 越大越靠屏幕上方；`spawn_ball(x, y, vx, vy, r)` 的 `vy < 0` = 向屏幕**下方**移动；
  按一下"扇翅膀"就 `entity_set_pos`/速度加法给一个 **正** 的 vy 冲量。
- 弹性/摩擦的来源（**实测**，2026-10）：① 脚本 `spawn_ball` 建的球取 `scn.Scene.restitution`（默认 0.86）+ 固定 `friction = 0.2`；
  ② **组件体**（`physics.RigidBody` + `physics.Collider`）目前由 runtime 装配时**写死** `restitution = 0.5`、`friction = 0.2`
  —— 实测把 `Collider.restitution` 从 `0.0` 改成 `0.95`（球与地面都改），逐帧位置/速度轨迹**完全一致**
  （`runtime.cpp` 的 `physics_components_setup` 把这两个字段读进了局部变量却没写进 `mq_physics_body_desc`）。
  所以"落地即停"目前只有脚本 `spawn_ball` + `scene.restitution = 0` 这条路；组件体的 `restitution/friction` 暂不生效。
- ⚠️ 离散窄相**无 CCD**：单帧位移超过碰撞体厚度会隧穿 → 薄地面要么加厚，要么用小速度/固定步长约束（已知限制）。

**复现实验（实测数值，2026-10）**

1. 边界四平面的实际位置（runtime，场景 320×240、无重力、`restitution: 0`、半径 8 的球、初速 ±120 px/s，`spawn_ball` 建体 + 脚本每帧 `physics_step()`）：

   ```
   [game] EXP-B f40 A=(80.00,8.00) B=(160.00,232.00) C=(312.00,120.00) D=(8.00,120.00)
   ```

   → 朝 −y 的球被挡在 **y = 8.00 = min_y(0) + r**；朝 +y 的被挡在 **y = 232.00 = max_y(240) − r**；
   x 两侧 8.00 / 312.00。即 **`min_y` 平面在 y 小的一侧（屏幕下沿）**，`max_y` 在 y 大的一侧（屏幕上沿）。
   平面接触法线：`min_y → (0.00,−1.00)`、`max_y → (0.00,+1.00)`、`max_x → (1.00,0.00)`、`min_x → (−1.00,0.00)`。

2. 世界 y 与屏幕行的对应（同一实验第 60 帧截图 `--shot`，320×240）：

   | 球的世界坐标 | 屏幕像素行 | 中心行 |
   |--------------|-----------|--------|
   | (80, 8) | 224–239 | 231.5 |
   | (160, 232) | 0–15 | 7.5 |

   → `y_screen = H − y_world`：**世界 y 越大越靠屏幕上方**，世界 `y=0` 是屏幕**底行**。

3. 重力方向（同一个球 + 静态盒：盒中心 y=100、半高 20 → 上面 y=120；球从 y=200 落下，`Collider.restitution=0`）：
   - `"gravity_y": -900`（= 默认）：`[game] EXP-G f30 ball=(160.00,139.25)` → `f60 ball=(160.00,128.38)`，
     接触 `floor<->ball n=(0.00,1.00)`，停在 **y=128 = 120 + 8**（盒的**上面**）。
   - **历史缺陷（本次修复）**：旧默认值是 **+900**（`scn.yaml` 注释写"y 向下"，与实际相反）→ 实测 `f0 ball y=150.2 v=+15`
     → `f12 y=172.0` 撞到 y=200 架子的**下表**面；空场景里球停在 **y=232**（= 屏幕**顶部**）。即"默认重力把物体推向屏幕上沿"。
     现已把默认改为 **−900**、注释与 ABI 文档同步纠正；`modules/world/physics/tests/physics_test.cpp` 的
     `test_coordinate_convention` / `test_bounds_sides` / `test_scene_fall_onto_floor` 钉住上述全部数值。

   跑法（不需要额外场景）：`ctest --test-dir build -R physics --output-on-failure`；
   想看运行期逐帧数值：`MAQUE_HEADLESS=1 MAQUE_TRACE_PHYSICS=1 MAQUE_MAX_FRAMES=60 \
   ./build/samples/player/maque_player scenes/contact/contact.scn`（打印 `[phys] fN eID@(x,y)v(vx,vy) contacts=…`）。

> 未覆盖（本次未改）：`scn.ParticleEmitter.gravity` 是**独立**字段（不进物理世界，`runtime.cpp` 里
> `p.vy += gravity * dt`）；`scn.Scene.gravity_y` 只影响 `mq_physics_*` 世界。


## 4. 粒子（Particle）

- **CPU 粒子**：确定（走引擎 RNG），参与回放；适合逻辑相关粒子。
- **GPU 粒子**（compute）：高性能，但**可能不确定** → **仅作视觉**，**排除出模拟确定性**（文档 10）。
- **发射器**：`ParticleEmitter` 组件；粒子本身进**专用数组**（不进实体表）。
- **预算**：粒子数上限 + 池化（文档 07 §8）。

## 5. 与场景树的关系（单一模型 + 派生视图）

- **唯一模型**：节点树 + 组件（发射器、骨骼、碰撞体都是节点上的组件）。
- **运行期**：每帧展平世界坐标后，物理按组件角色建体/迭代，动画按角色推进；粒子走**专用数组**
  （与文档 12 §4 一致：树是权威，视图是派生；高基数不进实体表）。

## 6. 观测

- 各系统耗时 / 实体数 / 碰撞对数 / 粒子数 → 指标（文档 09 §3）。
- 物理 desync 是最常见回放失败源 → 用 doc 10 的 checksum 二分定位到"物理帧"。

## 7. 遗留风险

| 风险 | 处理 |
|------|------|
| 物理非确定 | 固定步长 + 稳定排序；**Rapier 确定性需实测**，不达标退回自研（ADR-0028） |
| Rust↔C++ FFI 边界 | 只走 C ABI + 句柄；禁 C++ 类型/异常越界（文档 02） |
| 渲染帧率 ≠ 模拟帧率 抖动 | 只读插值，不回写模拟 |
| GPU 粒子破坏回放 | 仅视觉，排除出确定性 |
| 高基数拖慢节点树 | 专用数组（粒子）/ 批量存储（§5） |
| 资源加载卡帧 | VFS 预加载 + 异步隔离（帧内无异步） |
| 骨骼/蒙皮开销 | 实例化 + GPU 蒙皮（按平台评估） |

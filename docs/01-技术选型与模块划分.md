# 01 · 技术选型与模块划分

> 上游：`00-设计哲学与约束.md`。本文固化语言/运行时选型，并给出模块分层与依赖方向。
> 原则：**模块尽量解耦，各自编译为 `.so`；依赖方向单向向下。**

## 1. 技术选型清单

| 领域 | 选型 | 备注 |
|------|------|------|
| 语言 | **C++23**（+ C / ASM） | 见 00 §8，ADR-0012 |
| 构建 | CMake ≥ 3.15 | 导出 `compile_commands.json` |
| 渲染 | **WebGPU** | 唯一渲染后端，不再叠加第二层图形抽象 |
| 模块形态 | 独立 **`.so`** | 跨边界 **C ABI + 句柄** |
| 脚本 | **quickjs 为主**（内部 refcount）；lua / python / v8 可选 | **构建期可裁剪**，仅打包所选 VM |
| 存储 | persistence = 序列化中枢：`codec × backend` | 单一内存表示，可无损转任意格式 |
| 异步 | coroutine 作者层 + executor/reactor，**libuv** 首选 | 接口隔离，嵌入式可换极简 reactor |
| 物理 | **Rapier（Rust）**，经 **C ABI FFI** | 独立 `physics` 模块；Rust↔C++ 只走 C ABI（ADR-0028） |

## 2. 模块清单（按用途分组）

- **基础**：`math`、`core`（data / 反射 / 句柄）
- **运行时**：`executor`（任务/作业调度）、`async filesystem`（网络+）
- **数据**：`persistence`（多模态）、`ai`（资产管线，见 §4）
- **世界**：`scene`、`animation`、`physics`、`particle`
- **呈现**：`renderer/gfx`（WebGPU）
- **脚本**：`script`（quickjs / lua / python / v8）
- **诊断/控制**：`observability`、`control plane`（见文档 06、08）

## 3. 依赖分层与方向

依赖**只能向下**（上层依赖下层，下层不得反向依赖）：

```
                 ┌─────────────────────────────────────────────┐
  控制/诊断层 →  │ observability · control plane               │
                 ├─────────────────────────────────────────────┤
  脚本层     →   │ script (quickjs/lua/python/v8)              │
                 ├─────────────────────────────────────────────┤
  呈现层     →   │ renderer/gfx (WebGPU)                       │
                 ├─────────────────────────────────────────────┤
  世界层     →   │ scene · animation · physics · particle      │
                 ├─────────────────────────────────────────────┤
  数据层     →   │ persistence(多模态) · ai(资产管线)          │
                 ├─────────────────────────────────────────────┤
  运行时层   →   │ executor · async filesystem(network+)       │
                 ├─────────────────────────────────────────────┤
  基础层     →   │ core(data/反射/句柄) · math                 │
                 └─────────────────────────────────────────────┘
```

设计约定：

- 下层**绝不** `#include` 上层头文件；跨层通信走下层的抽象接口 / 事件。
- 世界层各模块（scene/animation/physics/particle）**互不直接依赖**，通过 scene 的句柄 + 反射中介。
- `renderer` 不认识 scene 的具体存储，只消费"可序列化的绘制描述"。

## 4. AI 资产管线（`ai` 模块）

独立、可脱离完整引擎运行的工具链，供 AI / CI 驱动：

1. **独立加载 `.scn`**：不启动运行时即可解析场景文件。
2. **计算依赖**：构建资产依赖图（引用关系）。
3. **binary 打包**：将资产编译为二进制包。
4. **压缩**：打包产物压缩。
5. **dump 数据**：输出机器可读（JSON/文本）的数据快照，供 AI 检查与 diff。

> 该模块是 A1（可自省）与 A2（可观测）在**构建期**的落点，与运行时反射共享同一套 schema 描述。

## 5. 风险与必须正面处理的问题

| 风险 | 说明 | 归属 |
|------|------|------|
| **跨 `.so` ABI 脆弱** | C++ ABI 不稳定；异常/RTTI/模板跨边界危险 | OD-4，文档 02 |
| **跨边界内存所有权** | 一个 `.so` 分配、另一个释放 = 崩溃。必须"分配者释放"或传 allocator | 文档 02、04 |
| **嵌入式 WebGPU 驱动** | 目标板可能无 Vulkan/Metal/D3D12；需评估降级路径 | OD-3，文档 10 |
| **脚本 GC 时机** | refcount 处理不了环引用；cycle GC 时机不确定，威胁回放 | OD-5，文档 07、11 |
| **异步 ⇄ 确定性** | libuv 完成顺序不确定，威胁回放 | 文档 10 |
| **第三方物理（Rust）** | Rapier 确定性需实测；跨语言 FFI 边界 | 文档 15、文档 02 |
| **coroutine 帧分配** | 每帧 coroutine frame 堆分配开销，需自定义 allocator/HALO | 文档 04、07 |
| **模块爆炸** | 模块过细会放大 ABI 与调度开销 | 文档 02 |

## 6. 开放问题

- **OD-3**：嵌入式是否需要 WebGPU 之外/之下的降级路径？
- **OD-4**：跨 `.so` 是否强制"C ABI + 句柄 + 分配者释放"，禁用跨边界异常/RTTI？
- **OD-5**：refcount 下 cycle GC 的触发时机如何与固定步长对齐？（已定向：帧内禁止隐式 GC）
- **OD-6**：**已澄清** —— 多存储后端 + 内存数据任意格式转换（序列化中枢，ADR-0011）。
- **OD-7**：是否升 C++23（`std::stacktrace` 等）？需评估嵌入式工具链。

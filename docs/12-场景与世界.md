# 12 · 场景与世界

> 上游：`06`（反射中枢）、`02`（句柄/ABI）、`00 §6`（三层解耦）、ADR-0003（双模式）、ADR-0018（单线程）。
> 本文综合两派：借鉴 **Godot** 的「场景 = 节点」统一，借鉴 **Unity** 的「脚本即组件 + 生命周期」，
> 但全部做**数据化重释**，并收敛为**单一模型**（节点树）+ 每帧展平的**派生视图**。

## 1. 核心结论

1. **Scene = Node = Prefab**：三者是同一数据形态（一棵子树资产）的不同用途，不是三个类。
2. **节点是反射记录，不是 C++ 类**：`{ id, type_id, properties, parent, children[] }`，用**组合**代替继承。
3. **单一模型 + 派生视图**：编辑/编排/调试/运行**都是同一棵节点树**；世界坐标与绘制项是每帧从树**展平**出的缓存（不引入 ECS/archetype 存储）。
4. **混合 2D/3D/UI**：维度由**组件**决定，不由节点基类决定；渲染用**分层**。
5. **生命周期确定化**：借鉴 Unity 的回调集，但在固定点、按确定顺序调用。

## 2. 三概念合一

| 概念 | 本质 |
|------|------|
| **节点 Node** | 树上一条反射记录：`{ id, type_id, properties, parent, children[] }` |
| **场景 Scene** | 被保存的**子树**资产（可序列化，文档 08） |
| **Prefab** | 带**局部覆盖**的场景（实例引用 + override 列表） |

- 任何节点子树都可**存成场景**；场景根就是一个节点；场景可**实例化**进另一棵树（嵌套）。
- 存储形态与文档 06 的反射描述完全一致 → 天然可自省、可序列化、可被 AI 读写。

## 3. 节点 = 反射记录 + 组合

**场景文件里的组件带 `type` 判别符**，由反射按类型名反序列化（异构组件）：

```json
{ "name": "ball",
  "components": [
    { "type": "scn.Transform2D", "x": 160, "y": 200 },
    { "type": "scn.Sprite", "radius": 16, "texture": "ball.png" }
  ],
  "children": [ ... ] }
```

- 实体 = `name` + 一组**带 `type` 的组件**（+ `children` 子节点）。
- 加载时按 `type` 查反射描述符 → 反序列化到该组件的类型化存储；渲染只从 `Sprite` 组件提取。
- 因此同一节点可**自由组合**不同组件（Sprite/Camera/…），按类型区分——这正是组件的意义。


- 节点携带 `type_id`（反射类型）+ 一组**能力组件**（transform / renderable / script / collider…）。
- **禁止 OOP 继承**（不做 `Node3D extends Node`）。"是 2D/3D" = 挂了 `Transform2D`/`Transform3D` 组件。
- 组件挂载**用句柄**（`{id, generation}`，文档 02/06），可跨场景引用；**非内联值**（分叉 1 结论）。

## 4. 单一模型：节点树（+ 派生视图）

```
   唯一模型（编辑 = 运行）                         派生（每帧重算，不落盘）
   ┌───────────────────────┐  flatten_world()   ┌──────────────────────────────┐
   │ 节点树 (Node Tree)     │ ─────────────────▶ │ 实体视图：world_x/y（缓存）    │
   │ 结构 / 编排 / 调试 / 玩法│                    │  ──提取──▶ 绘制项（排序/剔除）  │
   └───────────────────────┘                    └──────────────────────────────┘
```

- **节点树**：人类、AI、编辑器、脚本都友好；可嵌套、可隔离调试（"任意子树可当独立对象开发/调试"）。
- **组件是反射记录**（`type_id → blob`），语义由**角色**（`role: sprite/transform/…`）驱动：
  渲染 / 物理 / UI 都按角色遍历，不认具体类型名（docs/17）。
- **派生视图**：`Scene::flatten_world()` 每帧把局部 Transform 展平为 `world_x/y`（供渲染/物理/命中），
  再由组件提取出绘制项。它们**不是权威数据**、不参与序列化（快照只存组件与节点属性，载入后重算）；
  顺序确定（根/子按 id 升序）→ 与校验和、回放一致（docs/10）。
- **硬边界（取代"bake 为 ECS"）**：节点树**不作高基数承载**。粒子等高频数据用**专用数组**
  （`std::vector<Particle>`，实现即如此）；将来若需要，可在"热路径层"换 archetype/批量存储 ——
  那只是派生视图的存储优化，模型不变（ADR-0003 2026-10 修订）。

## 5. 混合 2D / 3D / UI

- 维度由组件决定，一棵树可自由混合。
- **渲染分层**：根级 `layer` / `viewport`（对应 Godot 的 `CanvasLayer` / `Viewport`）：
  2D 图层、3D 世界、UI 层**各有相机与坐标**。
- 结论：**UI 与 3D 图层可独立开发、独立调试**——它们只是不同的子树 + 不同的渲染层。

## 6. 生命周期（借鉴 Unity，确定化）

借鉴 Unity `MonoBehaviour` 的生命周期，但由引擎在**固定点**、**确定顺序**调用：

```
on_enter_tree → ready → [ process(dt) | physics_process(dt) ]* → on_exit_tree → on_destroy
```

- 顺序：**深度优先 + 声明顺序**，全局确定。
- 脚本 VM（文档 14）只**注册回调**，不自调度。
- 对齐 ADR-0005 / ADR-0018 / OD-5：帧内**禁止隐式 GC**、禁止阻塞、禁止发起异步（文档 04 §6）。

## 7. 实例化与嵌套

> ⚠️ 本节描述的是**目标设计**；当前实现只有 prefab（`.prefab.json`）的节点数据展开，被嵌套文件的脚本/生命周期/
> 事件作用域均不生效。行为归属与嵌套场景的重新设计见 [`32-场景实例与事件作用域`](32-场景实例与事件作用域.md)。

**一期（默认）**：实例化 + 引用重绑。

- 实例化 = 拷贝子树 + 重新生成 id + **重绑内部引用**（指向本实例内）+ 外部引用走句柄。
- 嵌套场景允许；**禁止循环实例化**（A 含 B 含 A），加载期检测并报错。
- 序列化用**稳定 ID / 路径**表示引用（文档 06 §3）。

**二期（延后）**：Prefab 局部覆盖（override 列表 / variant）。分叉 2 结论：先做实例化，override 缓上。

## 8. 与其它系统的接缝

| 系统 | 关系 |
|------|------|
| 反射（06） | 节点/组件即反射类型；属性面板、绑定、dump 全自动 |
| 序列化（08） | 场景资产 = 序列化的子树；codec 即对描述的 visitor |
| 脚本（14） | 生命周期回调解绑；绑定由反射生成 |
| 渲染（13） | 分层消费"可序列化绘制描述"，不认识节点存储细节 |
| AI（09/11） | 可 dump/编辑任意子树；孤立子树即可调试单元 |
| 内存（07） | 句柄世代、组件存储、展平视图的布局 |

## 9. 遗留风险

| 风险 | 处理 |
|------|------|
| 节点树高基数性能 | 硬边界 + 专用数组/批量存储（§4） |
| 嵌套/循环实例化 | 加载期检测；外部引用走句柄 |
| 引用重绑遗漏 | 序列化用稳定 ID；实例化后统一重绑并校验 |
| OOP 习惯回潮（继承节点） | 组件组合 + 评审禁止继承节点基类 |
| 双视图语义漂移 | 单一编辑期真相（节点树）+ 单向 bake |
| prefab override 复杂度 | 二期，先用实例化+重绑 |

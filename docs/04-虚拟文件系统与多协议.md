# 04 · 虚拟文件系统、多协议与挂载

> 上游：`01`（运行时层 async filesystem 模块）、`02`（provider 为 C ABI 模块）。
> 本文定义 **VFS**：统一路径空间 + 可挂载的多协议后端。它位于 persistence / 资产管线**之下**，是其 IO 底座。

## 1. 目标

- 引擎能像浏览器一样**按 URL 加载游戏**：`https://microgames.org/xxx`、`ftp://...`、`file://...`。
- 内部可**提前挂载目录 / 包**：
  ```js
  fs.mount("assets/",        "http://cdn.example.com/assets/");
  fs.mount("assets/musics",  "./musics.zip/musics");
  fs.mount("assets/",        "./assets/");   // 本地开发
  ```
- 对上层（资源、持久化、脚本）呈现**单一、稳定的路径空间**，屏蔽协议与来源差异。

## 2. 战略含义（需确认）

"像浏览器一样加载游戏" + 已选 **WebGPU** + **quickjs**，三者合起来指向一个可能：
**maque 也许要能编译到 WASM、在浏览器里运行并加载远程游戏。**
若成立，这会把"嵌入式"和"Web"统一到同一套 WebGPU 后端上。

> 记为 **OD-8：是否以浏览器（WASM）为正式目标平台？** 影响 VFS、渲染、控制平面多篇文档。

## 3. 核心抽象：Provider（协议后端）

VFS = **挂载点树**，每个挂载点由一个 **Provider** 支撑。Provider 就是实现某协议的 `.so` 模块，
接口形态沿用文档 02 的 **C ABI + 版本化 vtable**：

```c
typedef struct mq_fs_provider_v1 {
    uint32_t struct_size;
    uint32_t abi_version;
    const char* scheme;                 /* "file" "http" "ftp" "zip" "mem" "res" */
    int  (*mount)(void* host, const char* spec, void** out_prov);
    void (*unmount)(void* prov);
    int  (*stat)(void* prov, const char* path, mq_stat* out);
    int  (*open)(void* prov, const char* path, uint32_t mode, void** out_stream);
    /* 异步读：返回 coroutine 任务句柄 */
    int  (*read_async)(void* prov, void* stream, void* buf, size_t n, void** out_task);
    int  (*write)(void* prov, void* stream, const void* buf, size_t n);
    int  (*readdir)(void* prov, const char* path, mq_dir_cb cb, void* ud);
    int  (*readdir_async)(void* prov, const char* path, void** out_task);
} mq_fs_provider_v1;
```

## 4. 协议清单

| scheme | 来源 | 备注 | 优先级 | 现况 |
|---|---|---|---|---|
| `file://` | 本地磁盘 | 开发与部署基础 | P0 | ✅ 实现（挂载 + 直读） |
| `res://` | 编译进二进制的资源 | 嵌入式/无盘场景 | P0 | ✅ 实现（别名 + `builtin:`） |
| `mem://` | 内存 | 测试、生成数据、AI dump | P0 | ✅ 实现（挂载 + 命名空间） |
| `zip://` / `archive://` | 归档包（随机访问中央目录） | 与 `ai` 打包产物对接 | P0 | ✅ 实现（stored 项） |
| `http(s)://` | 远程 | **Range 请求 + 缓存 + 流式** | P1 | 🟡 **目录挂载已实现**（libcurl；Range/流式待做） |
| `ftp://` | 远程（遗留） | 兼容需求，安全性差，低优先级 | P2 | ⬜ |
| `data://` | 内联 base64 | 场景内嵌小资源 | P2 | ⬜ |

**`http(s)` 目录挂载**（已实现，`modules/io/vfs`）：

```c
mq_vfs_mount(vfs, "/", "https://cdn.example.com/game/");   // 目录基址挂到挂载点
mq_vfs_read(vfs, "/main.scn", &d, &n);                     // → GET https://cdn.example.com/game/main.scn
```

- 相对路径**逐段 percent-encode**（空格/中文/保留字安全）；`..` 段与反斜杠一律拒绝（§9）。
- HTTP 状态码映射错误码：`404/410 → MQ_VFS_ERR_NOTFOUND`，其余 `4xx/5xx → MQ_VFS_ERR_IO`；
  重定向跟随（≤5 跳）、连接/整体超时保护、`Accept-Encoding` 自动解压、`NOSIGNAL`。
- **会话内内容缓存**（单条 ≤32 MiB、总量 ≤256 MiB）：同一 URL 只走一次网络 →
  装载期可复现、CI 友好（磁盘级缓存见 §8 待做）。
- 未链接 libcurl 时挂载返回 `MQ_VFS_ERR_UNSUPPORTED`（构建期裁剪明确报错，不静默降级）。
- 运行时入口：`maque_player http://host/game.scn`（整局游戏经 HTTP 加载）或
  `MAQUE_MOUNT="/cdn=https://cdn.example.com/assets/"`（额外挂载；后挂载优先，可遮蔽场景目录，
  是"远程游戏 + 本地覆盖"的开发迭代路径）。远程场景不支持文件监视热重载（无本地文件可 watch）。

## 5. 挂载语义

- **最长前缀匹配**解析路径 → 决定用哪个 Provider。
- **嵌套挂载**：`assets/musics` 可覆盖 `assets/` 下的一子树。
- **优先级 / 遮蔽**：同前缀多个挂载按注册顺序（后挂载优先）或显式优先级；
  同一 `(挂载点, 来源)` 重复挂载为幂等（不堆积）。
- **Provider 配置**：每个挂载实例自带配置（如 http 的 base URL、鉴权头、缓存策略）；
  http(s) 的鉴权头 / 自定义请求参数尚未暴露（二期）。
- **只读 / 读写**：远程与归档默认只读；`file://`/`mem://` 可读写。
- `fs.mount` / `fs.unmount` 是**冷路径**操作，可在运行时执行（利于热重载与 AI 操作）；
  当前经 C ABI（`mq_vfs_mount`）与 `MAQUE_MOUNT` 环境变量可达，脚本级 `fs.*` 待补（§10）。

## 6. 与异步 / executor 的关系

- IO **一律异步**（coroutine，ADR-0010），Provider 返回 awaitable。
- 冷路径可提供**同步封装**（阻塞等待），但**禁止在模拟线程上使用**（破坏确定性与帧时间）。
- **确定性约束**：异步完成顺序不确定 → 资产的**加载**异步化，但**不得在模拟帧内触发异步**；
  回放时若加载时序影响行为，则把完成顺序纳入记录（与文档 08 对齐）。

## 7. 与持久化的关系（正交，且 VFS 在下）

文档 01 的分层里，VFS 是"运行时层"，persistence/资产在"数据层"之上。因此：

- **persistence 的 backend（file/memory/network/zip）应建立在 VFS 之上**，不再各自实现 IO。
  即：`serialize(data, codec, vfs_path)`，backend 由路径 scheme 决定。
- 这样**一处挂载，处处可达**：序列化、资产加载、脚本读取共享同一路径空间。

## 8. 缓存与打包

- 远程（http）必须有**本地缓存**：离线可玩、CI 可复现、AI 可断点续测。
- 现状：**会话内内容缓存**（进程内存，单条 ≤32 MiB / 总量 ≤256 MiB，命中即不再发请求）；
  **磁盘级缓存（内容寻址 + 失效策略）待做** —— 当前 CI 复现靠"本地 HTTP 服务器 + 同一内容"，
  离线可玩需要落盘缓存。
- `ai` 模块的 binary 打包产物就是一种归档，可被 `archive://` Provider 直接挂载。

## 9. 安全（远程加载 = 攻击面）

- **路径穿越防护**（`../` 越界）在 VFS 层统一拦截。
- **内容哈希校验**（ADR-0030）：远程资产/游戏按**内容寻址**验证完整性；**暂不引入签名链**（作者身份二期）。
- **能力限制**：远程内容不得触发本地任意执行（capability 门控 + 脚本沙箱，无原生 exec）。

## 10. AI 可用性结合

- VFS 是天然的**可观测点**：记录所有 IO、延迟、缓存命中、失败（A2）。
- AI 可**dump 挂载树、枚举任意路径、读取任意资源**（A1，全部可序列化）。
- `mem://` 与 dump 让 AI 可以**无副作用地造数据、验数据**。

## 11. ABI 与 WASM 边界

- Provider 是 `.so` 模块（文档 02），C ABI。
- **若**以 WASM/浏览器为目标（OD-8），Provider 可能由 JS 实现 →
  接口必须能跨 **JS/WASM 边界** 调用。这要求接口只含 POD 与函数指针，**正好符合文档 02 的约束**。

## 12. 遗留风险

| 风险 | 处理 |
|------|------|
| 远程加载延迟影响帧时间 | 异步 + 缓存 + 预取；模拟帧内不阻塞 |
| 挂载遮蔽语义易错 | 最长前缀 + 显式优先级 + 单测 |
| 归档随机访问内存开销 | 只读中央目录，按需解压 |
| 多协议一致性 | 统一 `stat/open/read/readdir` 语义与错误码 |

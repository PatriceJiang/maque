# 00 · 设计哲学与约束

> 本文是整套设计文档的根。后续所有文档都必须能追溯到这里的目标与约束；
> 若某篇文档与本文冲突，以本文为准，或先修订本文。

## 1. 一句话定位

**maque 是一个"可被 AI 自主驱动与观测"的轻量游戏引擎，同时服务嵌入式场景与独立游戏。**

它不是又一个 Unity/Godot，而是一个**把自身暴露成服务**的引擎：GUI 只是它的消费者之一，
AI（以及 CI、脚本、人）才是第一等使用者。

## 2. 目标场景（Target）

1. **嵌入式 / 小体积工具**：headless 优先，无强制 GUI，运行时占用可控。
2. **独立游戏**：功能性够用，迭代快，单人/小团队可持续开发。
3. **高 AI 可用**：AI 能自主 **加载、调试、预览、采集 crash 与性能信息**。

## 3. 非目标（Non-goals）

明确写下"不做"，避免架构被无限拉扯：

- 不追求 AAA 级画面与超大数据集吞吐（够用即可，不为极端性能牺牲可观测性）。
- 不强制 GUI 编辑器作为开发入口（GUI 是可选消费者）。
- 不绑定单一平台/单一渲染后端（但要为嵌入式留裁剪空间）。

## 4. 五条 AI 可用性硬指标

这是 maque 区别于普通引擎的核心。任何子系统设计都必须回答："它如何满足这五条？"

| # | 指标 | 含义 | 架构落点 |
|---|------|------|----------|
| A1 | **可自省** Introspection | 运行时能回答"有什么、有哪些字段、什么类型" | 反射 / schema codegen（文档 02） |
| A2 | **可观测** Observability | 结构化日志、可编程读取的性能计数器、带上下文的 crash | 可观测层（文档 05） |
| A3 | **可复现** Determinism | crash / 行为能被精确重放 | 固定步长、引擎 RNG、输入回放（文档 06） |
| A4 | **可操作** Control | 所有能力都有 headless 操作面（CLI / RPC / MCP） | 控制平面（文档 07） |
| A5 | **快迭代** Iteration | 快速构建、热重载、世界快照 / 回滚 | 快照与回放（文档 06） |

**推论**：反射不是"编辑器功能"，而是引擎的**对外语言**；日志不是调试便利，而是**对外契约**。

## 5. 核心矛盾与解决原则

> **AI 要"看懂"状态 ⇄ 嵌入式/性能要求状态"打包、cache 友好、不透明"。**

解决原则（贯穿全局）：

- 内部存储保持 **packed POD**（固定 size + `static_assert(sizeof==N)`）。
- 对外一律通过 **反射层 + 句柄 + ID 寻址**，永不暴露裸指针。
- 对 AI/编辑器的引用形如 `{type_id, entity_id, field_path}`：稳定、可序列化、可跨进程。

## 6. 三层解耦原则（承载"双场景管理器"等可切换能力）

为支持"ECS 与场景树可切换"，明确划分三层：

| 层 | 共享性 | 内容 | 约束 |
|---|---|---|---|
| ① 规范数据协议 | **必须共享** | schema/反射、`handle{index,generation}`、序列化格式 | 是所有模式的公共语言 |
| ② 场景门面 Facade | **可共享，仅冷路径** | create/destroy、按 `type_id` 挂载、按 `{entity, field_path}` 读写、`tick`、`snapshot/restore`、`serialize` | 不追求性能 |
| ③ 热路径 | **各自私有** | 逐实体读写、transform 传播、query 迭代 | **绝不过虚函数**，各用最优布局 |

关键设计约定：

- **query 返回句柄集合 / 可序列化游标，而非迭代器**，以绕开存储差异。
- 冷路径用 `{type_id, field_path}` 做通用读写，专供 AI / 编辑器 / 序列化。
- 游戏逻辑热循环**编译期绑定具体实现**，走零开销路径。
- 语义对齐：即使 ECS 也提供 `Parent` 组件，使层级 / transform 传播在两种模式语义一致。

## 7. 关键架构决策（ADR 索引）

| ID | 决策 | 状态 | 理由 / 详见 |
|----|------|------|------|
| ADR-0001 | 反射由 schema(YAML) + codegen 生成 | 采纳 | 面向 AI/序列化/编辑器的公共语言；仓库已具备雏形 |
| ADR-0002 | 内部数据为 packed POD，对外走句柄/ID | 采纳 | 调和"可观测"与"高性能"的矛盾（见 §5） |
| ADR-0003 | 场景模型采用 **Scene=Node=Prefab 统一**；ECS 与节点树为**双视图**（节点树编辑期源 → 单向 bake → ECS 运行期派生） | 采纳 | 数据化重释 Godot 统一 + Unity 生命周期；见文档 12 |
| ADR-0019 | 节点用**反射记录 + 组合**（组件），**禁止 OOP 继承节点基类** | 采纳 | 与文档 02/06 的 POD/无跨 `.so` 类一致 |
| ADR-0020 | 组件挂载用**句柄**（非内联值）；生命周期回调**确定化**（固定点 + 深序） | 采纳 | 支撑跨场景引用与 A3 回放 |
| ADR-0004 | 控制平面底层为稳定 JSON-RPC / 事件总线，MCP 作为上层包装 | **待定** | 见开放问题 OD-1 |
| ADR-0005 | 确定性为一等公民（固定步长 + 引擎 RNG + 输入回放） | 采纳 | 自主调试的前提（A3）；规则见文档 10 |
| ADR-0023 | 世界支持**快照/恢复/回滚**（POD memcpy + 增量脏页），与回放共用序列化中枢 | 采纳 | A5 快迭代 + 崩溃复现；见文档 10 |
| ADR-0024 | 控制平面 = **JSON-RPC 对齐 CDP 模型**（domain/method/event）+ **MCP 上层包装** | 采纳（解决 OD-1） | AI/CI/编辑器/工具共用一套协议；见文档 11、16 |
| ADR-0025 | 渲染 = **WebGPU**，消费**可序列化绘制描述**，pass 结构走 **T1 轻量声明式层**（T2 完整 frame graph 为可选演进），支持**离屏预览** | 采纳 | WebGPU 已代管同步，重图收益低；见文档 13、OD-11 |
| ADR-0026 | 脚本绑定**由反射生成**（禁手写）；**cycle GC 仅帧边界驱动**（帧内禁隐式 GC） | 采纳 | 保证回放一致 + 绑定不漂移；见文档 14 |
| ADR-0027 | 动画/物理/粒子为**世界层模块**，权威数据在 ECS；物理**确定性优先**，GPU 粒子仅视觉 | 采纳 | 见文档 15 |
| ADR-0028 | 物理**集成 Rapier（Rust）**，经 **C ABI FFI** 作为独立 `physics` 模块 | 采纳（解决 OD-10） | 确定性需实测；Rust↔C++ 边界走文档 02 规则 |
| ADR-0029 | 嵌入式**暂不做 WebGPU 降级**，**限定**为具备 Vulkan/Metal/D3D12 的目标 | 采纳（解决 OD-3） | 避免第二套渲染后端维护成本 |
| ADR-0030 | 远程资产 = **内容哈希校验 + 能力沙箱**，**暂不引入签名链**（二期） | 采纳（解决 OD-9） | 完整性由内容寻址保证；作者身份后置 |
| ADR-0006 | 渲染直接使用 **WebGPU** | 采纳 | 现代、跨平台、自带抽象层；headless/离屏渲染利于 AI 预览。嵌入式驱动成熟度见 OD-3 |
| ADR-0007 | 各模块解耦为独立 `.so`，跨边界走 **C ABI + 句柄** | 采纳 | 强边界、可插件化、可热重载、利于多实例；破坏性代价见 OD-4 与文档 02 |
| ADR-0008 | 脚本以 **quickjs 为主**（内部 refcount），lua/python/v8 为后续可选后端 | 采纳 | quickjs 小、快、无 JIT；refcount 析构即时利于确定性。GC 时机规则见 OD-5 |
| ADR-0009 | AI 资产管线：独立加载 `.scn`、计算依赖、binary 打包、压缩、数据 dump | 采纳 | 支撑 A1/A2；可脱离完整引擎运行，利于 AI 与 CI |
| ADR-0010 | 异步以 **coroutine 为作者层 + 内部 executor/reactor 接口**，**libuv 为首选实现** | 采纳 | coroutine 是语法、libuv 是 reactor，二者互补；接口隔离以支持嵌入式极简实现 |
| ADR-0011 | persistence 为**序列化中枢**：唯一内存表示 + 可插拔 `codec × backend` | 采纳 | 支撑 A1（文本可读/diff）；反射模型即 canonical IR，保证无损往返 |
| ADR-0021 | 资源**开发期文本优先**（入库、可 diff、AI 可读），**二进制为烘焙派生**（可再生，非唯一真相） | 采纳 | 见文档 08；文本格式遵守 diff/AI 友好规范 |
| ADR-0022 | 可观测性**结构化**（JSON 事件 + 指标 + trace + 崩溃上下文），**关日志行为不变** | 采纳 | A2 落点；崩溃上下文即回放输入，见文档 09 |
| ADR-0012 | 语言标准升至 **C++23** | 采纳 | `std::stacktrace` 支撑 A2 崩溃采集；`std::expected`/`std::generator` 改善接口与异步 |
| ADR-0013 | 跨 `.so` 边界**仅用 C ABI + C vtable + struct-size 版本化**；禁用跨边界异常/RTTI/STL；分配者释放 | 采纳 | 解决 OD-4。参照 Vulkan/WebGPU 成熟模式，见文档 02 |
| ADR-0014 | 多实例靠**零全局可变状态**实现 | 采纳 | 状态全在 instance context；禁止单例/可变 static |
| ADR-0015 | 引入 **VFS（虚拟文件系统）**：统一路径空间 + 可挂载多协议 Provider（file/http/ftp/zip/mem/res） | 采纳 | 像浏览器一样加载游戏；persistence/资产 IO 建立在 VFS 之上，见文档 04 |
| ADR-0016 | **WASM/浏览器为一等目标平台**（与原生、嵌入式并列） | 采纳 | 模块加载改为"逻辑统一、物理分平台"，见文档 05 |
| ADR-0017 | 平台抽象层保持**薄**：只抽象有平台差异处，不抽象热路径 | 采纳 | fs/线程/模块加载/时钟/日志/栈回溯；GPU 由 WebGPU 统一 |
| ADR-0018 | **默认单线程**；并行必须**显式**创建 `worker` / 提交 `job` | 采纳 | 使确定性成为默认属性；模拟线程永不阻塞；见文档 05 §4 |

## 8. 技术约束

- **语言**：**C++23**（`CMAKE_CXX_STANDARD 23`），含 C / ASM。用于 `std::stacktrace`、`std::expected`、`std::generator` 等。
- **构建**：CMake ≥ 3.15，导出 `compile_commands.json`（供 clang-tidy / AI 工具链使用）。
- **代码风格**：`.clang-format` + `.clang-tidy` 强制。
- **渲染后端**：**WebGPU**（唯一后端，不自建图形抽象之上的第二层抽象）。
- **模块形态**：各模块编译为独立 **`.so` 动态库**，模块间**尽量解耦**，跨边界接口走 **C ABI + 句柄**。
- **模块**：以 `modules/<layer>/<module>` 组织，每个模块自带 `CMakeLists.txt` 并导出 interface target。
  - 现有：`modules/core/data`（基础数据类型 + schema codegen）。
- **脚本后端**：**quickjs 为主**（内部 refcount）；lua / python / v8 为后续可选后端，**构建期按需裁剪**，仅打包所选 VM。
- **异步运行时**：coroutine 作者层 + 内部 executor/reactor 接口，libuv 为首选 reactor 实现。
- **持久化**：单一内存表示（反射/schema）+ 可插拔 codec（binary/json/yaml）× backend（file/memory/network/zip）。
- **标准版本**：**C++23**（已采纳，见 ADR-0012）。

## 9. 开放问题（Open Decisions）

- **OD-1（控制平面形态）** —— **已解决**，见 ADR-0024 与文档 11。
- **OD-2（双场景管理器是否长期双 ship）** —— **已被 ADR-0003 取代**：升级为"节点树编辑期源 → 单向 bake → ECS"的双视图，不再是二选一。
- **OD-3（嵌入式 WebGPU 驱动）** —— **已解决**：不降级，限定有 Vulkan/Metal/D3D12 的目标（ADR-0029）。
- **OD-4（跨 `.so` 的 ABI 与内存所有权）** —— **已解决**，见 ADR-0013 与文档 02。
- **OD-5（脚本 GC 时机）** —— **已解决**，见 ADR-0026 与文档 14（cycle GC 仅帧边界驱动）。
- **OD-6（persistence 定义）** —— **已澄清**：多存储后端 + 内存数据可任意格式转换，即"序列化中枢"（见 ADR-0011）。
- **OD-7（C++23）** —— **已采纳**，见 ADR-0012。
- **OD-8（浏览器/WASM 目标）** —— **已确认采纳**，见 ADR-0016 与文档 05。
- **OD-9（远程游戏/资产的信任模型）** —— **已解决**：内容哈希校验 + 能力沙箱，暂不签名（ADR-0030）。
- **OD-10（物理实现选型）** —— **已解决**：集成 Rapier（Rust，C ABI FFI）（ADR-0028）。
- **OD-11（是否/何时上完整 frame graph T2）** —— **已决定**：维持 T1；T2 仅当显存/pass 数成硬瓶颈时评估。

# M2 · 脚本驱动（quickjs / JS）

> 上游：`docs/14`（脚本）、`docs/06`（反射）、`docs/milestones/00-路线图`。
> 目标：把游戏的**逻辑层**交给 JS 脚本（quickjs），引擎提供物理/渲染/反射；流程仍是"加载→运行→退出"。

## 1. 目标（纵向切片）

把 M1 的 `ball_demo` 中**硬编码的逻辑**（何时生成球、何时移除）**搬进 JS 脚本**：

- 引擎（C++）：物理积分 + 弹跳 + 渲染（WebGPU）。
- 脚本（JS/quickjs）：`on_start()` 生成球；`update(dt)` 判断"静止后 5s"并移除。

## 2. 产出

| 组件 | 说明 |
|------|------|
| `modules/script` (`maque::script`) | quickjs 封装（C ABI）：create/eval/call/has/gc + 注册原生函数（数值/字符串） |
| `third_party/quickjs-ng` | quickjs 源码（静态库） |
| `scenes/ball_demo.js` | 游戏逻辑脚本 |
| `ball_demo` 更新 | `auto_remove=false`，移除由脚本决定；`main` 加载 `.scn` + `.js` |
| `handle`/反射驱动 | 脚本经宿主函数 `cfg(path)`（**反射**读场景字段）取参数 |

## 3. 脚本宿主 API（本切片）

```
log(s)                         // 字符串回调
cfg(path) -> number            // 反射读场景标量字段（如 "click.x"）
spawn_ball(x,y) -> id
ball_x/ball_y/ball_vy(id), ball_resting(id), ball_rest_time(id)
remove_ball(id), ball_count()
```

## 4. 确定性

- 脚本运行在**模拟线程**；`update(dt)` 用**固定 dt**。
- **cycle GC 仅帧边界**：每帧 `mq_script_gc(vm)`（对齐 docs/10/14）。
- 脚本无系统熵来源（宿主未暴露随机）。

## 5. 验收（实测）

- `script` 单测：注册原生函数、eval、调用、语法错误处理 → 通过。
- 端到端 `ball_demo_run`：`.scn + .js` 加载 → 反序列化/eval → WebGPU 运行 → 退出（ctest 通过）。
- 运行日志：
  ```
  scene: ... click=(160,200)
  script: spawn ball id=0 at (160,200)
  WebGPU backend: AMD Radeon Graphics (RADV)
  script: remove ball id=0
  >>> ball removed at t=7.27s
  ```
  （移除由 **JS** 决定：静止于 2.27s，脚本在 5s 后调用 `remove_ball`。）

## 6. 重构：引擎即浏览器，游戏即资源（docs/20）

M2 后进一步重构，使**宿主零游戏逻辑**：

- 新增 `modules/runtime`（`maque::runtime`）：**通用运行入口** `mq_run_scene(path)`——
  加载 `.scn` → 反序列化 → 加载 `.js` → 固定步长循环 → WebGPU 渲染 → 退出。
- 通用宿主 API（引擎能力，非游戏）：`log/cfg/clear/draw_sprite/rng/screen_w/screen_h/quit`。
- `samples/player`：宿主仅 `mq_run_scene(argv[1])`（一行），**无游戏逻辑**。
- 游戏逻辑全部在 `scenes/ball.js`；场景 `scenes/ball.scn` 为通用 `scn.Scene`（含 `script` 引用）。
- 旧 `ball_demo`（含 `ball_world` 物理）已移除——玩法由脚本实现。

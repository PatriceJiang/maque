# maque 路线图（重新规划）

> 上游：`docs/`（设计文档系列，长期约束）。本文是**执行顺序**，不是设计。
> 性质声明：**maque 是完整游戏引擎，长期工程（数月～数年量级）**。本文任何"里程碑"
> 都是**纵向切片**，用于验证架构是否打通，**不追求功能完备**。

## 0. 规划原则

1. **纵向切片优先**：每个里程碑都从"加载/数据 → 运行 → 退出"跑通一条真实链路（而非堆模块）。
2. **脚本是一等公民**：`quickjs` 从早期接入，作为游戏逻辑层；绑定由反射生成。
3. **地基先行、但不过度**：反射/句柄/模块/数学是地基；其上一层应尽早有真实用例驱动。
4. **确定性贯穿**：模拟单线程、固定步长、输入即数据（docs/10），脚本不得破坏它（帧边界 GC）。
5. **AI 可用性**：加载/调试/预览/采集的能力随里程碑逐步补齐（docs/09/11）。

## 4. 脚本轨（quickjs）—— 重点规划（T3）

**目标**：JS 成为游戏逻辑层，与反射/场景/控制面无缝协作。

1. **集成形态**：quickjs 编为 C 库；`script` 模块以 **C ABI**（docs/02）暴露：
   `create/eval/call/register_host_fn/gc_step`（对齐 docs/14 §1）。
2. **绑定生成**：**由反射描述符生成**（docs/06），禁止手写；POD↔JS 值经序列化转换。
3. **生命周期**：脚本注册 `on_enter_tree/ready/process/physics_process/on_exit_tree/on_destroy`，
   由场景在**固定点、深序**调用（docs/12）。
4. **确定性**（docs/10/14）：refcount + **cycle GC 仅帧边界 `gc_step`**；脚本 RNG = 引擎 RNG；
   脚本跑在**模拟线程**。
5. **沙箱**：capability 门控（远程内容受限，docs/11/19）。
6. **热重载**：脚本源文本入库 → 帧边界替换 + 状态迁移（docs/08/14）。
7. **前置依赖**：反射(✅)、句柄(✅)、**最小场景/生命周期**(M3 的一部分)——故 M2 需带**最小实体/生命周期**，
   或与 M3 紧邻并行。

## 5. 近期计划与关键路径

```
M2(脚本) ─┬─ 需要 最小场景/生命周期(M3 子集)
          └─ 依赖 反射(✅)
M2 之后 → M3(场景) → M4(资源/VFS) → M5(输入/UI) → M6(物理) → …
```

- **近期首选 M2（quickjs）**：理由——脚本是逻辑层，越早接入，后续每个切片都能"由脚本驱动"，最贴近真实引擎开发。
- M2 的**最小切法**：不引入完整场景系统，先让脚本能：
  ① 在"点击"时调用引擎 API 生成球；② 每帧 `process(dt)` 更新；③ 触发移除。
  以 **`.js` 脚本 + 反射绑定**替换当前 `main.cpp` 里的硬编码逻辑。

## 6. 风险与取舍

| 风险 | 处理 |
|------|------|
| 长期工程失焦 | 路线图 + 每里程碑"纵向可运行" |
| 脚本破坏确定性 | 帧边界 GC、引擎 RNG、模拟线程（M2 就定死） |
| 绑定手写漂移 | 一律反射生成（docs/06） |
| WebGPU/WASM/嵌入式分叉 | 平台薄抽象（docs/05），先原生/离屏跑通 |
| 无显示环境 | 离屏渲染 + 脚本化输入；SDL2 于有显示时接入（M5） |
| 组件/场景规模膨胀 | 先最小，按里程碑演进（docs/12/17） |

# M1 · 下落弹跳球（第一个纵向切片 / walking skeleton）

> 目标（用户设定）：
> **点击屏幕 → 在该处添加一个 sprite 球体 → 自由落体并弹跳 → 高度降到 0 → 5 秒后移除。**

这是第一个把"场景 / 精灵 / 输入 / 物理 / 计时 / 销毁"串起来的**端到端切片**，
用于验证架构打通，而非功能完备。

## 1. 验收标准（Acceptance）

1. **点击**：在一次点击（屏幕坐标）处生成一个球实体。
2. **落体**：球受重力自由落体（高度随时间下降）。
3. **弹跳**：触地后按恢复系数反弹，直至**静止（高度≈0）**。
4. **销毁**：球静止在高度 0 后，**5 秒**被移除。
5. **确定性**：给定 `点击序列 + 固定 dt`，逐帧位置可复现（docs/10）。
6. **可观测**：每帧可导出球的位姿（供渲染/AI 检查）。

## 3. 分阶段（越往后越接近"看得见"）

- **M1a（本里程碑先做）· 无头逻辑**：
  用**已有真实模块**（`maque::math`、`maque::handle`）+ 一个**最小球世界**：
  - 实体表（handle）持有 `Ball{pos, vel, ...}` 与 `Sprite{x,y,radius,color}` 渲染数据；
  - `on_click(x,y)` 生成球；`step(dt)` 做**确定的重力积分 + 地面反弹 + 静止判定 + 5s 移除**；
  - 可导出每帧 sprite 列表（供渲染/AI）。
  以**单测**验证验收 1–5；命令行 demo 打印 ASCII 帧验证 6。
- **M1b · 接入渲染**：把 sprite 列表喂给 `renderer`(WebGPU) 离屏渲染，截帧可视化（docs/13 §6）。
- **M1c · 接入输入**：用文档 19 的点击事件驱动 `on_click`（并纳入回放输入记录，docs/10）。
- **M1d · 接入真实物理**：如需更真实的弹跳，替换为 Rapier（docs/15，ADR-0028）；当前先用最小自研积分。

> 说明：M1a 刻意**不依赖** renderer/input/physics，先用最小实现打通"数据→步进→生命周期"，
> 这样能立刻验证架构与确定性，后续以真实模块替换桩。

## 4. 参数与语义（本切片）

- 屏幕坐标：`x` 右、`y` 上；地面 `y = 0`；球心最低为 `y = radius`（底部触地）。
- 重力 `g = 980 px/s²`；恢复系数 `restitution = 0.6`。
- 静止判定：触地后 `|v_y| < 20 px/s` → 视为静止（高度≈0）。
- 移除：静止后 `5.0 s` 移除（可配置）。
- 点击生成：在点击点 `(x,y)` 生成，初速度 0（自由落体）。

## 6. 实测结果（M1a/b/c）

命令：`./build/samples/ball_demo/ball_demo_run /tmp/ball_frames`

- 点击 (160,200) 生成球；`y` 由 199.7 持续下降到触地，`vy` 由负转正（**弹跳**）。
- 静止：`t=2.27s` 时 `y=8.0`（= 半径），`v=0`，标记 `[resting]`。
- 移除：`t=7.27s`（**静止后 5.00s**）球被移除，`ball_count=0`。
- 480 帧 PPM 输出到 `ball_frames/`；单测 `ball_demo` / `gfx` 经 ctest 通过（含确定性用例）。
- **WebGPU 渲染实测**（readback 像素分析）：帧 30 球心 (159.5,174.5)（下落中）→ 帧 150 停在底部 (…,231.5) → 帧 450 无球（已移除，0 非背景像素）。

> 说明：M1b 已是**真实 WebGPU** 渲染（wgpu-native）；M1c 暂用**脚本化点击**，
> 真实窗口事件将经 SDL2 平台层接入（无显示环境下不启用）。

# 16 · 与浏览器架构对照

> 上游：`05`（WASM）、`04`（VFS/URL 加载）、ADR-0016/0018。
> 目的：因为 maque 选的技术栈（WASM + WebGPU + VFS/URL + 沙箱 + 显式 worker）与浏览器高度同构，
> 本文做系统对照，明确**哪些直接借鉴、哪些刻意不同**。

## 1. 一句话结论

> **maque ≈ 一个"游戏化的浏览器运行时"，但加了三样浏览器没有的东西：
> ① 确定性 ② 插件化（多 `.so`/wasm 模块）③ 数据/反射核心（取代 DOM）。**

## 2. 高度重合的部分（几乎同构）

| 维度 | 浏览器 | maque | 出处 |
|------|--------|-------|------|
| 内容加载 | URL → fetch/HTTP + 缓存 | VFS 多协议，按 URL 加载 | 文档 04 |
| GPU | WebGPU / WebGL | **WebGPU** | 文档 13 |
| 脚本 | V8（JIT） | quickjs（解释器） | 文档 14 |
| 线程模型 | 主线程 + 显式 **Web Worker** | **默认单线程 + 显式 worker/job** | ADR-0018 |
| 异步 | 事件循环 / fetch | coroutine + executor/reactor | 文档 05 §4 |
| 场景树 | **DOM 树** | **Scene=Node 树** | 文档 12 |
| 生命周期 | DOM 事件 / 自定义元素生命周期 | `on_enter_tree…on_destroy` | 文档 12 §6 |
| 渲染 | DOM + 合成器 / GPU 进程 | 节点树 → 绘制描述 → WebGPU | 文档 12 §5、13 |
| 可观测 | **DevTools**（性能/内存/网络/控制台） | 结构化日志 + 指标 + trace | 文档 09 |
| 控制协议 | **CDP（DevTools Protocol）** | **MCP / JSON-RPC 控制平面** | 文档 11 |
| 安全 | 同源策略 + 进程沙箱 | 远程内容沙箱（WASM 免费获得） | 文档 05 §7 |
| 存储 | IndexedDB / OPFS / Cache | VFS 后端 + 文本/二进制双形态 | 文档 08 |

**关键同构**：`DOM ⇄ 节点树`、`CDP ⇄ 控制平面`、`Web Worker ⇄ worker/job`、`Service Worker ⇄ 资产缓存`。

## 3. 本质差异（maque 刻意不同）

| 维度 | 浏览器 | maque |
|------|--------|-------|
| **确定性** | 无（兼容优先） | **一等公民**（A3，ADR-0005） |
| **架构** | 单体核心 | **插件化 `.so`/wasm 模块**（ADR-0007/05） |
| **数据核心** | DOM（固定语义） | **通用反射"真相" + 场景树**（文档 06） |
| **隔离机制** | **多进程** OS 隔离 | **多实例 context**（同进程，ADR-0014） |
| **语言** | JS/TS + C++ 宿主 | C++/C + 脚本 |
| **多实例** | 标签页 = 进程 | 实例 = 对象（同进程可共存多个） |
| **调试** | 外部 DevTools | **内建控制平面 + MCP（AI 原生）** |

一句话：**浏览器为"安全与兼容"牺牲确定性；maque 为"可复现与可被 AI 驱动"牺牲了一点便利。**

## 4. 可直接借鉴的浏览器机制

1. **CDP → 控制平面（对齐模型）**
   Chrome DevTools Protocol 就是"引擎的可编程驱动面"。maque 的 MCP/JSON-RPC 控制平面应**对齐 CDP 的模型**
   （**domain / method / event**），生态与 AI 都熟。
   → **倾向落定 OD-1：底层 JSON-RPC 对齐 CDP 模型，MCP 作上层包装。**

2. **Origin / Capability → 远程内容安全**
   浏览器靠"来源"隔离远程内容。maque 加载 `https://microgames.org/xxx` 应有 **origin + 能力授权**模型。
   → 关联 **OD-9**。

3. **Service Worker → 缓存 / 离线 / 后台**
   对应 maque 的资产缓存 + 离线可玩 + 后台异步（文档 04 §8）。

4. **多进程隔离（可选）**
   原生/嵌入式加载**不可信远程内容**时，可借鉴浏览器的**进程隔离**做自建沙箱（文档 05 §7）。
   maque 默认用 context 隔离，但**不排除**为远程内容起子进程。

## 5. 两种身份（同时成立）

- **宿主平台**：maque 编译成 WASM，跑在浏览器里（ADR-0016）。
- **架构蓝本**：maque 自身架构 ≈ 浏览器同构体。

因此更准确的说法：**maque 是"给游戏用的、可确定回放的、插件化的迷你浏览器"**；
在浏览器里运行时，它是"浏览器中的浏览器"——复用 WebGPU/fetch/worker，自带数据核心与控制平面。

## 6. 最该模仿的一件事

**把控制平面做成 maque 的 CDP**（文档 11）：让 AI / CI / 编辑器 / 工具全部用**同一套协议**驱动引擎。
这统一了 A4（可操作），也让外部生态可复用。

## 7. 需要刻意保留的差异（不得被"浏览器同构"带偏）

| 保留项 | 原因 |
|--------|------|
| **确定性** | A3 是核心价值；不得为便利让步 |
| **插件化** | 强边界、可裁剪、可热重载；浏览器是单体 |
| **通用反射核心** | 取代固定语义的 DOM，支撑跨语言/AI/序列化 |
| **默认单线程** | 确定性与嵌入式友好；并行显式 opt-in |

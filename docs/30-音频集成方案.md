# 30 · 音频集成方案（SDL2 · 跨平台）

> 目标：给引擎补上**输出通道**——场景里的 `audio.AudioSource` / `AudioListener` 能出声，
> 脚本能播一次性音效（跳跃/开火/金币），Windows / Linux / macOS / WASM 用同一套代码。
>
> 定位与 docs/15 §4（粒子）、docs/13 §8 一致：**音频只读消费模拟状态，不写回、不进 checksum**；
> 但脚本可见的 `_state` / `_playhead` 仍按**模拟时间**确定性推进。

## 0. 结论（TL;DR）

| 决策 | 选择 | 理由 |
|---|---|---|
| 设备后端 | **SDL2 audio**（`SDL_OpenAudioDevice` + 回调） | SDL2 已是唯一强制平台依赖；Windows(WASAPI)/Linux(Pulse/PipeWire/ALSA)/macOS(CoreAudio)/WASM(WebAudio) 一套代码 |
| 混音/空间化 | **自研 `maque::audio`**（离线可渲染） | 确定性、可测试、无第三方混音器语义 |
| 解码 | WAV 自研；OGG=`stb_vorbis`；MP3=`dr_mp3`（可选） | 单头文件、无系统 codec 依赖、许可干净（public domain / MIT-0） |
| 线程 | SDL 音频线程只做**无锁混音**；模拟线程发命令 | 实时安全：回调里不分配、不加锁、不打日志、不碰 VFS/场景 |
| 落点 | `modules/world/audio`（schema 已在 `world/audio.yaml`） | 与 physics/nav/anim 同层；组件与系统同模块 |
| 默认开关 | **默认 null 后端**（逻辑/脚本可用、CI 静音）；`MAQUE_AUDIO=sdl\|auto` 开设备 | 与墙钟限速/呈现的默认策略一致；显式开设备才出声 |

## 1. 现状盘点（2026-10）

> 本节是方案落笔时的盘点（“缺什么”）；**当前实现状态以 §11 为准**（已全部补齐）。

已有：

- **类型/组件**：`schema/world/audio.yaml` 定义了 `AudioSource`（clip/bus/autoplay/loop/volume/pitch/panning/attenuation/curve/min/max distance/doppler + transient `_state/_playhead/_voice`）与 `AudioListener`；已生成 `maque_types.h`。
- **资产类型**：`schema/asset.yaml` 有 `AudioClip`（source/length/sample_rate/channels）、`AudioBus`（volume/mute）、`AudioCurve`（points）。
- **设计约定**：`docs/components/07-script-audio-nav.md` 已写清生命周期/确定性边界；docs/17 标为未实现。
- **Tracy**：`maque::tracy::Module::audio` 颜色已预留（`#86BCB6`）。

缺：

- 没有 `modules/.../audio` 目录、没有 `audio` 的 module ABI、没有任何 `audio_*` 脚本函数。
- `asset` 的 `mq_asset_kind` 没有 AUDIO；`detect_kind()` 不认 `.wav/.ogg/.mp3`，`AudioClip` 的元数据不会填充。
- 平台层 `SDL_Init(VIDEO|EVENTS)` 未初始化音频子系统。
- 无测试、无示例音频资源。

本机实测（写方案时的环境）：

```
SDL 2.32.10 / driver=pulseaudio / 3 个播放设备
48kHz F32 立体声 / samples=1024 → 300ms 内 14 次回调
SDL_AUDIODRIVER=dummy 同样正常回调（CI 可录）
```

## 2. 选型

### 2.1 设备后端：SDL2（选定）

| 方案 | 优点 | 缺点 / 结论 |
|---|---|---|
| **SDL2 audio** | 已是强制依赖；桌面/WASM 全覆盖；设备枚举/热插拔事件现成；与窗口同一套初始化 | **选它**。少一个第三方运行时，平台边界只有一处 |
| miniaudio | 单文件，设备+解码+重采样一体 | 与 SDL 重复一套设备层；~9 万行 vendored；仅解码时用又太重 |
| SoLoud | 现成混音/3D | 第三方混音语义，难做"离线确定性渲染"，与引擎自有总线/曲线模型冲突 |
| OpenAL Soft | 成熟 3D | LGPL（静态链接受限）、又一套设备层；3D 需求当前不急 |

### 2.2 解码

- **WAV**：自研（RIFF 解析 + PCM 8/16/24/32 + float32）——格式简单，测试可生成。
- **OGG Vorbis**：`stb_vorbis`（单文件，public domain），整段解码到内存。
- **MP3**（可选）：`dr_mp3`（public domain / MIT-0）。
- 解码结果统一为 **float32 交错、原始采样率/声道**；由混音器做重采样/声道映射。
- 解码发生在**加载期（模拟线程）**；音频回调只读已解码样本，不碰 VFS/解码器。

### 2.3 混音 / 空间化：自研

- 固定 voice 池 + 总线（`AudioBus`）+ master；音量/静音/envelope 渐入渐出（后续）。
- 空间化：距离衰减（inverse/linear/exponential/curve）、立体声 pan、pitch（含 doppler 系数）；
  HRTF 留到 P2（不做假 HRTF）。
- 重采样：P0 线性插值；P2 可选 4 点 cubic。采样率 = 设备采样率（48k 优先，可从设备获取实际值）。


CMake 目标：`maque_audio_core`（Mixer/解码）+ `maque_audio`（ABI/后端），链接 `maque::tracy`、SDL2（可选，缺失时只留 null 后端）。

**SDL 的边界**：只有 `device_sdl.cpp` 出现 `<SDL.h>`（与 `modules/ui/imgui/src/backend_sdl.cpp` 同一模式），
混音/解码核心不依赖 SDL——这样离线测试、WASM、未来的其它设备后端都不用改核心。
SDL 初始化：平台层 `SDL_Init(VIDEO|EVENTS)` 之后，音频模块在自己的 `open` 里
`SDL_InitSubSystem(SDL_INIT_AUDIO)`；销毁顺序是先关设备再 `SDL_QuitSubSystem(SDL_INIT_AUDIO)`。
不把音频塞进 `schema/platform.yaml` 的 ABI：设备枚举/回调参数多，且现在只有 SDL 一个实现
（将来要换后端时再抽 ABI，不提前抽象）。

公开接口（`schema/world/audio.yaml` 增加 `module_abi`，生成 `abi/audio.h`）：

```c
typedef struct mq_audio mq_audio;
typedef struct mq_audio_clip mq_audio_clip;   // 不透明：已解码 PCM + 元数据

typedef struct mq_audio_desc {
    uint32_t struct_size;
    uint32_t sample_rate;      // 0 = 设备默认/48000
    uint8_t  channels;         // 2
    uint16_t buffer_frames;    // 1024
    int32_t  device;           // -1 = 默认设备；-2 = 不建设备（null）
} mq_audio_desc;

typedef struct mq_audio_voice_desc {
    uint32_t struct_size;
    const mq_audio_clip* clip;
    float volume, pitch, pan;  // pan: -1 左 … +1 右（Stereo2D）
    uint32_t loop;
    const char* bus;           // NULL = "sfx"
    float x, y, z;             // 3D 声源位置（P1）
    uint32_t spatial;          // PanningMode
    uint32_t attenuation;     // AttenuationModel
    float min_distance, max_distance, doppler;
} mq_audio_voice_desc;

int  mq_audio_create(const mq_audio_desc*, mq_audio** out);
void mq_audio_destroy(mq_audio*);
int  mq_audio_load_wav(mq_audio*, const void* data, size_t size, mq_audio_clip** out);
int  mq_audio_load_memory(mq_audio*, const void* data, size_t size, const char* ext_hint,
                          mq_audio_clip** out);   // 按扩展名选解码器（VFS 读字节由调用方完成）
void mq_audio_clip_release(mq_audio_clip*);
uint64_t mq_audio_play(mq_audio*, const mq_audio_voice_desc*);   // 0 = 失败
void mq_audio_stop(mq_audio*, uint64_t voice);
void mq_audio_pause(mq_audio*, uint64_t voice, int paused);
void mq_audio_set_voice(mq_audio*, uint64_t voice, float volume, float pitch, float pan);
void mq_audio_set_listener(mq_audio*, const mq_audio_listener*);
void mq_audio_set_bus(mq_audio*, const char* bus, float volume, int mute);
void mq_audio_master(mq_audio*, float volume, int mute);
int  mq_audio_mix(mq_audio*, float* interleaved, uint32_t frames);  // 离线/回调共用
void mq_audio_update(mq_audio*, float dt);                          // 模拟线程：逻辑 playhead/状态
int  mq_audio_get_stats(mq_audio*, mq_audio_stats*);
```

> 生成规则见 docs/21；ABI 只在 `schema/` 声明，`abi/audio.h` 是生成物。
> `mq_audio_mix` 同时服务设备回调与离线测试——这是"混音可回归"的关键。

脚本面（`schema/runtime/host.yaml`，`global: true`）：

```js
const v = audio_play("assets/sfx/coin.wav", 0.8, false, "sfx")  // path, volume, loop, bus
audio_stop(v); audio_pause(v, true); audio_set_volume(v, 0.5); audio_set_pitch(v, 1.2)
audio_master_volume(0.7); audio_bus_volume("sfx", 0.8)
audio_state(v)      // 0 stopped / 1 playing / 2 paused
audio_playhead(v)   // 秒（逻辑时间）
```

场景里的 `AudioSource` 走组件路径（`node_set_number(id, "AudioSource.volume", ...)` 即可调），
脚本 API 只补一次性音效。

## 4. 线程模型与实时安全

```
模拟线程（step_frame）                    SDL 音频线程（device callback）
  AudioSource/Listener 扫描（只读）          出队命令（SPSC ring，try_pop）
  play/stop/参数 → 命令队列（无锁）    ───▶  读 voice 参数快照（原子/双缓冲）
  _state/_playhead += dt（逻辑时钟）           混音 → 写 out 缓冲
  teardown：pause + close device（join）   ◀──  状态回写 ring（播放结束/欠载计数，仅诊断）
```

硬规则（回调内）：

1. 不 `new/delete`、不 `std::mutex`、不打日志、不读 VFS/场景、不调用 SDL API；
2. 命令 ring 固定容量（如 1024），满则丢弃并计数（`stats.dropped`），绝不阻塞；
3. voice 参数用**双缓冲快照 + release/acquire**（或每字段 atomic<float>），避免撕裂；
4. clip 样本不可变，生命周期由引用计数保证；`stop` 后延迟释放（回收队列，P1）；
5. 设备关闭顺序：`SDL_PauseAudioDevice` → `SDL_CloseAudioDevice`（SDL 会 join 回调）→ 再销毁混音器。

## 5. 确定性边界

- 音频输出**不参与** checksum / 快照 / 回放（与 GPU 粒子同位）。
- `AudioSource.playhead` 由**模拟 dt** 推进（`playhead += dt * pitch`，loop 回绕），
  状态（Playing→Stopped）也由逻辑时间判定——**不依赖设备回调**，所以同一输入下脚本可见状态确定。
- 设备实际出声位置可能因缓冲/欠载与逻辑 playhead 有毫秒级偏差，**允许**（docs/components/07）。
- 音频线程的播种 RNG（如噪声）用独立引擎 RNG，不动模拟 RNG。

## 6. 运行时/场景集成

`Engine`（P1 已实现）：

- `setup()`：`mq_audio_create`；默认 **null 后端**（逻辑/脚本可用、CI 静音），
  `MAQUE_AUDIO=sdl|auto|1` 才开设备；
- `step_frame()`：`flatten_world()` 之后 `audio.step`（Tracy zone）：
  1. 按 **role** 扫描 `AudioSource` / `AudioListener`（`MQ_ROLE_AUDIO_SOURCE/LISTENER`，
     实体 id 升序 → 稳定；不硬编码组件类型）；
  2. 听者：首个 active 的 `AudioListener`（世界位置 + 节点 angle 作为朝向），
     `master_volume` **只在变化时**下发（脚本 `audio_master_volume` 不会被每帧覆盖）；
  3. 源：`autoplay` 且 `voice==0` → 按 `clip` **路径**（VFS，相对场景目录）解码并播放；
     每帧同步 `volume/pitch/空间位置/衰减`；把 `state/playhead` 写回 transient；
     非 loop 播完后 `state=Stopped`、`voice` 保留（避免 autoplay 每帧重触发）；
  4. `mq_audio_update(dt)` 推进逻辑 playhead/state（director 暂停时不推进）；
- `teardown()`：先 `mq_audio_destroy`（内部停设备/join 回调），再释放场景与解码缓存；
- 控制面（docs/11，D2 默认只读）：`Audio.info` / `Audio.voices`（只读）、
  `Audio.play` / `Audio.stop` / `Audio.set_master` / `Audio.set_bus`（变更类，只读会话拒绝）；
  voice 句柄在控制面用**字符串**（64 位句柄经 JSON number 会丢精度）。

组件字段：`clip/bus/curve` 用 **`string` 路径/总线名**，不是 `asset_ref<T>` ——
后者是内容哈希句柄，场景里无法写路径（`docs/27 §6` 的既有教训；`scn.Sprite.texture` 同约定）。

`asset`：

- `MQ_ASSET_KIND_AUDIO`（`.wav/.ogg/.mp3`）已加；
- `AudioClip` 资产头元数据（length/sample_rate/channels）尚未做 —— 当前解码器在加载时直接填 `Clip`；
- 播放走 `clip` 路径 → VFS 读字节 → 解码缓存（按路径，切场景清空；voice 持 `shared_ptr` 保证存活）。

## 7. 跨平台矩阵

| 平台 | 设备（SDL 后端） | 解码 | 注意 |
|---|---|---|---|
| Windows | WASAPI（SDL2） | WAV/OGG/MP3 | `fetch-deps.ps1` 已含 SDL2；无额外依赖 |
| Linux | PulseAudio / PipeWire / ALSA | 同上 | 本机 PulseAudio 实测通过；无设备时回退 null |
| macOS | CoreAudio | 同上 | SDL2 官方支持；CI 无设备时 null |
| WASM | Web Audio（Emscripten SDL2） | 同上 | **自动播放策略**：首次用户手势后 resume；单线程，回调在主线程 → 混音必须快且无阻塞；解码在加载期完成 |
| Android/iOS（未来） | SDL2（AAudio/OpenSL ES、CoreAudio） | 同上 | 同一 ABI，不需改上层 |
| CI / headless | null / `SDL_AUDIODRIVER=dummy` | 同上 | dummy 实测正常回调；`MAQUE_AUDIO_CAPTURE` 落 WAV 断言 |

环境变量：

| 变量 | 作用 |
|---|---|
| `MAQUE_AUDIO=off/null/sdl/auto` | 关闭 / 只做逻辑推进不出声 / 真设备（**默认 null**；`sdl`/`auto`/`1` 开设备） |
| `MAQUE_AUDIO_DEVICE=<index\|name>` | 选设备（默认 -1） |
| `MAQUE_AUDIO_BUFFER=<frames>` | 设备缓冲（默认 1024；越小延迟越低，越易欠载） |
| `MAQUE_AUDIO_CAPTURE=<file.wav>` | 离线抓音：**强制 null pump**，每模拟步 `mq_audio_mix` 后写 WAV（确定性；CI 断言非静音） |
| `MAQUE_AUDIO_RESUME_ON_INPUT=1` | WASM：首次输入时 resume AudioContext |

## 8. 测试

1. **单测 `audio`**（`modules/world/audio/tests/audio_test.cpp`）：WAV 16-bit/float32、坏数据报 `ERR_FORMAT`；
   离线混音 RMS/等功率 pan；loop/结束；**Spatial3D 衰减 + pan**；逻辑时钟（playhead/状态/loop 回绕）；
   voice 池容量与 `dropped`；**SDL dummy 设备回调 >0**。
2. **离线 golden**：固定 PCM（测试内合成 440Hz）→ `mq_audio_mix` N 帧 → RMS/峰值（容差比较，不做逐字节哈希）。
3. **e2e `audio_e2e`**：`MAQUE_AUDIO=null` 跑脚本 `audio_play` + 场景 `AudioSource(autoplay)`，
   断言 `state/playhead`（0.1s clip 在 0.5s 时 Stopped、playhead 夹在 0.1）；再用
   `SDL_AUDIODRIVER=dummy MAQUE_AUDIO=sdl` 跑同一场景验证设备路径；**不出声**也能验证逻辑（CI 主路径）。
4. **确定性**：`world_trail` 与不开音频一致（音频不进 checksum）；`playhead` 只由模拟 dt 推进。
5. **WASM**（P2）：浏览器手动冒烟；自动播放策略与无设备路径至少不崩。
6. `MAQUE_AUDIO_CAPTURE` 已实现：e2e 断言 WAV 头/帧数/RMS 非静音；Goertzel 频谱断言仍 P2。
7. **控制面 `audio_control_e2e`**：`MAQUE_CONTROL` 逐条调用 `Audio.info/play/voices/stop/set_master/set_bus`，
   断言 JSON 结果与 voice 句柄（无脚本场景下句柄确定）。

## 10. 风险与开放问题

- **WASM 自动播放**：浏览器要求用户手势；需在首次输入/点击时 `resume`，否则"没声音但不是 bug"。
- **多实例**：`mq_host_scene` 多实例时每实例一个 SDL 设备（可接受）；若要共享设备需在进程层做混音总线（P2 再议）。
- **暂停语义**：`director.pause` 是否暂停音乐？建议 P1 默认暂停全部，提供 `audio_pause_all(false)` 例外。
- **内存**：48k 立体声 float ≈ 23MB/分钟；长音乐 P2 改流式/16-bit 存储。
- **设备热插拔**：SDL 有 `SDL_AUDIODEVICEADDED/REMOVED`；P2 处理，P1 失败回退 null 并打日志一次。
- **decoder 许可**：stb_vorbis（public domain）、dr_mp3（public domain/MIT-0）、dr_wav（public domain）——可入库；miniaudio 仅作备选。

- **组件系统**：`AudioSource`（autoplay、每帧参数/空间化同步、`state/playhead/voice` 回写）与
  `AudioListener`（位置/朝向、master 变化下发）；字段用 **string 路径**；e2e 同时断言脚本与组件两条面。
- `asset`：`MQ_ASSET_KIND_AUDIO`（`.wav/.ogg/.mp3`）。
- **解码**：WAV + **OGG（stb_vorbis）** + **MP3（dr_mp3）**，单测用 `tests/data/audio/beep.ogg/mp3` 断言
  rate/channels/frames/RMS；组件 e2e 额外跑一条 OGG 源。
- **离线抓音**：`MAQUE_AUDIO_CAPTURE=<wav>` → 强制 null 后端，每模拟步 mix 后写 PCM16 WAV；
  e2e 用 Python 断言 stereo/帧数/RMS（实测 frames=32000、rms≈0.095）。
- **控制面**：`Audio.info/voices/play/stop/set_master/set_bus`（D2 变更类限制），e2e 覆盖。
- e2e：`tests/audio_e2e.sh`（null 后端逻辑/组件断言 + SDL dummy 设备路径 + capture），
  场景/脚本/WAV/OGG/MP3 在 `tests/data/audio/`；Debug + ASan/UBSan 下同一组测试通过。

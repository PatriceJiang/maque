# 21 · 接口声明与绑定生成（declaration + generate）

> 上游：`docs/06`（反射/代码生成）、`docs/14`（脚本绑定）。ADR-0001。
> 回答："ball.js 如何调用引擎的 math / scene 接口？"——**所有引擎接口只声明一次（IDL），
> 由 codegen 生成 C++/脚本/JSON 多份产物**。

## 1. 原则：单一真相 → 多份产物

引擎的**一切**都在 `schema.yaml`（IDL）里声明一次：

| 声明 | 内容 | 生成产物 |
|------|------|----------|
| `class_list` | 数据类型（struct/enum） | C++ 类型头 + C ABI 描述符 + JSON |
| **`api_list`** | **函数接口**（args/returns） | **C++ 声明头 + 脚本绑定** + JSON |

> 手写绑定 = 漂移之源。**绑定必须生成**（ADR-0026）。

## 2. 函数接口声明（`api_list`）

```yaml
- namespace: math
  class_list: [ ... ]
  api_list:
    - fn: clamp
      args: [ { name: value, type: float }, { name: lo, type: float }, { name: hi, type: float } ]
      returns: float
    - fn: lerp
      args: [ { name: a, type: float }, { name: b, type: float }, { name: t, type: float } ]
      returns: float
```

- `type` 支持标量（`float/double/bool/intN_t/uintN_t`）与 `string`（后续扩展具名 struct 值传递）。
- 生成两个文件：
  - **`maque_api.h`**：`namespace math { float clamp(float,float,float); ... }`（引擎据此实现）。
  - **`maque_bindings.cpp`**：`mq_bind_generated(mq_script_vm*)`——
    为每个函数生成**编组 trampoline**（JS 数值 ⇄ C++ 标量），并注册为 **`<ns>.<fn>`**。

## 3. 分层与依赖

```
schema.yaml ──codegen──▶ maque_api.h(声明) ──▶ modules/api (引擎实现 math::clamp…)
            └─────────▶ maque_bindings.cpp ──▶ maque::genbind ─┐
                                                               ├─▶ maque::runtime ─▶ mq_run_scene
mq::script（quickjs）───────────────────────────────────────────┘
```

- **声明与实现分离**：`maque_api.h` 由生成；`modules/api` 提供实现；两者签名由同一 IDL 保证一致。
- **绑定与运行时**：`maque_bindings.cpp` 编成 `maque::genbind`；runtime 创建 VM 后调用
  `mq_bind_generated(vm)`，脚本即获得 `math.*` 等接口。
- 脚本模块支持 **带点名称**（`"math.clamp"`）→ 在全局建立命名空间对象。

## 4. 调用示例

脚本（资源）里直接调用引擎接口：

```js
log("math.clamp(5,0,3)=" + math.clamp(5, 0, 3));      // → 3
log("math.lerp(0,10,0.25)=" + math.lerp(0, 10, 0.25)); // → 2.5
```

实测输出：
```
[game] math.clamp(5,0,3)=3 math.lerp(0,10,0.25)=2.5
```

## 5. 与"通用宿主 API"的关系

- **引擎 API**（`math.*`、`scene.*`…）走 **`api_list` 声明 + 生成**（本文）。
- **平台/宿主内建**（`log/draw_sprite/entity_*/quit` 等）当前仍由 runtime 手写注册；
  后续同样应**迁移到 `api_list` 声明**，由生成绑定统一，彻底消除手写。
- 目标态：`runtime` 只提供**极少的原语**（或零），其余全部声明式、可被脚本与多语言消费。

## 6. 扩展方向

1. **具名 struct 值传递**：参数/返回值支持反射类型（`Vec3` 等）→ 生成对象编组。
2. **语义化命名/重载/可选参数/默认值**。
3. **多语言目标**：同一 `api_list` 再生成 MCP 工具、C ABI thunk、编辑器调用。
4. **能力门控**：声明中标注 capability，生成门控检查（docs/11）。
5. **文档生成**：从声明生成参考文档 + 供 AI 消费的 JSON。

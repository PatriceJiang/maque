# 06 · 反射与代码生成（中枢）

> 上游：`03`（数据即真相）、`02 §10`（C ABI 描述符）、`04`（VFS）。
> **反射不是模块，是中枢**：它是 A1 可自省的实现，是 ADR-0011「序列化中枢」的 canonical IR，
> 是脚本绑定、场景组件、编辑器、AI 工具链的**共同语言**。

## 1. 定位

一句话：**引擎里每一份"有意义的数据"，其形状都由 schema 描述；反射据此生成 C++ 代码与运行时描述符。**
所有需要"理解数据"的子系统都是反射的消费者：

```
                        ┌──────────── schema (YAML) ────────────┐
                        │        codegen (parser.js)            │
                        └───────┬──────────────┬────────────────┘
                     C++ POD 头 │      C ABI 描述符 │      JSON schema
                                ▼              ▼                ▼
                          运行时(零开销)   反射运行时/跨.so    AI/工具/校验
                                │              │                │
        ┌───────────┬───────────┼──────────┬───┴────┬───────────┴──────┐
    序列化(08)   脚本(14)    场景(12)   编辑器   资产(08)          AI(11)
```

## 2. 设计目标

| 目标 | 含义 |
|------|------|
| **无侵入** | 不改数据布局；运行时热路径仍走生成的 C++，零开销 |
| **ABI 稳定** | 描述符是**数据**，可跨 `.so` / 跨进程 / 跨语言（含 WASM） |
| **双向** | 既能自省读取，也能构造 / 赋值 / 序列化 |
| **可裁剪** | 嵌入式可移除不需要的元数据（编译期开关） |
| **机器可读** | 可导出 JSON schema，供 AI 直接消费（A1） |
| **确定性** | 生成物排序稳定、可 diff；类型 ID 用**稳定哈希**而非序号 |

## 3. schema 语言（在现有 `schema.yaml` 上扩展）

现有已支持：`namespace` / `class` / `size` / `fields(name,type,default)` / `enum`。
拟扩展：

```yaml
- namespace: world
  type_list:
    - struct: Transform           # struct = POD，class = 可有方法/不透明
      fields:
        - { name: position, type: Vec3 }
        - { name: rotation, type: Vec3 }
        - { name: scale,    type: Vec3, default: "{1,1,1}" }

    - struct: Enemy
      size: 32
      fields:
        - { name: hp,       type: "int32_t", attrs: { range: [0, 100] } }
        - { name: target,   type: "entity_ref", attrs: { transient: false } }
        - { name: sprite,   type: "asset_ref<Texture>" }
        - { name: path,     type: "Vec3[]" }
        - { name: state,    type: "EnemyState", default: "EnemyState::Idle" }
        - { name: _scratch, type: "float", attrs: { transient: true } }  # 不序列化

    - enum: EnemyState
      values: [ { name: Idle, value: 0 }, { name: Chase, value: 1 } ]
```

**类型系统**（至少覆盖）：

- 标量：固定宽度整型 / 浮点 / `bool` / `char`
- `enum`
- POD `struct`（可 `memcpy`）
- 定长数组 `T[N]`、动态 `T[]`、`map<K,V>`、`string`
- **引用类型**：`entity_ref`、`asset_ref<T>`（存句柄，序列化为稳定 ID / 路径）
- `optional<T>`

**字段属性（attrs）**：`transient`（不序列化）、`range`、`unit`、`readonly`、`tooltip`、
`ref`（引用目标类型）、`deprecated`。属性本身就是给编辑器/AI/校验用的元数据。

## 4. codegen 的三种产出（一次 schema，三处落地）

| 产出 | 用途 | 特性 |
|------|------|------|
| **C++ POD 头** | 运行时 | 固定布局 + `static_assert(sizeof==size)` + 默认值 |
| **C ABI 描述符**（数据表） | 反射运行时 / 跨 `.so` | 纯 C/POD，含 `type_id`、字段名、偏移、类型种类、属性 |
| **JSON schema** | AI / 工具 / 校验 | 机器可读，供 A1 自省与外部工具 |

> 三者由**同一 schema** 派生，保证 C++ 布局、运行时描述、对外文档**永不漂移**。

## 5. 反射运行时

- **`type_id`**：全限定名的**稳定哈希**（如 FNV-1a），**绝不用序号**（序号会因增删类型而漂移）。
- **Registry**：`name → descriptor`、`id → descriptor`；每个模块在 `init` 时通过 C ABI
  注册自己的类型（文档 02 §8）→ 跨 `.so` 也成立。
- **操作面**（均为**冷路径**）：
  - 迭代字段、按 `field_path` 读 / 写、构造、销毁、复制；
  - `visit(data, visitor)` —— codec 即 visitor（文档 08 的序列化就是跑一遍 visitor）。
- **零开销原则**：热循环用生成的 C++ 直接访问；反射**只用于**序列化 / 脚本 / 编辑器 / AI。

## 6. 与其它系统的接缝

| 系统 | 关系 |
|------|------|
| 序列化（文档 08） | `codec × backend` 都是对描述符的 **visitor**；canonical IR 即 schema |
| 脚本（文档 14） | 从反射**自动生成**绑定（quickjs 等），无需手写 |
| 场景（文档 12） | 组件 / 节点就是反射类型；ECS 与场景树共享同一描述 |
| 编辑器 | 属性面板由反射生成 |
| AI（文档 09/11） | dump / 读 / 写任意路径，JSON schema 直接喂给 AI |

## 7. 版本与迁移

- schema 带版本；类型/字段可标 `deprecated`。
- **兼容规则**：加字段 = 兼容（用默认值）；删/改字段 = 需迁移钩子或报错。
- 反序列化旧数据时，描述符按名匹配 + 应用迁移。
- 与文档 02 的 `abi_version` 对齐：类型描述符本身也可版本化。

## 8. codegen 实现（现有 `parser.js`）

- 输入 `schema.yaml` → 输出 `.h` / 描述符 / `.json`。
- 需扩展：属性解析、引用类型、动态容器、枚举、稳定排序输出（可 diff）。
- **确定性**：输出按名字排序，保证同一 schema 生成同一结果（利于 CI 与 AI 比对）。
- WASM / 原生共用同一生成物（描述符是数据）。

## 9. 遗留风险

| 风险 | 处理 |
|------|------|
| 反射元数据膨胀（嵌入式） | 编译期裁剪：按需注册 + 分级（P0 只留类型名/偏移，P1 加属性） |
| 类型 ID 漂移 | 用稳定哈希，禁用序号 |
| 热路径误用反射 | 约定 + 评审；反射 API 命名上显式（`reflect_*`） |
| 引用类型的环 / 悬垂 | 句柄带 generation；序列化用稳定 ID，反序列化重建 |
| 跨语言绑定工作量 | 必须**生成**，禁止手写 |

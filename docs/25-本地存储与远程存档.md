# 25 · 本地存储与远程存档（storage）

> 上游：`docs/04`（VFS 与协议）、`docs/08`（持久化）、`docs/14`（脚本）、`docs/21`（声明+生成）。
> 一句话：给游戏一个**浏览器 localStorage 那样的键值存储**——但**模式可配**（本地文件 / 内存 /
> HTTP(S) 服务 / WebSocket），并带 `(uid, session)` 命名空间。

## 1. 目标与边界

- 游戏只记"键 → 值"，引擎负责**落哪里**：换模式不改一行游戏代码（`MAQUE_STORAGE` 或 C ABI 的 spec）。
- **读写协议固定**（同一语义映射到四种传输），服务端只需实现四条路由/四种帧 —— 便于自建存档服务。
- 与 VFS 的分工：VFS 是"资源（只读为主）"，storage 是"**玩家数据**（可写、按人/按会话隔离）"。
- 不做的事（当前）：并发写仲裁、鉴权（HTTP 头）、磁盘级缓存、二进制大对象流式传输。

## 2. 命名空间：`(uid, session)`

```
<uid>/<session>/<key>            ← 键空间（key 可含 '/' 形成子目录；每段非空、非 "."/".."）
```

| 来源 | 默认 | 说明 |
|------|------|------|
| `uid` | `MAQUE_UID` → `"default"` | 玩家/账号维度（多人同机的存档隔离） |
| `session` | `MAQUE_SESSION` → `"main"` | 会话维度：`"main"` 是**持久档**；给个运行期 id（如 `run-1234`）就是"临时档"（浏览器 sessionStorage 语义） |
| `spec` | `MAQUE_STORAGE` → 见 §3 | 模式与目标 |

## 3. 模式（spec）与 `file://` 默认路径

| spec | 后端 | 目标 | 构建期依赖 |
|------|------|------|-----------|
| `file://<目录>` | 本地文件 | `<目录>/<uid>/<session>/<key>` | 无（默认） |
| `file://`（不给路径） | 本地文件 | 兜底默认：`$MAQUE_STORAGE_ROOT` → `$XDG_DATA_HOME/maque/storage` → `~/.local/share/maque/storage` | 无 |
| `mem://[名字]` | 进程内 | 不落盘（测试、临时档；**spec 为空/NULL 时的默认**） | 无 |
| `http(s)://host[:port][/base]` | REST（libcurl） | §4 四条路由 | libcurl |
| `ws(s)://host[:port]/path` | WebSocket（libwebsockets） | §5 JSON 文本帧 | libwebsockets |

**运行时（`maque_player` / 宿主）的默认**：`<场景目录>/.maque`（场景就在 CWD 时 → `<CWD>/.maque`），
即"**游戏目录旁的存档目录**"（`scenes/sokoban/.maque/…`）。远程场景（`https://…/game.scn`）没有可写目录
→ 落到模块的 XDG 兜底（仍然持久）。`.maque/` 已在 `.gitignore`。

## 4. HTTP(S) 固定协议（服务端实现四条路由即可）

```http
GET    <base>/<uid>/<session>/<key>       → 200 值（原始字节） | 404 不存在
PUT    <base>/<uid>/<session>/<key>        请求体 = 值           → 2xx
DELETE <base>/<uid>/<session>/<key>       → 2xx | 404
GET    <base>/<uid>/<session>?keys=1      → 200 JSON 数组（键列表）
```

- 路径逐段 percent-encode（空格/中文/`?`/`&` 安全）；`404/410 → MQ_STORAGE_ERR_NOTFOUND`，其余 4xx/5xx → `PROTO`。
- 重定向跟随、连接/整体超时保护、`NOSIGNAL`（与 VFS 的 URL 后端同款策略）。

## 5. WS(S) 固定协议（JSON 文本帧；协议名 `maque.storage.v1`）

```json
→ {"op":"get", "ns":"alice/main", "key":"save/slot1"}
← {"value":"…", "enc":"utf8"}        或   {"error":"notfound"}
→ {"op":"put", "ns":"…", "key":"…", "enc":"utf8"|"b64", "value":"…"}
→ {"op":"del", "ns":"…", "key":"…"}
→ {"op":"keys","ns":"…"}             ← {"keys":["a","b/c"]}
```

- 值非 UTF-8（或含 NUL）时 `enc:"b64"`（base64）；`enc` 缺省为 `utf8`。
- 当前实现**每次操作一条连接**（冷路径：存档/配置量级）→ 状态机简单、失败即报错；连接复用留待需要时加。

## 6. 接口面（C ABI + 脚本 + 控制面）

**C ABI**（`abi/storage.h`，声明在 `schema/io/storage.yaml` 的 `module_abi`）：

```c
mq_storage* mq_storage_create(const char* spec, const char* uid, const char* session);  // NULL spec → mem://
const char* mq_storage_mode(mq_storage*);   // "file" | "mem" | "http" | "ws"
const char* mq_storage_root(mq_storage*);   // 目录 / 名字 / URL 基址（观测）
const char* mq_storage_ns(mq_storage*);     // "<uid>/<session>"
int  mq_storage_put(mq_storage*, const char* key, const void* data, size_t size);
int  mq_storage_get(mq_storage*, const char* key, void** out, size_t* out_size);   // 调用方 mq_storage_free
int  mq_storage_remove(mq_storage*, const char* key);
int  mq_storage_exists(mq_storage*, const char* key);
int  mq_storage_keys(mq_storage*, char* out, size_t cap);                          // JSON 数组
```

**脚本面**（`api_list`，`ctx:true` → 宿主实现；JS 与 Lua 同一套生成绑定）：

```js
storage.set('demo/count', String(n));   // → 1/0
storage.get('demo/count');              // → 字符串（不存在为空串；用 exists 区分）
storage.exists('demo/count'); storage.remove('demo/count');
storage.keys();                         // → '["demo/count","demo/last_seen"]'
storage.info();                         // → '{"mode":"file","root":"…","ns":"alice/main"}'
```

**控制面**（`Storage.info` / `Storage.list` / `Storage.get` 只读；`Storage.put` / `Storage.remove` 变更类，
只读会话返回 `-32001`）：AI/CI 可读写存档、核对键空间。

## 8. 风险与后续

| 风险/缺口 | 处理 |
|-----------|------|
| 服务端不可用 | 错误码明确（`IO`/`PROTO`）；游戏可自行降级（如 `mem://` 或本地 file） |
| 鉴权/多租户 | 未做：HTTP 头/WS 握手扩展位留给二期（`uid` 只做命名空间隔离，不是安全边界） |
| 大对象 | 当前值全量进出内存；> 数十 MB 的应用请走 VFS + 内容哈希（docs/04 §8） |
| 并发写 | 单写者假设（游戏内一次一个）；多进程同档需上层加锁 |

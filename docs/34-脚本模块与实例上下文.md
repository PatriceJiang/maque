## 0. 结论摘要

把四件事拆开，之前互相纠缠的问题各自归位：

| 层 | 定义 | 数量级 | 生命周期 |
|----|------|--------|----------|
| **VM** | 语言运行时（`JSRuntime` / `lua_State`） | 每 Engine 每语言 1 个（隔离 realm 例外） | Engine |
| **包（package）** | 可移植单元：清单 + 目录；跨项目共享的就是它 | O(挂载的包) | 挂载 → 卸载；包作用域状态随 Engine |
| **模块（module）** | 一个脚本文件；每 VM 每键只求值一次 | O(包内文件) | 首次需要 → 卸载包（可缓存） |
| **实例 / 上下文（context）** | 挂在节点上的一份运行状态（`this`） | O(挂载点) | 节点 |

一句话：

> **VM 是语言运行时，包是可移植单元，模块只求值一次，节点实例就是上下文（`this`/`self`）。**

决定（本文按此定稿）：

1. **每语言一个 VM**（每 Engine）。JS 与 Lua 不可能同 VM；混用时各一个。
2. **包清单 `maque.package.json`** 是可移植性的显式声明；模块键 = `包id@版本/包内相对路径`。
3. **JS 用原生 ESM、Lua 用受限 `require`**；包内可互相导入，不得越出包根；`maque:` 是唯一保留的引擎内建命名空间。
4. **模块导出定义（对象/class/零参工厂/table），引擎按挂载点实例化**；`this`/`self` 就是上下文，没有显式 `ctx` 参数；只有声明过的 `props` 进存档。
5. **`global_*` 按包自动命名空间**；脚本 API 不变。
6. **热重载 = 模块代际替换 + 反向依赖闭包重建 context**；`props` 回灌，闭包状态不保留。
7. **单 VM 内做确定性指令预算**；不可信/远程包用 opt-in 的独立 realm（P2），默认共享。
8. **一次性迁移，不做双语义**；仓库内 38 个脚本 + 39 个带脚本的 `.scn` 纳入迁移与回归范围。

### 0.1 语义变化清单（评审先看这张表）

| 项 | 现在 | 之后 | 影响 |
|----|------|------|------|
| 脚本顶层 `var` | 每场景实例私有（每实例一个 VM） | **整个 VM 共享**（模块只求值一次） | 实例状态必须进 `this`/闭包/组件；现有脚本必须迁移 |
| VM 数 | Σ 实例脚本数 + global + overlay | 每语言 1 个（+ 隔离包） | td 的 100 个敌人从 100 VM → 1 模块 + 100 context |
| 事件 handler | VM 全局函数，`this = undefined` | 实例方法，`this`/`self` = 实例 | 同名 handler 天然按实例区分 |
| `node_off` | 删除该事件的全部 handler | **只删除当前 context 注册的** | 修正跨实例误删 |
| 定时器 | 引擎全局，只投给根 `bus` | 记录 owner 实例，随实例销毁 | 修正子实例 `schedule` 打到根脚本 |
| `global_*` | 引擎全局一份 | **按包命名空间** | 包可移植、不污染宿主 |
| 快照恢复 | 结构相同则保留 VM 状态 | **重建 context、重派 `on_start`**；状态只来自组件/props | `32 §15` 的保证作废；测试改写 |
| 热重载 | 新 VM，其它脚本状态保留 | 新模块代际；反向依赖闭包的 context 重建，其它 context 保留 | 日志/测试改写；props 保留 |
| 脚本错误归属 | 每 VM 一个 `last_error` | **每 context**（含包/模块/节点） | 崩溃上下文更准确 |

## 1. 现状与问题

### 1.1 现在的 VM 拓扑

- 根场景 `script`/`scripts`：每个条目一个 VM，装进一个 `mq_script_bus`（`modules/runtime/src/scene/instance.cpp`：`load_instance_scripts`）。
- 每个 `scn.SceneInstance` 子场景：自己的 bus + 每个脚本一个 VM。
- `global_script`、`overlay_script`：各一个独立 VM。
- 公式：`VM = Σ(存活实例的 scripts 条数) + global + overlay`。

实测 `scenes/td/level1.scn`：根脚本 + `global.js` + 3 座塔 + 2 只史莱姆 = 7 个 VM；每只敌人都是一个独立 `.scn`，也就是**每只敌人一个 VM**。

### 1.2 为什么跨项目共享不成立

单看"能不能跑"，把 `scenes/td/towers/arrow/` 拷进另一个项目是能跑的——因为每个实例自带 VM。真正不成立的是**作为一个可复用单元**：

1. **没有命名空间**：两个项目各带 `lib/util.js` 时，当前模型靠"每个实例一个 VM"碰巧不撞；一旦共享 VM 就会撞。
2. **全局状态是引擎全局**：共享包里的 `global_set("gold")` 会污染宿主，换项目就撞键。
3. **代码不能复用**：没有 import/require，共享包无法带自己的工具库；每个实例重新编译一份源码。
4. **成本随实例线性增长**：每个 VM 一份 `JSRuntime`/GC + 一份完整宿主绑定表；共享一个"敌人包"给 100 个敌人 = 100 个运行时。
5. **生命周期边界是 VM**：卸载一个实例必须销毁它的 VM，导致"同一份代码的 N 个实例"无法共享任何模块级缓存。

### 1.3 换成单 VM 后暴露的语义问题（必须一起解决，否则是回归）

- **顶层 `var` 从"实例私有"变成"全实例共享"**：现在 `scenes/td/*.js` 的 `var S = {...}` 是安全的；单 VM 后 100 个敌人会共用一份 `S`。
- **定时器没有归属**：`step_schedules` 只调用根 `bus`（`modules/runtime/src/engine/ui.cpp`），子实例脚本 `schedule` 会打到根脚本；context 销毁时也不会清理。
- **错误归属**：`last_error` 是每 VM 一个；单 VM 后所有包/实例的错误互相覆盖。
- **快照状态**：现在"结构相同则保留 VM 状态"（`32 §15`）；单 VM 后"VM 状态"不再有实例含义，必须改成"context 重建 + 数据恢复"。
- **GC 单域**：所有包共享一次帧边界 GC；一个包的堆增长会影响全部。

## 2. 目标模型

```
Engine（一个世界）
├─ ScriptRuntime(js)  ← 1 个 JSRuntime + 1 个 Context
│   ├─ PackageRegistry: td@1.2.0 → /scenes/td（VFS 根）
│   │    ├─ Module: scripts/enemy.js      （求值一次）
│   │    ├─ Module: scripts/level1.js
│   │    └─ Module: global.js
│   ├─ 宿主 API（一份，所有模块/实例共享）
│   └─ Context 表
│        Node#12  enemy.js  实例 → this { node, hp, … }
│        Node#37  enemy.js  实例 → this { node, hp, … }
│        Node#-1  level1.js 实例 → this { node, … }   ← 场景级脚本 = 根实例
└─ ScriptRuntime(lua) ← 混用时才有（同一套包/模块/context 规则）
```

### 2.1 不变量

1. 每 Engine 每语言**最多一个共享 VM**；隔离包（realm）额外每包每语言一个。
2. 模块键在 VM 内唯一；**每键只求值一次**（热重载产生新代际是唯一例外）。
3. **context 数 = 挂载点数量**，与 VM 数无关。
    - `VM 数 = 有脚本的语言数 + Σ(隔离包的语言数)`；单语言单包项目 = **1 个 VM**。
    - `context 数 = Σ(每个存活场景实例的 scripts 条数) + Σ(每个 script.Script 组件) + global/overlay（各 1）`。
4. context 之间不共享 JS/Lua 堆；共享通道只有：世界状态（组件字段）、节点事件、包作用域（同包）、`storage`。
5. 持久状态只来自 **组件字段**（含 `script.Script.exposed`）；闭包/`this` 上的普通字段是瞬态。
6. 模块顶层是**无副作用**的（只放定义、常量、纯缓存）；有副作用/读墙钟/改世界 = bug。

## 3. 包与模块身份

### 3.1 清单

**包根 = 最近的、包含 `maque.package.json` 的祖先目录。** 没有清单的场景是宿主本地包（id 由挂载路径派生），**不承诺可移植**；加载时打一行 warning。

```json
{
  "id": "td",
  "version": "1.2.0",
  "api": 1,
  "backends": ["js"],
  "isolation": "shared",
  "assets": "."
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | `[a-z0-9_.-]`，包身份；同 `id@version` 不同内容视为冲突 |
| `version` | 是 | 语义化版本；`id@version` 才是模块键的一部分 |
| `api` | 是 | 依赖的引擎脚本 API 主版本；宿主不满足则加载期报错 |
| `backends` | 否 | 默认可由脚本扩展名推断；声明后用于"缺后端"的明确报错 |
| `isolation` | 否 | `shared`（默认）/ `realm`（P2，见 §10） |
| `assets` | 否 | 包内资源根，默认包根；`pkg:/` 前缀解析到这里 |

```
scenes/td/                    ← 包根（此目录有 maque.package.json）
  maque.package.json
  menu.scn  level1.scn …
  global.js  menu.js  level1.js
  towers/arrow/arrow.scn  towers/arrow/arrow.js
  lib/util.js                 ← 包内共享模块：import "./lib/util.js"
```

搬走 `scenes/td/` 整个目录 = 搬走一个可运行的行为单元；宿主只要有对应语言后端与 `api` 版本即可。

### 3.2 模块键与重复挂载

- 模块键：`td@1.2.0/scripts/enemy.js`；每个 VM 内 intern 成 `u32`，事件/依赖/诊断都用它。
- 同一 `id@version` 被多处挂载：视为**同一个包**；逐模块比内容哈希，不一致 → 报错（防"同名不同物"）。
- 开发覆盖（`MAQUE_MOUNT` 遮蔽远程包）：`MAQUE_PACKAGE_OVERRIDE=1` 时按挂载优先级取一份，并打 warning；默认关闭，保证确定性。
- 不同版本可共存（`td@1` / `td@2`）；场景引用自己的清单，不做版本求解（v1）。

### 3.3 路径解析

| 出现位置 | 基准 | 规则 |
|----------|------|------|
| `.scn` 的 `script`/`scripts` | **场景文件目录** | 解析后必须落在同一包根内 |
| `script.Script.source` | 场景文件目录（也可写 `pkg:/`） | 同上（保持现有 `.scn` 兼容） |
| 模块内 `import "./x.js"` | 导入者模块路径 | 不得越出包根；`../` 允许在包内 |
| `pkg:/textures/x.png` | `assets` 字段（默认包根） | 稳定引用，推荐共享包使用 |
| 裸标识符 | — | 只认 `maque:`（引擎内建），其余报错 |

`pkg:/` 是为了让"共享脚本里写死的资源路径"不随场景所在子目录漂移；`.scn` 既有字段保持场景相对，迁移零改动。

### 3.4 被否掉的方案

| 方案 | 否决理由 |
|------|----------|
| 纯 VFS 路径做模块键 | 挂载别名 = 两个身份；不同项目同名文件互撞 |
| 纯内容哈希做模块键 | 热更换身份、诊断/依赖图难读；相同内容的两个库会意外共享模块状态 |
| 包信息写进每个 `.scn` 字段 | 同一包内每场景重复；目录移动即失效；清单是唯一的包边界真相 |
| 无清单也可移植（自动推导） | 无法区分"两个同名 `util.js`"，冲突只能运行时撞 |

## 4. 模块系统

### 4.1 JS：原生 ESM

- 每个 `ScriptRuntime(js)` 用 `JS_SetModuleLoaderFunc`（`third_party/quickjs-ng/quickjs.h:1225`）挂引擎 loader：
  - normalizer 把 `(importer, specifier)` 归一成模块键（包内相对路径 / `maque:`）；
  - loader 查模块缓存，未命中则按包根从 VFS 读源码、编译、登记依赖边。
- 模块在**装配期**求值（场景加载/实例构建/组件挂载），不在模拟帧内做 IO。
- 顶层 `await` / 动态 `import()` / 异步初始化一律禁止（固定步长 + 帧边界确定性）。
- 导出对象 `Object.freeze`；模块命名空间只读。

### 4.2 Lua：受限 `require`

- 恢复一个**引擎实现**的全局 `require(spec)`（仍不开放 `package`/`loadfile`/`dofile`）：
  - 以当前模块为基准解析 `spec`，缓存表按模块键；
  - chunk 用独立 `_ENV`（`__index` → 宿主全局），与现有 `module_load` 同形；
  - 执行前先把空表放进缓存，循环 `require` 返回半成品（Lua 习惯）；执行失败则移除缓存并报错。
- 模块返回 table（定义）；`props` 是 table 字段；引擎用它实例化。

### 4.3 规则

1. `./`、`../` 只能在包内；越界是**加载错误**，不是静默失败。
2. 裸标识符只允许 `maque:`；跨包 `pkg:` 导入 P2（需清单 `dependencies` 声明）。
3. 模块顶层不得：读写世界、读墙钟、发事件、注册全局 handler、调用 `schedule`。
4. 模块求值失败：根场景 → 加载失败；子场景实例 → 该实例 `error` 状态，宿主继续；组件脚本 → 该组件禁用（`Script.init_err`），宿主继续。
5. `maque:` 预留为引擎内建（数学/序列化等），随 `api` 版本走；v1 可只留占位。
6. 挂到节点/场景的模块必须导出定义（JS `default` 对象/class/零参工厂；Lua table 或 `M.new`）；纯库模块只能被 import，挂载时没有定义 → 加载错误。

## 5. 实例：`this` / `self` 就是上下文

### 5.1 形态

模块导出**定义**（JS 对象 / class / 零参工厂；Lua table 或 `M.new`）。引擎为每个挂载点创建一个实例；上下文成员直接挂在实例上，**没有显式 `ctx` 参数**。

```js
// scripts/enemy.js
export const props = {
  hp:   { type: "number", default: 10 },
  kind: { type: "string", default: "slime" },
};

export default {
  on_start() { this.props.hp = 10; },                 // 持久属性
  update(dt) { this.props.hp -= dt; },                // this === 本实例
  on_damage(id, amount) { this.props.hp -= amount; }, // node_on(id,"damage","on_damage")
};
```

class 形式同样可用：

```js
export default class Enemy {
  on_start() { this.props.hp = 10; }
  update(dt) { this.props.hp -= dt; }
}
```

Lua：

```lua
local M = {}
function M:on_start() self.props.hp = 10 end
function M:update(dt) self.props.hp = self.props.hp - dt end
return M
```

**工厂形式**（迁移旧脚本最省事；顶层 `var` 保持为每实例闭包）：

```js
export default function () {
  var S = { t: 0 };
  function update(dt) { S.t += dt; }
  return { update };
}
```

- 导出对象/class/工厂（JS）或 table/`M.new`（Lua）；数字/数组等其它类型在加载期报错。
- JS 对象：`inst = Object.create(上下文层)`；class：`new` 后把上下文层插到实例与 class 原型之间；工厂：引擎建 seed 对象并以它为 `this` 调用，返回的对象即实例；Lua：实例表 + `__index`/`__newindex` 元表。
- 工厂返回后才注入 `node/params/props`（工厂内部不要用 `this.node`；放到 `on_start`）。
- 生命周期和事件 handler 调用时 `this` / `self` **永远是实例**。
- **没有 `create(ctx)`**；也**不需要 `self()`**：Lua 的 `self` 是方法参数，JS 的 `this` 由引擎按方法调用。普通回调里丢了 `this` 就用箭头函数捕获，或按名注册（`node_on(id,"evt","on_evt")`）。**不提供全局 `self()`**——它会引入隐式的"当前实例"状态，和多实例/热重载的确定性冲突，且和 `this` 是同一份信息。
- 持久属性通过 `this.props.xxx` / `self.props.xxx` 读写；**不直接铺到 `this.hp`**，避免与方法名、保留名、class 字段相互遮蔽。
- 纯库模块可以没有定义，只能被 import。
- 同一模块的多个实例共享定义/原型与方法，但**实例字段互不共享**（`this`/`self` 上的是每实例的）。

### 5.2 上下文成员（保留名）

| 成员 | 说明 |
|------|------|
| `node` | 挂载节点 id；场景级脚本 = `-1`（根） |
| `scene` | 所属场景实例 id |
| `package` | `id@version`，诊断/条件逻辑用 |
| `params` | 只读对象；来自 `SceneInstance.params`，无则 `{}` |
| `props` | 声明属性的访问器对象：`this.props.hp` / `self.props.hp`；没有声明时为空只读对象 |

- 保留名不能被**定义上的方法**占用：**加载期报错**（props 在 `props` 命名空间内，不与保留名冲突）。
- JS 中保留成员是 getter（只读）：`this.node = x` 在模块严格模式下抛错；`this.props` 也不能整体替换，只能读写字段。
- Lua 中 `__newindex` 拦截保留名的写入；`self.props.hp = x` 由 `props` 表自己的元表写 exposed；其它新字段 `rawset` 到实例（瞬态）。
- 场景级脚本（`.scn` 的 `script`/`scripts`）= 挂在根上的实例：`node = -1`，**没有 props**；持久状态用组件字段或包作用域。
- `global_script` / `overlay_script` 是引擎持有的实例（`node = -1`），每次场景装配后重派 `on_start`。

### 5.3 生命周期与顺序

沿用现有名字，减少迁移：`on_start` / `update(dt)` / `on_destroy`，事件 handler 任意命名。

| 阶段 | 顺序 |
|------|------|
| 实例创建 | 装配期；节点树先序；同节点按组件声明序；根场景级实例最后建 |
| `on_start` | 场景实例**后序**（子先父）；实例内节点**后序**；场景级根实例最后 |
| `update` | 场景实例**前序**（父先子）；实例内节点**前序**；场景级根实例最先 |
| `on_destroy` | 场景实例**后序**；实例内节点**后序**；根实例最后；然后销毁实例 |
| 事件 | 冒泡沿父链；每个 handler 在**注册它的实例**上调用；注册序 = 派发序 |

- 生命周期与事件 handler **都只从实例/原型链取**；不存在"模块命名导出按名查找"。
- `Script.enabled = false`：实例照建（对象定义无构造；class 构造仍执行），但不调用生命周期与事件。
- `Script.callbacks` 位掩码继续过滤回调（`Ready=2`↔`on_start`、`Process=4`↔`update`、`OnDestroy=32`↔`on_destroy`）。
- class 的构造函数**早于上下文注入**：构造函数里不要用 `this.node` / `this.props`，放到 `on_start`。
- 暂停/未激活的场景实例整棵跳过（沿用 `32 §4.3`）。

### 5.4 `props`：唯一的持久化边界

- 模块导出 `props` schema；类型映射到已有的 `PropertyVariantType`（`Bool/Int/Float/Vec2/Vec3/Color/EntityRef/AssetRef`）。
- 引擎在实例化时构建 `expose_defs`，合并默认值与场景里 `script.Script.exposed` 的按名覆盖。
- `this.props.hp` 是访问器：读写直接落到 `Script.exposed`（按 node id + 类型查组件，不缓存裸指针，快照/重建后仍有效）。
- class 字段与定义对象上的数据字段**不会自动变成 prop**：它们分别是实例瞬态字段与共享原型值；持久属性只能通过 `this.props.xxx` / `self.props.xxx` 读写。这样也避免了 class 字段遮蔽访问器、prop 名与保留名/方法冲突两类问题。
- 访问器走宿主函数；runtime 维护 `current_context` 栈（单线程），用它定位组件、归属错误与指令预算。
- 存档/快照/编辑器/inspector 全部走这一张 `map<string, PropertyVariant>`，不引入第二套状态格式。
- 热重载按名字对齐：保留同名同类型值；新增字段用默认值；删除字段丢弃并告警；类型变化回默认并告警。
- **不提供通用 JS 对象序列化**：函数、闭包、WeakMap 不可序列化，字段改名/类型演化不可控；`this`/`self` 上其它字段明确是瞬态。

### 5.5 迁移配方（38 个脚本可以机械改写）

旧脚本：

```js
var S = { t: 0, score: 0 };
function on_start() { S.score = 0; }
function update(dt) { S.t += dt; }
```

新脚本（JS，P0 迁移采用工厂形式，顶层 `var` 原样保留为每实例闭包）：

```js
export default function () {
  var S = { t: 0, score: 0 };
  function on_start() { S.score = 0; }
  function update(dt) { S.t += dt; }
  return { on_start, update };
}
```

需要持久化的状态再声明 `props`、通过 `this.props.xxx` 读写（P1 接线）；长期代码也可改成定义对象/class，把状态放到 `this`。

步骤：① 在文件头加 `export default function () {`，末尾 `return { ...所有顶层函数名 }`；② 顶层 `import`/`require` 保留；③ 顶层副作用移到 `on_start`；④ 需要跨重载/存档的状态改到 `props`/组件。
不要把可变对象放在定义对象/模块 table 上——那是**所有实例共享**的；工厂闭包/`this` 字段才是每实例私有。

### 5.6 组件挂载（`.scn`）

```json
{ "type": "script.Script",
  "source": "scripts/enemy.js",
  "exposed": { "hp": { "type": 2, "f": 20.0 } } }
```

- `type: 2` = `PropertyVariantType::Float`；`exposed` 是按名覆盖默认值，序列化时 `std::map` 按 key 有序 → 逐字节确定。
- 值转换：`number`→Float/Int（按 schema）、`bool`、`string`、`vec2/vec3/color`→`v[0..3]`、`entity`→`i`、`asset`→`s`。
- 同一节点多个 `script.Script` 按组件声明序创建实例；场景级 `script`/`scripts` 等价于挂在根上的实例，不生成组件。

## 6. 事件与定时器

### 6.1 `node_on` 的归属与解析

`node_on(id, "damage", "on_damage")` 记录 `(entity, event, handler, owner_instance)`。

派发时在 **owner 实例**上解析：实例自身 → 定义对象/class 原型链或工厂返回对象上的同名方法（`this.on_damage`）。**没有"模块命名导出按名查找"**：方法必须在实例/定义上；Lua 同理（`M` 的字段经元表可见）。

调用参数沿用现有事件表的签名：指针 `(target, x, y)`、按键 `(target, key)`、文本 `(target, text)`、`node_emit` `(id, value)`；`this` / `self` = 实例。`node_off(id, event[, handler])` **只删除当前实例注册的记录**（修正现在"删掉所有实例"的问题）。v1 只支持按名注册（字符串）；直接传函数引用放 P2。

### 6.2 广播与作用域

- 键盘/文本等全局事件：按场景实例前序 + 实例内脚本实例顺序遍历，各自调用同名方法。
- 指针事件：按 target 的实例祖先链路由（沿用 `32 §4.3`），最后 global/overlay。
- `global_script` / `overlay_script` 的实例可监听任意节点（保留旧能力），但记录的 owner 是它们自己。
- `scene_emit(instance, event, value)` 在目标场景实例的脚本实例集合里按名派发（等价于对该实例做一次命名事件）。
- 跨语言仍是"按名字路由"：JS 实例与 Lua 实例各自解析自己的方法，载荷只有标量/字符串。

### 6.3 定时器与补间

- `Scheduled { owner_instance, handler, interval, remaining, repeat }`；触发时在 owner 实例上按名解析（可跨热重载）。
- `schedule_count()` 改为**当前 context** 的定时器数（现在返回全引擎总数）；`unschedule` 只删自己的。
- context 销毁时（节点销毁/场景卸载/热重载重建）按 id 顺序取消其定时器；`tween` 同样记录 owner，节点销毁时取消（现在会留下指向已删实体的补间）。
- 这是"context 拥有资源"的一部分：定时器、补间、`node_on` 注册、输入监听、音频 voice 都应在 context 销毁时按确定性顺序清理。

## 7. 全局状态

`global_*` 的脚本 API **不变**，但存储改为：

```
Engine
├─ engine scope        ← 宿主/控制面/引擎级脚本（保留命名空间）
└─ package scopes      ← td@1.2.0 → { gold, lives, … }；按包隔离
```

- 包内脚本调用 `global_set("gold")` → 写入自己的包作用域（归属由 runtime 的 `current_context` 栈决定）；包与包、包与宿主互不可见。
- `storage` **不**自动按包命名空间（它是显式共享通道）；共享包应自行加前缀，或只用 `params`/事件。
- engine scope 只供宿主/控制面使用，**脚本默认拿不到**（要暴露给脚本就加显式 API，而不是共享全局表）。
- `global_script` / `overlay_script` 在其**源文件所属包**的作用域里执行；td 的 `global.js` 与 `level1.js` 同包 → 仍共享 `td.*`（现有行为不变）。
- `global_emit(event, value)` 直接调用 global context 的命名处理器（不再经总线/广播）。
- 包作用域的生命周期 = **Engine**（与现在的全局状态一致，跨 `director_load_scene` 保留）；卸载包不清状态，显式 `global_clear()` 只清当前包。
- 快照按包键排序编码（`MQGL` 块扩展），恢复先于实例表。
- inspector 按包分组显示；控制面只读查询可看到包键。
- 否决"前缀约定"（人会忘）与"新增一套 per-package state API"（迁移代价大、双 API 永久存在）。

## 8. 生命周期、热重载、卸载、快照

### 8.1 引用计数

- `PackageRegistry` 记录每个包的挂载引用（场景/实例/组件引用）。
- 模块缓存随包存活；包引用归零后可保留代码缓存（默认保留到 Engine 结束，避免"重进场景重新求值"带来的行为差异），显式 `unload_package` 才释放。
- context 销毁不释放模块；模块释放必须保证没有存活 context/依赖者。

### 8.2 模块热重载（代际 + 反向依赖闭包）

ESM 的 live binding 决定：只换一个模块，依赖它的模块仍持有旧绑定。所以重载单位必须是**闭包**。
代际体现在**归一化后的内部模块名**（`key#gen`）：源码里的 `import` 不变，依赖者重新编译时由 normalizer 指向当前代际。

1. watcher 把绝对路径映射到 `(package, module key)`；
2. 受影响集合 = 改动模块 + 反向依赖的传递闭包（有环取 SCC）；
3. 帧边界：按拓扑序重新编译（新 generation）→ 成功才换入 → 快照受影响 context 的 `props` → 销毁旧 context → 用新模块重建 → 回灌 `props` → 调 `on_start`（重新注册 handler）→ 可选 `on_reload(old_gen)`；
4. 任何一步编译失败：丢弃新代际，保留旧模块与旧 context（原子，沿用现有"写坏脚本不致命"语义）；
5. 未受影响的 context 不重建、状态保留（替代现在"按文件保留其它 VM"的语义）。

日志改为模块粒度：`hot reload module 'td@1.2.0/scripts/lib.js' gen=2 (3 contexts rebuilt)`。
watcher 同时监视包清单；清单变化/显式命令 → 整包重载（重建包内全部 context）。

### 8.3 卸载

顺序固定：停 update → `on_destroy`（后序）→ 取消定时器/补间/事件注册 → 销毁 context → 包引用减一 → 引用归零时（可选）释放模块。
动态 `scene_unload`、`node_destroy`、场景切换都走这一条路径；不得留下指向已销毁 context 的回调。
`node_destroy` 在帧末 `flush_pending_destroy` 里销毁实例；运行期 `add_component("script.Script")` 在帧边界建实例（模块已加载时只做实例化，不再读盘）。

### 8.4 快照与恢复（语义变更）

- **快照不保存 context/闭包/模块状态**；保存的是实体/组件（含 `Script.exposed`）与包作用域。
- 恢复：按恢复后的节点树重建 context → 重派 `on_start`；`props` 从组件读回。
- `global_script`/`overlay_script` 的 context 不随世界重建销毁；恢复后同样重派 `on_start`（与场景热重载一致）。
- 因此 `32 §15` 的"结构相同则保留 VM 状态、不重复 `on_start`"**作废**，替换为"context 重建、`on_start` 重派、数据状态不丢"。
- 理由：单 VM 下"VM 状态"没有实例含义；把状态放进数据（组件）才能同时满足存档、热重载、跨项目共享三种场景。

### 8.5 错误归属

- 每次调用受保护（JS exception / Lua `pcall`）；错误记到 **context**（包/模块/节点/场景实例），同时累加包级计数。
- `last_error` 按 context 查询；崩溃上下文包含 `package → module → node → handler` 链。
- 连续 N 次错误的 context 自动禁用（可恢复），避免每帧刷屏；包级错误在 inspector/控制面可见。

## 9. 确定性与预算

### 9.1 顺序清单

| 事件 | 顺序 |
|------|------|
| 包加载 | 挂载顺序 / 场景声明顺序；快照按包键排序 |
| 模块求值 | 依赖后序（ESM 静态图）；Lua `require` 按调用序 |
| context 创建 | 节点树先序 + 组件声明序 |
| `on_start` | 实例后序、节点后序 |
| `update` | 实例前序、节点前序 |
| 事件 | 注册序 + 父链冒泡 |
| 定时器 | 插入序；同一帧按列表序 |
| GC | 帧边界；按 context 创建序收集 |
| 预算 | 指令计数（非墙钟） |

### 9.2 指令预算（单 VM 的兜底）

- QuickJS：`JS_SetInterruptHandler`（`quickjs.h:1193`）按固定指令间隔检查当前 context 的计数器；超预算抛异常，禁用该 context 本帧（记录），其它 context 继续。
- Lua：`lua_sethook(L, hook, LUA_MASKCOUNT, N)` 做同样的计数与中断。
- 预算按"每 context 每帧指令数"配置（`MAQUE_SCRIPT_BUDGET`）；指令数确定 → 回放一致。**墙钟预算不可用于确定性路径。**
- 内存：`JS_SetMemoryLimit` / Lua 自定义分配器只能设**整 VM 上限**（建议默认 64 MiB，可配）；单堆无法按包限额——这是 §10 存在的原因。

### 9.3 三个现有隐患（一并修）

1. **Lua `pairs` 顺序**：`luai_makeseed` 用 `time()` + 地址做字符串哈希种子（`third_party/lua/src/lstate.c:71`），跨进程 `pairs` 顺序会变。构建期固定种子（如 `-Dluai_makeseed(L)=0`），或提供 `sorted_keys` 并在文档中要求遍历顺序敏感的逻辑使用它。
2. **墙钟**：`Date` / `performance.now` 目前可直读；绑定到模拟时间（或禁用），否则模块初始化/逻辑不可回放。
3. **异步**：禁止顶层 `await`、动态 `import()`、Promise 驱动的初始化；模块求值返回 Promise 视为错误。

## 10. 隔离模型（realm）

**单 VM 是性能/共享选择，不是安全边界。** 同一 VM 内所有包共享堆、GC、异常域；一个包死循环/吃爆内存会影响全部。

- 默认：`isolation: "shared"`，所有本地包进宿主 VM。
- 可选：`isolation: "realm"` → 该包每语言一个独立 VM（独立堆/GC/模块表）；跨 realm 只允许引擎 API + 事件总线（标量/字符串），不能共享对象/模块。
- 宿主策略：`MAQUE_PACKAGE_ISOLATION=remote|all|none`（`https://` 挂载的包默认 `remote`，P2 落地）。
- 成本：VM 数从 O(实例) 降到 O(隔离包)；默认包仍共享。
- 与"每语言一个 VM"的关系：**默认 1 个/语言；隔离是 opt-in 扩展**，不改变本文其余设计。

### 11.3 runtime 内部结构

- `PackageRegistry`：包键 → 根 VFS 路径/清单/模块表/引用计数。

- `ScriptRuntime`（每语言）：VM、模块表、context 表、预算、错误计数。
- `Context`：id、node、scene、module、实例句柄、owner 注册表、props 绑定、enabled/error。
- `SceneInstanceRuntime`：`bus`/`scripts`/`script_hashes` → `std::vector<context_id>` + 脚本元数据。
- 事件表：`(entity, event) → [record]`，record 带 `owner_context`（替换 `owner_instance + script_slot`）。
- 定时器/补间：加 `owner_context`。

## 13. 实施阶段与验收

> 落地方式：P0 已合入（有清单的 JS 场景走新路径；无清单场景继续旧路径直到 P1 全量迁移）；P1/P2 按 §13 推进，不引入"两套 API"——新旧差异只在**加载路径**，脚本契约统一为 `this`/`self`。

### P0 · 地基（JS）— 已完成

- 包清单（`maque.package.json`，支持祖先包根）+ 模块键 + intern + **本地文件 ESM loader**（远程/VFS 读取 P1）。
- 每 Engine 一个 JS VM；无清单场景仍走旧的每脚本 VM 路径。
- 定义/class/工厂 + 实例化（`this`/`self` 注入 `node/scene/package/params/props`）+ 实例表 + 生命周期/事件按 owner 实例派发。
- 迁移 `scenes/nested`、`scenes/td`（14 个脚本）；`scene_instance_e2e`、`scene_serialization_e2e`、`td_e2e` 已绿。
- 验收：同一 `.scn` 两实例共享模块、状态独立；卸载一个不影响另一个（`scene_instance_e2e` churn 覆盖）。

### P1 · 组件脚本与持久化

- `script.Script` 接线：`props` schema、`exposed` 读写、`enabled/callbacks`、inspector 编辑。
- Lua runtime 对齐定义/实例/props（**不含**跨模块 `require`）。
- 全部仓库脚本迁移；`schedules/tweens/node_off` 归属修正。
- 模块代际热重载 + 反向依赖闭包 + `props` 回灌。
- 包作用域 `global_*` + 快照格式 v2（包键排序）。
- 验收：改底层模块只重建依赖闭包；快照恢复后 `props` 不丢；`global_*` 包隔离。

### P2 · Lua、预算、隔离

- Lua `require` 跨模块导入 + loader 对齐；缺后端明确报错；`multilang`/`lua_e2e` 回归。
- 指令预算 + 错误隔离 + 包级诊断。
- realm opt-in + 远程包策略；`Package.list/info` 控制面；inspector 包树。
- 验收：JS/Lua 同语义；死循环不拖垮宿主（同 VM 内被中断）；realm 包可独立卸载。

### DoD（整体）

1. `ctest` 全绿（含 A 类改写后的断言）。
2. 三条硬门：**模块只求值一次而实例状态互不串**、**热更只重建依赖闭包**、**带清单的包拖进另一项目能跑且不污染宿主 `global_*`**。
3. 同 seed + 输入，`world_trail` 两跑一致；预算中断可回放。
4. 单 VM 下内存/GC 无回归（对比现有 `MAQUE_TRACY_MEM_REPORT`）。

## 14. 风险与开放决策

| 风险 | 处理 |
|------|------|
| 顶层状态语义翻转（最大迁移风险） | §5.5 机械配方 + 全量迁移 + `context_state_e2e` 门 |
| ESM 热重载代际复杂（live binding/环） | 代际键 + SCC 闭包；失败原子回退；必要时整包重载兜底 |
| 单 VM 内存/GC/错误域共享 | 指令预算 + 内存上限 + realm opt-in；文档明确"不是安全边界" |
| 模块求值期 IO/副作用 | 装配期求值、模块顶层禁副作用；loader 只在引擎侧读 VFS |
| 快照语义变更影响现有保证 | 明确写入 `32 §15` 修订；`props` 作为唯一持久状态 |
| Lua `pairs`/墙钟破坏回放 | 固定哈希种子 + 模拟时间 `Date` + 禁用异步初始化 |
| 38 个脚本 + 10 余个 e2e 改写的工程量 | 分 P0/P1；先迁嵌套/td 两条最能暴露问题的路径 |
| ABI v3 破坏兼容 | 主版本升级；`mq_script_bus` 退役；同步 `21`/`API.md` |

**已定**：清单用独立 `maque.package.json`；realm 放 P2；`props` 只用于组件脚本；`script`/`scripts` 保留为根 context 简写；跨包 `import` 放 P2。

**待实现时确认**：`maque:` 内建模块的首批内容；`MAQUE_PACKAGE_ISOLATION` 的默认策略（本地 shared / 远程 realm）；`script.Script.vm` 是否改名 `context`（建议保留字段名，仅文档改称）；是否提供模块级 `self()` 兼容糖（默认不提供，理由见 §5.1）。

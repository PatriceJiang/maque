# 20 · 运行时与资源模型（引擎即浏览器）

> 上游：`03`（Our Machinery）、`05`（WASM）、`08`（资源）、`11`（控制平面）、`14`（脚本）。
> 本文固化一条核心架构原则：**引擎就是"浏览器"，游戏就是"一堆资源"**。

## 1. 核心原则

- **引擎 = 通用运行时（"浏览器"）**：提供窗口/GPU/反射/序列化/脚本/循环/输入等**通用能力**。
- **游戏 = 资源**：场景（`.scn`）+ 脚本（`.js`）+ 资产（纹理/字体/…）。**游戏逻辑全在资源里**。
- **宿主零游戏逻辑**：示例程序只做初始化与消耗；核心入口**就一句**：

```c
mq_run_scene("ball.scn");
```

## 2. 运行流程

```
mq_run_scene(path)
  ├─ 加载 .scn（文本资源）→ 反序列化（反射驱动, docs/06/08）
  ├─ 读取 scene.script → 加载 .js（资源）→ quickjs 求值
  ├─ 创建 WebGPU 设备（docs/13）
  ├─ on_start()                      # 脚本初始化
  └─ 固定步长循环 (docs/10)：
        update(dt)  →  帧边界 GC  →  render(WebGPU)  →  (可选 dump)
        ... 直到脚本 quit() 或硬上限
  → 退出
```

## 3. 通用宿主 API（引擎能力，非游戏）

脚本可用的**引擎通用能力**（不掺任何游戏概念）：

| 能力 | 说明 |
|------|------|
| `log(s)` | 日志（docs/09 交汇） |
| `cfg(path)` | **反射**读场景字段（docs/06） |
| `screen_w()` / `screen_h()` | 视口尺寸 |
| `draw_sprite(x,y,r,color)` | 提交精灵（渲染为通用能力） |
| `rng()` | **引擎 RNG**（确定性，docs/10） |
| `clear(r,g,b)` | 清屏色 |
| `quit()` | 请求退出 |

> 复用"引擎即浏览器"对照（docs/16）：`draw_sprite` ≈ 浏览器的绘制原语；`cfg` ≈ 读写文档；
> `rng` 提供确定性随机；`quit` ≈ 关闭页面。

## 4. 场景资源（`scn.Scene`）

场景类型是**引擎通用**的，不含游戏字段：

```json
{ "title": "ball", "script": "ball.js", "width": 320, "height": 240, "seed": 12345 }
```

游戏参数（重力/弹性/…）属于**游戏**，放在**脚本资源**里（仍是资源），使引擎保持通用。

## 5. 与"双视图 / 组件"的关系（演进方向）

当前切片：脚本直接用**通用绘制 + 数学**实现玩法；引擎尚无组件/场景树。
后续（M3+）：引擎提供**实体/组件**（节点树/ECS，docs/12/17），
脚本改为操作引擎组件；`draw_sprite` 等原语由渲染层从组件提取。**原则不变**：引擎通用，游戏资源化。

## 6. 意义

- **统一入口**：任何游戏都是 `mq_run_scene(path)`；引擎不随游戏变化。
- **可被 AI 驱动**：加载/运行/截帧/退出都可程序化（docs/11）。
- **多实例**：多个 `mq_run_scene` 即多个实例（ADR-0014）。
- **浏览器/WASM**：该模型天然对齐"从 URL 加载游戏"（docs/04/05）。

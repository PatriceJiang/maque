# 32 · 场景实例、事件作用域、序列化与动态实例化（重新设计）

> 上游：`12`（场景与世界）、`14`（脚本）、`19`（输入与事件）、`10`（确定性快照）、`20`（运行时与资源模型）、
> `02`（ABI/多实例）、`components/07`（Script 组件设计稿）。
> 关联计划：[`plans/11-scene.md`](../plans/11-scene.md)（被本文取代的部分见 §9）。
> 本文回答一个问题：**为什么"加载一个 .scn"不等于"得到一个有行为的场景"，以及怎么改**。

## 0. 结论摘要

现状把**行为**绑在"整个世界的唯一主脚本"上，而不是绑在"场景资产"上：

- 一个进程只有一棵世界、一组主脚本 VM；`.scn` 只是被加载的**数据**；
- 场景可以"嵌套"（prefab 展开）但嵌套进来的**内容没有行为**、没有生命周期、没有事件作用域；
- `Scene.save` 把世界手写回 7 个字段，`scripts`/`overlay_script`/环境/视图等直接丢失，嵌套关系被烘焙；
- 没有运行期"再实例化一个场景 / 卸载一个场景"的接口。

重新设计后的核心定义（**一句话**）：

> **Scene（`.scn`）= 节点树 + 行为（脚本集合）+ 场景级配置；
> 加载/实例化一个 Scene 得到一个 SceneInstance（独立 VM 组 + 独立生命周期 + 独立事件作用域 + 可卸载），
> 场景可以嵌套场景（SceneInstance 树），并且整棵树可无损序列化与动态增删。**

四个专题分别落在：

| 专题 | 设计落点 |
|------|----------|
| 1. 事件系统 | §4：事件带**作用域**（instance）、按 instance 路由、明确的生命周期与派发顺序；保留现有按处理器名路由的跨语言语义 |
| 2. 嵌套场景 | §5：`scn.SceneInstance` 组件 + 实例注册表 + 每实例 VM 组；静态嵌套与 prefab（纯数据）明确分工 |
| 3. 序列化/反序列化 | §6：`.scn` v2、反射驱动、实例**保引用不烘焙**、稳定 ID、快照扩展、round-trip 验收 |
| 4. 动态实例化接口 | §7：脚本 API + 控制面 + C ABI；帧边界生效、确定性、预算与错误模型 |

## 1. 现状与问题（不是审美问题，是完整性缺口）

### 1.1 行为没有归属

- `Engine::load_scene_into` 先把旧世界（含 `bus` → 所有主脚本 VM）销毁，再只读**根场景**的
  `script` / `scripts`（`modules/runtime/src/runtime.cpp`：`load_scene_into`）。
- `expand_prefab` 只读被嵌套文件的 `"entities"`；`load_entity` 只认 `name/components/children/source`。
  **嵌套文件的 `script`/`scripts`/`overlay_script` 被静默忽略**（实测无任何警告）。
- 结果：想让子场景有行为，只能把它的逻辑硬塞进根脚本，并让根脚本了解子场景内部结构
  → "场景"退化成数据片段，组合性与封装性都不成立。

### 1.2 事件是"全世界广播"，没有作用域

- `dispatch_event` 对 `bus` + `overlay_bus` 按处理器名广播；`node_emit` 的处理器表是**全局**
  `entity id → handler`，不记录"由哪个脚本/哪个场景实例注册"。
- 两个相同 `handler` 名（例如两个子场景都写 `on_tick`）会互相串扰；
  `node_on` 可以对任意实体注册，没有所有权约束。
- 生命周期只有全局 `on_start` 一次 + 每帧一次 `update`；没有"进入场景/就绪/退出/销毁"的实例级回调。
- 文档 `19 §5` 描述的捕获→目标→冒泡模型目前也没有落地；脚本侧仍是"每个 VM 各收一份广播"。

### 1.3 序列化是"有损快照"，不是"场景存档"

`mq_control_Scene_save` 手写输出：`title / script / width / height / seed / gravity_y / restitution / entities`。

- **丢失**：`scripts`（多脚本）、`overlay_script`、`views`、`eye_sep`、`msaa_samples`、`env_*` 等 `scn.Scene`
  的其余字段（schema 里已有，`Scene.save` 没写）；
- **丢失嵌套语义**：prefab/嵌套内容在加载时就已 spawn 成普通实体，`Scene.save` 把它们当普通节点写出
  （只有 `expand_prefabs` 显式把 `PrefabInstance.detached` 置 true 之后才"应当"这样）；
  `Meta.source_scene` / `source_prefab` 运行期**从未写入**；
- **没有稳定身份**：实体 id 是按加载顺序单调分配的运行期索引，没有持久 `stable_id` 约定
  （`Meta.stable_id` 字段存在但未赋值），引用/存档/增量更新都缺少可靠锚点；
- **运行期状态不可存档**：VM 变量、定时器、粒子等不落盘（可接受，但必须明确边界并把"结构性状态"补回来）。

### 1.4 没有动态实例化

- 只有 `director.load_scene`（**整世界替换**）和加载期 prefab 展开；
- 没有"在运行中生成/卸载一个场景实例"的接口 → 无法做关卡流式加载、弹窗/模态子场景、
  可复用的玩法模块、编辑器里的场景实例化预览。

## 2. 设计原则

1. **行为归属于场景资产**：`.scn` 自己声明脚本；每个实例化出来的 SceneInstance 拥有自己的 VM 组。
2. **组合优先于特例**：嵌套场景、prefab、overlay 都是同一套实例模型的三种用法，不再各写一套旁路。
3. **作用域显式**：事件、节点注册、资源解析都有"当前场景实例"这个作用域；跨作用域必须显式。
4. **确定性不变**：实例创建/派发/销毁顺序固定；所有结构变化发生在帧边界；RNG/GC 语义不放宽。
5. **序列化保真**：保存的是"场景的组成"，不是"当前世界的克隆"；需要烘焙时显式请求。
6. **增量落地**：每个阶段保持老场景零回归；`.scn` 不写新字段时行为与今天一致。
7. **数据即真相**：新增公开接口一律走 `modules/core/data/schema/`（类型/API/控制面/回调），不手写。

## 3. 总体模型

### 3.1 资产与实例

```
.scn 资产（authoring）
  ├─ SceneDesc（title/scripts/overlay_script/width/height/seed/env/...）
  └─ 节点树（entities[].children...，组件）
        │  实例化（静态声明 / 动态 API）
        ▼
SceneInstance（运行期，0..N；根场景 = 实例 0）
  ├─ instance_id（运行期句柄，单调、确定性）
  ├─ source（VFS 路径）+ asset_hash
  ├─ attach_entity（父场景里的挂载节点；根实例无）
  ├─ root_entities[]（本实例的节点子树根）
  ├─ bus（本实例的 VM 组；脚本来自该 .scn 的 scripts/script）
  ├─ state：pending / active / paused / unloading / invalid
  └─ children[]（按创建/声明顺序）
```

- **根场景**：`mq_run_scene(path)` 加载的 `.scn` = 实例 0，`attach_entity = -1`；
  它今天的 `scripts`/`on_start`/`update` 语义**完全不变**（只是内部多了一层 instance 记账）。
- **嵌套场景**：父场景节点上的 `scn.SceneInstance` 组件在加载期实例化为子实例；
  子场景的 `scripts` 在该实例内创建 VM；子树挂在父节点下（组件持有者 = 挂载壳节点）。
- **prefab（`.prefab.json`）**：仍然是**纯数据模板**（无行为、无 VM）。需要行为时请用 `.scn` + `SceneInstance`。
  这样 `Scene = Node = Prefab` 的数据形态不变，但"行为单元"的边界清晰：**带 `scripts` 的 `.scn` 才有行为**。
- **overlay_script**：保持现状的"全世界常驻 VM"特殊角色（HUD/外壳），不参与实例树；
  只允许根场景声明（嵌套场景里声明 → 警告并忽略）。

### 3.2 所有权

- 每个运行期实体记录 `owner_instance`（运行期字段，不序列化）。
- 根场景直接拥有的实体 `owner_instance = 0`；子实例拥有的实体 = 子实例 id；
  挂载壳节点归属**父**实例（它承载 `SceneInstance` 组件）。
- 任何"按作用域"的能力（`node_on` 注册、事件投递、资源解析基准）都用 `owner_instance` 判定。
- **跨作用域允许但必须显式**：父实例的脚本可以操作子实例的节点（它看得到整棵树）；
  子实例脚本默认只能操作自己子树 + 通过显式 API 访问外部（见 §4.4、§7）。

### 3.3 生命周期（每个实例）

```
pending → enter → ready → [update]* → exit → destroyed
             │        │
             │        └─ on_start（本实例全部节点就绪后）
             └─ 节点/组件创建完成
```

- `on_start` per instance：**后序**（子实例先 ready，父实例后 ready；同实例内按声明顺序）。
  这样父场景在 `on_start` 里查询子场景状态时，子场景已经初始化完毕（对齐 Godot `_ready` 直觉）。
- `update(dt)` per instance：**前序**（父实例先于子实例；同实例内按 `scripts` 声明顺序），
  然后 overlay（最后）。`paused` 的实例及其子树跳过 `update`（但渲染/命中仍按 `active` 语义）。
- `on_destroy`（新增回调）：卸载实例时**后序**（子先父后）派发；VM 随后销毁。
- 根场景的 `on_start` 仍在"整个世界装配完成后"发生（后序下它就是最后一个），与今天时序一致。
- 生命周期派发点固定：加载/实例化在帧边界；销毁在帧边界；绝不在脚本调用栈内递归实例化（见 §7.3）。

### 3.4 作用域内可见的 API 上下文

- 每个 VM 知道自己属于哪个实例（运行期绑定，不写进脚本）。
- 新增自省：`scene_self()`（当前脚本所属实例 id）、`scene_self_root()`（该实例挂载壳/根实体）。
- 宿主函数在派发期间通过 `Engine::active_instance` 提供上下文（单线程固定步长，进入/退出时保存恢复）；
  现有 `entity_*` / `node_*` 默认仍看全树（渐进式收紧，见 §12 开放决策 D4）。

## 4. 事件系统

### 4.1 事件分类

| 类别 | 例 | 作用域 | 载荷 |
|------|----|--------|------|
| 生命周期 | `on_start` / `on_destroy` | 单实例 | 无 / 无 |
| 帧回调 | `update(dt)` | 每实例 VM | dt |
| 输入 | `on_pointer_*` / `on_wheel` / `on_key_*` / `on_text` | 按规则路由（§4.3） | target + 坐标/键/文本 |
| 节点自定义 | `node_emit` / `node_emit_number` | 节点 → 祖先冒泡 | 标量 + 字符串 |
| 跨实例 | `scene_emit(instance, event, value)` | 指定实例 | 标量 + 字符串 |

桥接/定时器等引擎产生的事件（`tween_complete`、`changed`、`toggled`…）走**节点自定义事件**同一条路径，
因此自动获得实例作用域。

### 4.2 注册（node_on）与所有权

- `node_on(entity, event, handler)` 注册记录新增 `owner_instance`：
  - 允许注册的范围：当前脚本实例的**子树内任意实体**（含挂载壳）；根实例（0）与 overlay 允许任意实体
    （保持今天"根脚本可以监听全树"的能力）；
  - 越界注册 → 返回 0 + 明确日志（不是静默生效），避免子场景脚本偷偷监听别家节点。
- 处理器记录：`{ entity, event, handler, owner_instance }`，按注册顺序保存（确定性）。
- 名称仍语言无关：JS 注册的 `on_ai_tick` 可以被 Lua 触发（不变）。

### 4.3 派发与顺序（冻结）

**节点自定义事件**（`node_emit_number(target, event, value)`）：

```
target → 父 → … → 世界根
  沿路对每个实体：按注册顺序匹配 event 的处理器
  处理器只调用其 owner_instance 所属的 bus（VM 组）
  跨实例边界不截断（父实例可在挂载壳/祖先上监听子场景事件）
```

- 只有匹配的处理器被调用；返回命中数（与今天一致）。
- 同名 handler 分属不同实例时互不串扰（因为每条记录带 owner_instance）。
- 在处理器内部再次 emit → 嵌套调用，按调用顺序执行（现有语义），但**深度上限**保护（如 16 层）。

**输入事件**：

| 输入类型 | 路由 |
|----------|------|
| 指针/wheel（命中 target ≥ 0） | 先 root 实例 VM，然后 target 的 owner 实例及其祖先实例（root → … → owner），最后 overlay |
| 指针/wheel（未命中） | root 实例 + overlay |
| 键盘/文本 | 所有 active 实例 + root + overlay（顺序：root → 实例树先序 → overlay） |

- 这样 HUD/根玩法仍能拿到全部输入（今天的根脚本行为不变），子场景脚本只收到"发生在自己子树"的指针事件。
- 完整 DOM 捕获/冒泡（`docs/19 §5`）作为后续阶段在**同一路由层**实现，不改变脚本回调签名。
- 同一事件内各 VM 的相对顺序 = 实例树先序 + 实例内 `scripts` 声明顺序（确定性）。

**生命周期**：

- 实例创建完成 → 后序 `on_start`（子先父后；同实例内声明序）。
- 每帧 → 前序 `update`；`paused` 子树跳过。
- 卸载 → 后序 `on_destroy`；随后销毁 VM/实体。
- overlay 的 `on_start`/`update` 仍在最后（保持今天"主脚本之后"的语义）。

### 4.4 跨实例通信

- 默认：子场景事件沿父链冒泡到父实例（§4.3），父实例挂在壳节点/祖先上的处理器可收到。
- 显式：`scene_emit(instance_id, event, value)` —— 直接调用该实例 VM 组中定义了 `event` 的处理器
  （等价于对该实例做一次命名事件），用于解耦的上下级通信。
- 禁止隐式按 handler 名跨实例广播（今天的全局广播在新模型里只保留给根实例/overlay 的兼容路径）。

### 4.5 多 VM 与数据共享（澄清）

"每个实例一组 VM"不意味着"一个引擎只有一个 VM"：`Engine` 仍是唯一的**世界实例**，
而 `mq_script_vm` 本来就是**多实例**的——今天根场景 `scripts: ["game.js", "ai.lua"]`
就已经创建 2 个 VM（`mq_script_bus` 持有并按声明序投递）。场景实例只是把 VM 的**归属**从
"整个世界一组"细化为"每个场景实例一组"：

```
Engine（一个世界）
├─ SceneInstance #0（根场景） ── bus0: [vm0, vm1]      ← 今天已有的形态
├─ SceneInstance #1（子场景） ── bus1: [vm2]           ← 新增：实例级归属
└─ SceneInstance #2（子场景） ── bus2: [vm3, vm4]
```

**数据怎么共享**（脚本之间不共享 JS/Lua 堆）：

| 通道 | 说明 |
|------|------|
| **世界状态（主通道）** | 组件字段 / `Transform` / UI 字段 / 自定义组件是唯一共享真相；所有 VM 读写同一棵扁平节点树（实例子树就在树里），不复制数据 |
| **节点事件** | `node_emit` 沿父链冒泡 + `node_on`（按实例作用域注册）；子实例事件可被父实例在挂载壳/祖先上监听 |
| **跨实例显式事件** | `scene_emit(instance, event, value)`；父 → 子在壳/子根上写组件字段（子 `on_start` 读取） |
| **持久化共享** | `storage`（键值）或场景文件的共享组件；VM 全局变量**不**跨 VM、不跨实例、也不序列化 |

**生命周期隔离的理由**：卸载一个实例时，必须能确定性地销毁**它自己的** VM/闭包/定时器，
并只对它的脚本派发 `on_destroy`；如果所有实例共用一个 VM，无法做到"卸载一半场景而不打断其它实例"，
同名 handler 也无法按实例区分。VM 只在 `.scn` 声明了脚本时创建，源码/字节码可按路径缓存，
并有实例数/VM 数预算（§8）。

**什么时候不要用每实例 VM**：大量同类对象（子弹/敌人/履带印）应走 **prefab（纯数据）+
根场景一个系统脚本批量驱动**（省 VM、缓存友好）；`SceneInstance` 适合**少量独立行为单元**
（关卡/弹窗/子游戏/复杂 AI 模块）。

## 5. 嵌套场景（SceneInstance）

### 5.1 声明（静态）

新增组件（`modules/core/data/schema/world/scn.yaml`）：

```yaml
- struct: SceneInstance
  fields:
    - { name: source,    type: string, default: "" }      # 相对**父场景目录**的 .scn 路径
    - { name: paused,    type: bool,   default: false }   # 只停行为，不隐藏
    - { name: active,    type: bool,   default: true }    # 等价 node_set_active（含渲染/命中）
    - { name: detached,  type: bool,   default: false }   # true = 已烘焙/自包含（不再按 source 实例化）
    # 运行期（transient，不序列化）：
    - { name: instance_id, type: int32_t, default: -1, attrs: { transient: true, readonly: true } }
    - { name: state,       type: int32_t, default: 0,  attrs: { transient: true, readonly: true } }
    - { name: error,       type: uint16_t, default: 0, attrs: { transient: true, readonly: true } }
```

语义：

- 组件持有者节点 = **挂载壳**（归属父实例），子场景根实体作为它的子节点；
  壳节点上的 `scn.Transform2D` 即子场景整体摆放（与世界坐标规则一致）。
- 加载期递归实例化，**循环检测**：实例化栈记录 source 路径链；A→B→A 报错并跳过该实例。
- 深度/数量预算：`MAX_INSTANCE_DEPTH=16`（默认）、`MAX_INSTANCES=256`、`MAX_INSTANCE_VMS=512`（可配）；
  超限 → 该实例进入 error 状态，父场景继续运行（不拖垮整个游戏）。
- 子场景的 `script`/`scripts` 是该实例的行为；`overlay_script`、`width/height/seed/gravity/env_*` 等
  **世界级字段**对嵌套实例无效（世界只有一个）：加载时打一行警告；未来若需要"局部世界"另立设计。
- prefab 与实例可以混用：子场景内部可以再有 prefab 展开 / 更深层 SceneInstance。
- **资源解析基准**：每个场景资产携带自身 base 目录（根场景 = 场景目录；嵌套 = 该 `.scn` 所在目录）。
  子场景内的 prefab、纹理、字体、脚本、mesh 路径一律**相对自身 base**解析
  （同时修复今天"prefab 内相对路径按根场景目录解析"的隐患）。

### 5.2 运行期行为

- 子实例的 VM 由该 `.scn` 的 `scripts` 创建（语言按扩展名，JS/Lua 可混用，顺序 = 声明顺序）。
- 只在实例有脚本时才创建 VM（纯数据场景零开销）。
- 每个实例一个 `mq_script_bus`（现有总线语义直接复用：按顺序、只投订阅者、错误隔离、帧边界 GC）。
- `paused`：跳过该实例及子实例的 `update`，但渲染/命中/其他系统照常（用于"关闭的弹窗逻辑"）。
- `active=false`：等价隐藏（复用 `node_set_active` 子树语义），行为也停（与树一致）。
- 卸载：先后序 `on_destroy` → 销毁 VM/总线 → 删除子树实体（帧边界统一执行）→ 句柄失效。
- 加载失败（文件缺失/JSON 错/脚本 eval 失败）：实例进入 error 状态，打日志 + 结构化事件；
  节点子树可保留为占位（便于编辑器诊断）或整体移除，由 `strict` 配置决定（默认保留占位、error 可查）。

### 5.3 热重载

- watcher 递归监视：根场景 + 所有实例的 `.scn` + 所有实例脚本 + overlay（今天只监视根脚本）。
- 脚本文件变化：只重建**使用该文件的实例**里的 VM（按文件增量），每个实例内槽位顺序不变；
  重建失败保留旧 VM（原子）。
- 实例源 `.scn` 变化：帧边界重建该实例（先构造新实例，成功后原子换入；失败保留旧实例）。
- 根 `.scn` 变化：维持今天"整世界重载"路径，但必须一并重建所有实例（内存/VM/监视列表清理干净）。

## 6. 序列化与反序列化

### 6.1 `.scn` v2 文档

```json
{
  "version": 2,
  "title": "...",
  "scripts": ["game.js", "ai.lua"],
  "overlay_script": "gallery.js",
  "width": 1280, "height": 720, "views": 1, "eye_sep": 0, "render_scale": 1.0,
  "seed": 1, "gravity_y": -900, "restitution": 0.86,
  "env_color": [0.27, 0.28, 0.31, 1], "env_intensity": 1.6,
  "msaa_samples": 0,
  "entities": [
    { "name": "Turret", "components": [
        { "type": "scn.Transform2D", "x": 100, "y": 120 },
        { "type": "scn.SceneInstance", "source": "modules/turret/turret.scn" } ] }
  ]
}
```

- **写出方式**：描述符（`scn.Scene`）走反射 `mq_persist_write_json` 自动覆盖**全部已有字段**，
  不再手写 7 个字段（以后加场景字段零改动）；实体/组件继续按类型排序、`transient` 跳过。
- **读取方式**：`version` 缺失 = v1（兼容）；未知字段忽略并计数告警；未知组件类型告警不中断。
- **确定性文本**：组件按 type_id 排序、字段顺序即描述符顺序、浮点格式统一 → 同一世界两次保存逐字节一致
  （e2e 断言）。

### 6.2 嵌套与 prefab 的保存规则

| 运行期状态 | 保存结果 |
|------------|----------|
| `SceneInstance`（`detached=false`） | 只写组件（`source`/`paused`/`active`），**不写**其生成的子树 → 重载后再实例化 |
| `SceneInstance`（`detached=true`） | 写组件 + 子树（自包含，不再按 source 加载）；`Scene.expand_instances` 负责烘焙 |
| `PrefabInstance`（`detached=false`） | 只写组件（保持今天的 `prefab_e2e` 行为） |
| `PrefabInstance`（`detached=true`） | 写组件 + 展开子树（今天的 `Scene.expand_prefabs` 语义） |

- 保存时按 `owner_instance` 过滤：**只写根实例拥有的实体** + 实例壳节点；
  子实例生成的实体不写（它们由 source 决定）。
- 编辑器若要让实例内容"可独立修改"，走 `detached`（烘焙）；未烘焙实例的子树视为只读派生数据
  （编辑期修改应改源 `.scn`，与 prefab 一致）。
- `Meta.stable_id` / `Meta.source_scene` / `Meta.source_prefab` 在实例化时写入：
  - `stable_id`：由（父场景路径、实例内节点路径、兄弟序）确定性哈希生成；写盘后成为持久 id；
  - `source_scene`：该节点所属实例的 source（根场景节点写根场景路径）；
  - `source_prefab`：prefab 展开来源。
  这为将来的引用重绑、增量保存、编辑器 undo 提供锚点（字段已在 schema，只是从未赋值）。

### 6.3 快照（与存档区分）

| 产物 | 内容 | 用途 |
|------|------|------|
| `.scn` 存档（`Scene.save`） | 场景组成（资产级、保引用、可再实例化） | 编辑/发布/热更 |
| 世界快照（`World.snapshot`） | 运行期状态（实体/组件扁平编码） | 回放/undo/回滚 |

- 快照块扩展：末尾追加 **实例表**（instance_id、source、attach_entity、root_entities、paused、owner 映射），
  版本化编码；旧快照可读（实例表缺失 → 修复为单实例）。
- `World.restore` 后：实体/组件恢复；实例表重建实例记录；VM 若 source 未变则保留（状态不丢失），
  若 source/脚本变化则重建并派发 `on_start`；结构不兼容（实例表对不上）→ 明确失败，不做半恢复。
- `world_trail` 纳入实例表（id/source/root）→ 回放能检出"实例结构漂移"。

### 6.4 验收（round-trip）

`load(save(scene)) ≡ scene`：实体数、实例树、每个实体 `owner_instance`、组件字段值、
脚本声明、场景级字段、稳定 ID 全部一致；未烘焙实例不产生重复子树；保存两次逐字节一致。

## 7. 动态实例化接口

### 7.1 脚本 API（`runtime/host.yaml`，生成 JS/Lua 绑定）

```yaml
# 实例生命周期（变更类；帧边界生效）
- { fn: scene_instantiate, ctx: true, args: [parent: float, path: string, params: string], returns: float }   # params=JSON（可省略）
- { fn: scene_unload,      ctx: true, args: [instance: float], returns: float }
- { fn: scene_reload,      ctx: true, args: [instance: float], returns: float }
- { fn: scene_set_instance_paused, ctx: true, args: [instance: float, paused: float] }
- { fn: scene_set_instance_active, ctx: true, args: [instance: float, active: float] }
# 实例参数（§16.2）：父场景 → 子场景的 JSON 配置
- { fn: scene_self_params,          ctx: true, returns: string }
- { fn: scene_instance_params,      ctx: true, args: [instance: float], returns: string }
- { fn: scene_set_instance_params,  ctx: true, args: [instance: float, params: string], returns: float }
# 查询（只读；立即反映已提交状态）
- { fn: scene_instance_valid,  ctx: true, args: [instance: float], returns: float }
- { fn: scene_instance_root,   ctx: true, args: [instance: float], returns: float }   # 壳/根实体 id
- { fn: scene_instance_parent, ctx: true, args: [instance: float], returns: float }
- { fn: scene_instance_source, ctx: true, args: [instance: float], returns: string }
- { fn: scene_instance_paused, ctx: true, args: [instance: float], returns: float }
- { fn: scene_instance_count,  ctx: true, returns: float }
- { fn: scene_instance_at,     ctx: true, args: [index: float], returns: float }      # 创建/声明顺序
- { fn: scene_instance_of,     ctx: true, args: [entity: float], returns: float }    # 实体所属实例
# 当前脚本上下文
- { fn: scene_self,       ctx: true, returns: float }
- { fn: scene_self_root,  ctx: true, returns: float }
# 跨实例事件
- { fn: scene_emit, ctx: true, args: [instance: float, event: string, value: float], returns: float }
# 错误自省
- { fn: scene_last_error, ctx: true, returns: string }
```

语义要点：

- **句柄立即分配，构建延迟**：`scene_instantiate` 返回的 id 立即可用于后续查询/取消；
  实体、VM、`on_start` 在**下一个帧边界**完成。`scene_instance_valid` 在构建完成后才为真。
- `parent = -1`：挂到世界根（根实例的顶层），用于"动态关卡/模态场景"。
- `scene_unload` 延迟到帧边界，**脚本阶段结束后**执行（保证当前 update 不被半路拆掉）。
- 同一帧内的请求按调用顺序（FIFO）执行；一次边界内新实例的 `on_start` 里再请求实例化 → 排到下一个边界
  （禁止递归构建，防爆栈/IO 帧内抖动）。
- 失败返回 -1 并记录 `scene_last_error`（路径不存在/循环/深度/预算/脚本错误），不崩溃不静默。
- 根场景/overlay 脚本可以实例化任意场景；子实例脚本只能实例化"自己子树内"的挂载点
  （或显式授权，见开放决策 D4）。

### 7.2 控制面（`control_list`）

| 方法 | 类型 | 说明 |
|------|------|------|
| `Scene.instances` | 只读 | 实例树：id/source/parent/root_entities/paused/state/error/script 列表 |
| `Scene.instance_info` | 只读 | 单实例详情（含 VM 数、脚本错误计数） |
| `Scene.instantiate` | 变更 | `{parent, path, strict?}` → `{instance}`；走与脚本同一队列 |
| `Scene.unload_instance` | 变更 | `{instance}` |
| `Scene.reload_instance` | 变更 | `{instance}` |
| `Scene.bake_instances` | 变更 | `{dry_run}` → 把实例标记 detached 并落盘可自包含（对齐 `Scene.expand_prefabs`） |

变更类方法遵守控制面 D2 只读会话规则（`control_mutating`）。

### 7.3 C ABI（为将来 scene 模块化预留）

若后续把场景实例化下沉到 `modules/world/scene`（plans/11），接口按 `docs/02` 冻结为：

```c
    int      (*unload)(void* self, int32_t instance);
    int      (*info)(void* self, int32_t instance, mq_scene_instance_info* out);
    int      (*instantiate_pending)(void* self);   /* 帧边界 pump：返回本次提交数 */

```

### 7.4 错误模型

| 错误 | 返回 | 诊断 |
|------|------|------|
| 路径不存在 / 不是 `.scn` | -1 | `scene_last_error` + obs 事件 |
| 循环实例化（source 链） | -1 | 错误信息含环上路径 |
| 深度/实例数/VM 数超限 | -1 | 同上 + 计数器 |
| 脚本 eval 失败 | 实例创建但 error=SCRIPT | 保留节点/停止行为，可 reload |
| 未知组件/字段 | 继续 | 结构化告警（计数） |
| 卸载不存在的实例 | 0 | 不崩溃 |

## 8. 确定性、性能与可观测性

- **确定性**：实例创建顺序、静态声明顺序、动态调用 FIFO、派发顺序（§4.3）、GC 帧边界逐 VM 顺序全部固定；
  新增用例用 `world_trail` 断言同 seed/输入下逐帧一致。
- **性能**：只有带脚本的实例创建 VM；脚本源码/字节码可按路径缓存（同 source 的多个实例共享已解析源码）；
  `scene_instance_of` 用实体上的 `owner_instance` O(1)；事件路由不引入每帧哈希重建。
- **预算**：实例数/总实体/总 VM 计数，超限报错；`MAQUE_SCENE_INSTANCE_LIMIT` 环境变量可调（诊断/CI）。
- **可观测**：Tracy zone 增加 `scene.instance.instantiate/unload`、按实例名的 `script.update` 细分；
  `Scene.instances` / inspector 展示实例树；崩溃上下文带"脚本 → 实例 → handler"调用链。

## 12. 风险与开放决策
| 风险 | 处理 |
|------|------|
| 每实例 VM 的内存/启动开销 | 无脚本实例零 VM；源码/字节码按路径缓存；实例数预算 + 指标 |
| 事件路由从"广播"改为"作用域"引入行为差异 | 根实例/overlay 保留广播能力（根=全树可见），老场景零回归；新增作用域只影响嵌套实例 |
| 子实例脚本仍能访问全局实体（越权/串扰） | P1 明确"全树可读、作用域内可注册"；能力沙箱/子树限制列为 D4 后续 |
| 保存/快照语义分叉 | §6.3 明确两类产物；e2e 锁 round-trip 与 restore |
| 嵌套资源路径解析改变既有 prefab 行为 | 先加"相对自身 base"解析 + 回归测试；无相对路径的旧资产不受影响 |
| 动态实例化在脚本栈内递归/IO 抖动 | 帧边界队列 + 禁止同边界递归 + 预算 |
| 热重载实例源导致状态丢失 | 原子换入（失败保留旧实例）；文档明确"重载=状态重置"边界 |

**开放决策（建议默认值，待确认）**

- **D1 嵌套场景的世界级字段**（width/height/seed/gravity/env）：建议**忽略并警告**（世界只有一个）；
  "局部世界"另立设计（大工程）。
- **D2 `on_start` 顺序**：建议**后序**（子先父），对齐 Godot `_ready`；若希望父先配置子，可改用"父 `on_enter` /
  子 `on_start` / 父 `on_start`"三段式（P1 前定稿）。
- **D3 键盘/文本事件**：建议**所有 active 实例都收到**（今天的全局键盘语义），指针按 target 作用域。
- **D4 子实例脚本的世界可见性**：建议 P1 **全树可读**（最小改动、够用），后续可加 `sandbox` 能力位；
  越界 `node_on` 已先限制。
- **D5 保存默认**：建议**保引用**（不烘焙）；`bake:true` / `Scene.bake_instances` 显式烘焙。
- **D6 节点级 `script.Script`**：建议**不并入本文**，作为后续独立特性（场景脚本 + 节点脚本两层模型）。

## 16. 全局脚本、全局状态与实例参数（P5，2026-10）

> 目标：让 `.scn` 组合从"父场景把子场景当无参数模块"升级为**可配置、可共享服务**的模块树，
> 并提供真正跨场景存活的游戏服务层。示例：`scenes/td/`（小小塔防）。

### 16.1 全局脚本（`scn.Scene.global_script`）

与 `overlay_script` 同形但语义不同：

| | `overlay_script` | `global_script` |
|---|---|---|
| 定位 | 视图/HUD/导航外壳 | 游戏级服务（进度/存档/跨场景规则） |
| 生命周期 | 跨 `director_load_scene` 保留 | 同左 |
| 派发顺序 | 实例之后（最后） | 实例之后、覆盖层**之前** |
| 寻址 | 节点事件/输入 | 节点事件/输入 + `global_emit(event, value)` |

- 独立 VM/总线（`Engine::global_bus`），只允许**根场景**声明；嵌套场景声明会按世界级字段忽略并警告。
- 同一路径复用已有 VM（跨场景状态保留）；路径变化 → 换脚本（状态重置）。热重载与 overlay 同规则
  （原子换入、失败保留旧 VM、换入后派发一次 `on_start`）。
- `on_start` 在根实例（含子实例）on_start 之后、overlay 之前，每个场景装配后一次；`update` 每帧在实例之后；
  键盘/指针输入同样在实例之后、overlay 之前。`node_on` 归属 `-3`（可监听任意节点）。
- `global_emit(event, value)` 只调用全局脚本里名为 `event` 的处理器，返回命中数（跨场景服务入口）；
  反向通信仍用 `node_emit` / `scene_emit` / 全局状态。
- 场景未声明 `global_script` 时**保持现有全局脚本**（与 overlay 相同）——菜单/关卡可以只在入口声明，
  也可以各自声明同一路径（推荐，便于单场景直跑）。

### 16.2 实例参数（`scn.SceneInstance.params`）

```yaml
- struct: SceneInstance
  fields:
    - source: string
    - params: string          # JSON 文本；父场景 → 子场景
    - paused / active / detached / instance_id / state / error
```

- 静态组合：关卡 `.scn` 里写 `params: "{\"tier\": 2}"`；加载期在 `build_instance` **之前**写入实例记录，
  子场景 `on_start` 用 `scene_self_params()` 读取。
- 动态组合：`scene_instantiate(parent, path, params)` 在**入队时**写入，帧边界构建 → 子脚本必能看到；
  也可在构建前用 `scene_set_instance_params(inst, params)` 改写（已构建实例需 `scene_reload` 才重读）。
- 参数是**纯数据**（JSON 字符串），不共享 VM 堆；子场景自行解析/校验（示例里 `try { JSON.parse } catch`）。
- 持久化：静态实例的 `params` 随组件反射保存；动态实例的挂载壳由 `ensure_instance_component` 写回
  `params`/`source`/`paused`/`active`，因此 `Scene.save` 后重载仍可复原。

### 16.3 全局状态（`global_set/get/...`）

- `Engine` 实例内**唯一一份**键值：`std::map<string,double>` + `std::map<string,string>`（数值/文本分开，
  同键可同时存在两种值）；**所有 VM 共享**（根/子实例/全局脚本/overlay），不进入任何 VM 堆。
- API：`global_set/get`、`global_set_text/get_text`、`global_has/remove/clear/keys`。
  `global_keys` 返回按键字典序的 JSON 数组（确定性）。
- 确定性：键有序遍历 → `world_checksum` 稳定；空状态不混入校验和（老场景 `world_trail` 零变化）。
- 快照：世界快照在实例表**之前**追加 `MQGL` 块（数值/文本全量）；`World.restore` 先恢复全局状态，
  再重建实例并派发 `on_start`（脚本能读到恢复后的值）。旧快照无该块 → 探测 magic 失败、保持现状。
- 边界：全局状态是**运行期**共享状态，不写进 `.scn`；需要跨进程持久化请用 `storage`（docs/25），
  由全局脚本在开始/结算时读写。

### 16.4 动态实例的挂载壳清理与实体 id 单调

动态 `scene_instantiate` 自动创建的挂载壳属于**父**实例；此前卸载子实例只删子实体、空壳残留。
`SceneInstanceRuntime::owns_shell` 记录该壳由实例创建，卸载时一并删除（避免每波敌人在世界根累积空节点）。

`Scene::spawn` 的"实体 id 单调、永不复用"契约现在**跨场景重建/热重载/快照回滚**也成立：
`load_scene_into`/`reload_scene` 把旧世界的 `next_id` 水位带到新场景，`Scene::decode` 取
`max(旧水位, 快照 max+1)`。否则常驻脚本（global/overlay）持有的旧 id 会在切场景后**别名到新场景实体**
（示例：HUD 的 `destroyHud` 会误删关卡里的塔/节点）。

### 16.5 示例：小小塔防（`scenes/td/`）

```
scenes/td/
  menu.scn + menu.js              # 菜单（选关/继续/重置）
  global.js                       # 全局脚本：HUD + 进度 + 结算 + 全局热键
  level{1,2,3}.scn + .js          # 3 个独立关卡（路径点/预置塔/波次）
  towers/{arrow,cannon,frost}/    # 3 个独立塔：各自 .scn + 行为脚本，可单独运行
  enemies/{slime,runner,tank,flyer}/  # 4 个独立敌人：各自 .scn + 行为脚本，可单独运行
```

组合链路：

1. 菜单把 `td.level` 写入全局状态并 `director_load_scene(levelN.scn)`；
2. 关卡 `.scn` 用 `scn.SceneInstance` + `params.tier` 预置塔；关卡脚本读 `WP*` 路径点，
   用 `scene_instantiate(-1, "enemies/...", params)` 动态生成敌人（params 带 hp/speed/path/uid）；
3. 塔扫描 `/enemies/` 实例，读挂载壳位置，`scene_emit(enemy, "on_damage", v)`；敌人死亡/泄漏时
   `scene_emit(parent, "on_enemy_dead|on_enemy_leak", uid)`；关卡更新全局金币/生命/分数；
4. 胜负时关卡 `global_emit('level_finished', 1|2)`；全局脚本解锁、写提示、画横幅，2.4s 后切回菜单；
5. `global.js` 的 VM 跨场景保留（`td.unlocked/td.best/td.notice` 不丢），HUD 每次按新场景重建。

测试：`ctest -R td_e2e`（菜单→关卡 / 直接通关→解锁→回菜单 / 确定性 / 锁定·重置 / 3 关独立装载 /
7 个塔/敌人场景单独运行并 `--shot`）。

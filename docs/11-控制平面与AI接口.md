# 11 · 控制平面与 AI 接口

> 上游：`00` A4、`16`（CDP 同构）、`09`（观测）、`10`（回放）、`04`（VFS）、`02`（模块）。
> 本文是 **A4 的落点**，也是 maque 相对传统引擎的**核心创新**：
> 引擎把自己暴露成**统一的、可编程的驱动面**，AI / CI / 编辑器 / 工具共用一套协议。

## 1. 定位

- 所有能力都有 **headless 操作面**：加载、运行、调试、预览、采集。
- **一套协议**服务所有消费者（AI、CI、编辑器、脚本化工具）。
- 模型**对齐 CDP**（文档 16 §4）：**domain / method / event**。

## 2. 协议栈

```
┌──── MCP（上层，面向 AI 工具生态）────┐
│  tools / resources / notifications     │
├──── JSON-RPC（底层，稳定契约）─────────┤
│  domain.method(params) → result/error  │
│  domain.event（订阅/推送）             │
├──── 传输 ──────────────────────────────┤
│  stdio · TCP · WebSocket · WASM 内 JS 桥 │
└────────────────────────────────────────┘
```

- 底层 **JSON-RPC 对齐 CDP 风格**：`domain` 分组、`method` 调用、`event` 推送。
- **MCP 作上层包装**：把 domain 暴露为 MCP tools/resources，event 暴露为 notifications。
- 传输可插拔：本地 stdio、远程 WebSocket；**WASM 里经 JS 桥 / WebSocket**（文档 05）。

## 3. Domains（对齐 CDP 的分组）

| domain | 能力 |
|--------|------|
| `Instance` | 创建/列举/切换**多实例**（ADR-0014） |
| `Runtime` | 求值、读取运行时值、内存/指标 |
| `Types` | 反射自省：类型/字段/属性（文档 06，A1） |
| `Scene` | 查询/编辑节点树、实例化场景、快照/恢复（文档 12） |
| `VFS` | 挂载、列举、读/写、路径解析（文档 04） |
| `Asset` | 导入、依赖、烘焙、打包、dump（文档 08） |
| `Renderer` | **截帧 / 离屏预览**（WebGPU readback，文档 13） |
| `Script` | 求值、断点、单步（文档 14） |
| `Perf` | 计数器、trace、帧捕获（文档 09） |
| `Log` | 结构化日志尾部、订阅（文档 09） |
| `Replay` | 载入快照、喂输入、取 checksum（文档 10，A3） |
| `Debugger` | 断点、暂停、状态检查 |
| `Module` | 加载/卸载/热重载插件（文档 02） |

## 4. 语义约定

- **结构化错误**：`std::expected` 风格（ADR-0012），错误码 + 上下文。
- **事务 / dry-run**：破坏性操作可先 `dry_run` 预览影响（利于 AI 安全试错）。
- **事件订阅**：状态变更、崩溃、日志、指标为**推送事件**，AI 可持续订阅。
- **幂等性**：查询类幂等；变更类返回**句柄/版本**以便回滚。

## 5. AI 工作流（本设计的靶心）

被显式支持的标准动作序列（也就是你要的"AI 能自主加载、调试、预览、采集"）：

```
Instance.create → VFS.mount("assets/", "https://microgames.org/xxx")
→ Scene.load / Asset.cook → Replay.load(snapshot, seed, inputs)
→ Replay.step(n) → Renderer.capture_frame → Types/Scene.dump
→ Perf.sample / Log.tail / 触发崩溃 → 取崩溃报告（文档 09）
→ Replay.replay 复现 → 验证修复（checksum 对比）
```

每一步都是稳定、结构化、可脚本化的调用。

## 6. 预览（Preview）

- 无 GUI 也能"看"：`Renderer.capture_frame` 做**离屏渲染 → readback → 图像流**（文档 13）。
- WASM/嵌入式同样支持（WebGPU 离屏）。
- AI 以图像 + 指标 + dump 三者交叉判断渲染正确性。

## 7. 安全与权限

- **控制平面本身要鉴权**（尤其远程/CI 场景）。
- **能力门控（capability）**：远程加载的游戏（OD-9）只能调用被授权的 domain/method。
- 与浏览器对照：origin + 权限 → 对应 domain 级授权（文档 16 §4）。
- 破坏性操作默认 dry-run / 需显式确认。

## 8. 多实例

- 所有 method 带 `instance_id`（或先 `Instance.select`）。
- 实例间**完全隔离**（ADR-0014），控制平面可并行驱动多个实例（如 AI 同时跑多组实验）。

## 9. 为什么对齐 CDP

- 生态与心智成熟：AI、编辑器、测试框架都熟 CDP 范式。
- 工具可复用（协议 dump / 录制 / 回放）。
- MCP 让 AI **零适配**接入。

## 10. 遗留风险

| 风险 | 处理 |
|------|------|
| 控制平面对性能的影响 | 独立线程/传输；模拟线程只处理必要事件 |
| 远程控制面安全 | 鉴权 + capability 门控 + dry-run |
| 协议膨胀 | domain 分组 + 版本化 + 只暴露稳定子集 |
| WASM 传输受限 | JS 桥 / WebSocket 双路径 |
| 事件风暴 | 订阅过滤 + 采样 + 背压 |

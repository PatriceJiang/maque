# 14 · 脚本（quickjs 为主 + 可选 VM）

> 上游：ADR-0008（quickjs 主 + refcount）、`06`（反射生成绑定）、`12`（生命周期）、`09`（诊断）、`02`（模块）。
> 定位：脚本是**游戏逻辑层**，运行在**模拟线程**、**单线程**、**确定**的前提下（ADR-0018 / ADR-0005）。

## 1. VM 策略

- **主 VM = quickjs**：体积小、无 JIT、启动快、**内部 refcount**（ADR-0008）。
- 其它 VM（**lua / python / v8**）为**后续可选后端**，**构建期裁剪**，仅打包所选。
- **统一后端 ABI**（沿用文档 02 的 C ABI + 版本化 vtable）：

```c
typedef struct mq_script_vm_v1 {
    uint32_t struct_size; uint32_t abi_version;
    int  (*create)(void* host, void** out_vm);
    int  (*eval)(void* vm, const char* src, const char* name);
    int  (*call)(void* vm, const char* fn, const char* json_args);
    int  (*register_host_fn)(void* vm, const char* sig, void* fn);
    void (*gc_step)(void* vm, size_t budget);   /* 帧边界驱动 */
} mq_script_vm_v1;
```

- 换 VM 只换实现，**上层与绑定层不变**。

## 2. 绑定：从反射生成，禁止手写

- 所有宿主类型/函数绑定的**签名与编解码**由**反射描述符**生成（文档 06 §6）。
- 参数/返回值经**序列化中枢**（文档 08）在脚本值与 POD 之间转换。
- 原则：**新增引擎 API → 自动出现在脚本**；手写绑定视为 bug 源。

## 3. 宿主 API 面与能力门控

- 脚本能调用的是一张**受控 API 表**（非裸引擎指针）。
- **capability 门控**（文档 11 §7 / OD-9）：远程游戏只能访问**被授权的** API（如禁文件写入、禁网络）。
- 调用经**句柄**（文档 07），不暴露裸指针。

## 4. 生命周期（对齐文档 12 §6）

脚本注册回调，引擎在**固定点、确定顺序**调用：

```
on_enter_tree → ready → [ process(dt) | physics_process(dt) ]* → on_exit_tree → on_destroy
```

- 回调内**禁止**：阻塞、发起异步（帧内无异步，文档 04 §6）、隐式 GC 风暴。
- 顺序确定（深序 + 声明序）→ 回放一致（文档 10）。

## 5. 确定性（OD-5 落点）

- **refcount + 帧边界 GC**：quickjs 的 **cycle GC 只在帧边界 `gc_step`** 驱动，
  **模拟帧内禁止隐式 GC**（否则析构时机不确定 → 回放漂移）。
- 脚本 RNG 必须用**引擎 RNG**（文档 10 D2），禁 `Math.random` 直连系统熵。
- 脚本运行在**模拟线程**（ADR-0018）；不跨 worker 共享可变 JS 对象。
- 对象析构的**外部副作用**（真正释放 GPU 资源等）延迟到确定点。

## 6. 沙箱（远程内容安全，ADR-0030）

- 远程游戏（`https://microgames.org/xxx`）的脚本跑在**受限沙箱**：
  - API 能力白名单；无原生宿主调用；有资源/时间预算。
  - 完整性由**内容哈希校验**保证（VFS/资产层，文档 04 §9）。
- **浏览器**：叠加 WASM 沙箱（文档 05 §7）→ 双层隔离。
- **原生/嵌入式**：自建沙箱（能力门控 + 可选进程隔离，文档 16 §4）。
- **签名链**为二期，暂不做。

## 7. 热重载

- 脚本源**文本入库**（文档 08）→ 变更监听 → 重载**在帧边界**替换（文档 02 §6、12 §6）。
- 重载时**保留实例状态**：序列化脚本可见状态 → 重建 VM 上下文 → 反序列化。

## 8. 诊断

- 脚本错误 → **结构化异常**（含 VM 栈 + 宿主栈拼接，文档 09 §5）。
- 脚本求值/断点/单步经控制平面 `Script` domain（文档 11 §3）。
- 性能：脚本耗时计入指标（文档 09 §3）。

## 9. WASM 平台

- quickjs 可编译为 WASM（体积小，天然合适）。
- 与宿主浏览器共享同一个 WASM 沙箱；脚本 VM 实例随引擎 instance（ADR-0014）隔离。

## 10. 遗留风险

| 风险 | 处理 |
|------|------|
| 隐式 GC 破坏回放 | GC 仅帧边界驱动；帧内禁隐式（§5） |
| 手写绑定漂移 | 一律反射生成；评审拦截 |
| 远程脚本越权 | capability 门控 + 沙箱（§6） |
| VM 语义分叉（多 VM） | 统一后端 ABI + 绑定层；二期再评估 lua/python/v8 |
| 脚本阻塞模拟 | 禁阻塞/异步/高频分配；预算与看门狗 |
| 脚本栈不完整 | VM 栈 + 宿主栈拼接（文档 09） |

## 脚本后端（多语言，统一 ABI）

**已实现的后端**：

| 语言 | 后端 | 选择方式 | 备注 |
|------|------|----------|------|
| JavaScript (ES2023) | quickjs-ng（vendored） | `.js`（默认） | 主后端 |
| **Lua 5.4** | 官方源码（vendored，`third_party/lua`） | **`.lua`** | 沙箱运行；`-DMAQUE_ENABLE_LUA=OFF` 可裁剪 |

- **语言由脚本文件扩展名决定**（`mq_script_lang_for_path`）：`"script": "game.lua"` 即用 Lua；
  也可显式 `mq_script_vm_create_lang("lua")`。未编入的后端**明确报错**（不静默降级），
  自省用 `mq_script_backends()` / `mq_script_lang(vm)`。
- **同一套 API 面**：宿主函数、命名空间、事件回调（`on_start` / `update(dt)` /
  `on_pointer_down(target,x,y)` / `on_text` …）在两种语言下**同名同义** ——
  绑定由 DSL 生成（docs/21），后端只负责把函数注册进 VM，脚本侧无需为语言写两遍。
  · JS：`math.clamp(...)`；Lua：同样 `math.clamp(...)`（**合并**进 Lua 的 `math` 标准库，
    保留 `abs/floor/…`）；命名空间 `hud.score` 在 Lua 侧落到表 `hud.score`。
- **值语义**：数值统一按 double 传递（Lua 5.4 整数自动转换）；字符串经宿主缓冲复制
  （返回字符串的 API 两后端一致）。
- **沙箱（Lua）**：只开基础库（base/table/string/math/utf8）；移除
  `io/os/package/debug/coroutine/require/dofile/loadfile/load/collectgarbage` ——
  脚本不能触达外部世界，也不能自行改变 GC 时机。
- **确定性（两后端一致，docs/10）**：
  · `Math.random()` / `math.random()` 都由**引擎 RNG** 接管（同一 seed → 同一序列 → 可回放）；
  · GC 只在**帧边界**推进（`mq_script_frame_boundary`）：JS 走 cycle GC，Lua 停用自动步进 + 固定步数；
  · 脚本错误**受保护调用**（`pcall` / JS exception）：记录 `last_error` 并写崩溃上下文，不中断引擎。
- **跨语言一致性**：`tests/lua_e2e.sh` 用同一份语义的 js/lua 场景 + 相同模拟输入，
  断言**帧数与 world_trail 完全相同**（当前：436 帧 / `0xf6be9d00b5636e7d`）——
  这是"统一后端 ABI"最强的正确性证据。

### 多 VM 与跨语言协作（事件总线）

一个场景可以有**多个脚本、不同语言**：`"scripts": ["game.js", "ai.lua"]`。

- **事件总线**（`mq_script_bus_*`，模块 ABI 声明 → `abi/script.h`）持有全部 VM，负责投递。
  总线**拥有** VM（销毁总线即销毁全部 VM）。
- **投递语义**（确定性可证）：
  · **顺序 = 声明顺序**（`scripts` 数组顺序 = 事件投递顺序）；同一事件在所有 VM 中的相对顺序固定；
  · **只投给订阅者**：定义了该处理器（`mq_script_has`）的 VM 才收到调用；
  · **载荷只有标量与字符串**（现有 `(a,b[,c],text)` 语义）→ 跨语言不共享对象/表，**事件即消息**；
  · **错误隔离**：每个 VM 独立受保护调用；出错只记录（`mq_script_bus_error_count` 单调递增），
    调用方按**增量**判定是否写崩溃上下文 —— 不中断其它脚本；
  · **GC 逐 VM 在帧边界推进**（docs/10 D7），多 VM 不改变 GC 时机。
- **跨语言怎么用**：处理器按**名字**路由，因此不需要额外协议 ——
  JS 侧 `node_on(id, "ai_tick", "on_ai_tick")` 注册、`node_emit_number(id, "ai_tick", v)` 触发；
  只要某个 VM 定义了 `on_ai_tick`，事件就落到它（哪怕语言不同）。
- **宿主 → 脚本**同一条路：控制面 `Scene.emit`（变更类方法，只读会话拒绝）与脚本内 emit 等价。
- **RNG 一致**：`mq_script_bus_set_rng` 给全部 VM 注入同一引擎 RNG → 两种语言同一 seed 同一序列。
- 验证：`ctest -R multilang`（双语言装载 / 声明顺序 / 双向跨语言事件 / 确定性 / 宿主 emit），
  样例场景 `scenes/multilang/`（JS 玩法 + Lua AI）。

### 热重载（多脚本、按文件、原子）

改脚本**不重启游戏**即生效；`MAQUE_WATCH=1` 开启（监视场景 + **全部**脚本文件）。

- **按文件增量**：只重建**被改动**的那个脚本的 VM，其余脚本继续运行 ——
  改 `ai.lua` 不会打断 `game.js`（它的状态、实体、定时器都保留）。
- **顺序不变**：替换发生在**原槽位**（`mq_script_bus_swap`），投递顺序仍等于声明顺序 → 确定性不受影响。
- **原子**：先创建新 VM 并 eval，**成功才换入**；失败则销毁新 VM、**保留旧的**并打印错误
  → 写坏一个脚本不会让运行中的游戏失去该逻辑（"热更出错不致命"）。
- **换入后只对新 VM 派发一次 `on_start`**：脚本借此重新初始化并**重新注册事件处理器**
  （否则热更后 `node_on` 注册丢失 → 收不到事件、功能静默失效）。
- 触发方式：`MAQUE_WATCH=1`（文件监视，帧边界每 6 帧轮询）或控制面 `Reload.script` / `Reload.scene`
  （`dry_run=1` 只报告不执行）。
- 验证：`ctest -R hot_reload`（原有单脚本热更 + `hot_reload_multi_e2e`：Lua 增量生效 /
  JS 状态保留 / 顺序不变 / 坏脚本原子回退）。

> 状态迁移：热重载得到**全新词法作用域**（VM 重建），需要跨重载保留的状态由脚本显式放在
> `globalThis`（JS）或模块级 upvalue 之外（Lua）—— 这是刻意设计：热更不应隐式继承旧闭包。

### 再加一个后端（如 Python / V8）

1. `modules/script/src/<lang>_backend.cpp`：实现 `vm_base.h` 里同形的函数集
   （`vm_create/vm_destroy/eval/has/call0..call2s/last_error/set_rng/gc/register_*/frame_boundary`），
   `vm_create` 里把公共首部 `lang` 设成语言 id；未编入时返回 `nullptr`；
2. `modules/script/src/script.cpp` 的 `mq_script_vm_create_lang` 增加分支（并 `mq_script_lang_for_path` 认识新扩展名）；
3. `modules/script/CMakeLists.txt` 加源文件与可选开关（构建期裁剪，见 docs/14 §9）；
4. 绑定与 runtime **无需改动**（宿主注册走 ABI）；
5. 测试：后端单测 + e2e 跨语言一致性。

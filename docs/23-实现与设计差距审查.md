# 23 · 实现与设计差距审查（诚实版）

> 结论先行：现状是**"一条纵向切片 + 若干地基"**，demo（WebGPU 球）能跑；
> 但**多条设计主线几乎未动**，且**部分地基与设计相悖**。偏离的根因是"先做可见结果、越过硬约定"。

## 0. 一句话结论

**引擎的"浏览器/插件/确定性/可观测/控制面"主干基本没建；
且已建的地基里，模块不是插件（全 STATIC）、反射是全局可变状态、渲染接口是 C++ 虚类、
引擎硬编码了游戏组件**——这些是必须先纠正的**方向性错误**。

## 1. 与设计相悖的"地基错误"（最该先修）

| # | 设计（docs/ADR） | 现状 | 后果 |
|---|------------------|------|------|
| G1 | 模块编译为**独立 `.so`**，跨边界 C ABI + registry（docs/02, ADR-0007） | **全部 `STATIC` 静态库**，链接进单一可执行文件；`maque::module`(dlopen) 建了却**无人使用** | 插件化/热重载/模块边界名存实亡 |
| G2 | **零全局可变状态**（ADR-0014, 多实例） | `mq_reflect` 用 `static` 全局注册表 | **多实例不成立**（实例间共享类型注册表） |
| G3 | 跨模块接口 **C ABI**（docs/02） | `maque::render::Renderer` 是 **C++ 抽象类**（含 `std::vector/std::string`） | 违背 C ABI 约定，无法跨 `.so`/语言 |
| G4 | 引擎通用、游戏资源化（docs/20） | runtime **硬编码** `scn::Sprite`/`scn::Transform2D`（`tid_sprite`、`reinterpret_cast<scn::Sprite*>`） | 加一个新组件要**改引擎**；不是通用引擎 |
| G5 | 绑定**由反射生成**、禁手写（docs/21, ADR-0026） | 宿主 API（`log/cfg/entity_*/draw_sprite`）**全是 runtime 手写注册**；仅 `math.*` 生成 | 绑定漂移、"声明+生成"只做了一半 |

## 2. 设计主线：整块缺失

| 指标/主线 | 设计 | 现状 |
|-----------|------|------|
| **A2 可观测** | 结构化日志 / 指标 / trace / 崩溃上下文（docs/09） | **无**（仅 `std::print`） |
| **A3 确定性/回放** | 输入即数据、回放、快照/回滚、checksum、失步检测（docs/10） | **无**（只有固定 dt / 引擎 RNG / 帧边界 GC） |
| **A4 控制平面** | JSON-RPC（CDP 式）+ MCP（docs/11, 16） | **无** |
| **A1 自省（服务化）** | AI 可查询/驱动（docs/06/11） | 数据层反射有雏形；**未对 AI 暴露** |
| **平台/输入** | SDL2 窗口 + 事件分发（docs/05/19） | SDL2 模块存在，**runtime 不用**；输入仍是"脚本点击" |
| **executor/async** | coroutine + libuv（ADR-0010） | **无** |
| **资产管线 `ai`** | 导入/依赖/烘焙/打包/压缩/dump（ADR-0009, docs/08） | **无** |
| **场景双视图** | 节点树→bake→ECS、Prefab 实例化/重绑、生命周期回调（docs/12） | **无**（有扁平的实体/组件） |
| **WASM/浏览器** | 一等目标平台（ADR-0016, docs/05） | **零实现** |
| **热重载** | 帧边界换 `.so`/脚本（docs/02/14） | **无** |
| **物理/动画/粒子/导航/音频** | docs/15 | **无** |
| **`asset_ref`/稳定 ID/内容哈希** | docs/06/07/04 | **无** |

## 3. 半成品（有壳无实）

- **VFS**：仅 `file://` + curl URL；无 `mem/zip/res`、无挂载矩阵、无异步、无内容哈希（ADR-0030）。
- **脚本**：无生命周期（`on_enter_tree/ready/…`）、无 capability 沙箱、无热重载；绑定仅标量。
- **渲染**：无相机/投影/3D/pass 层；`DrawItem` 只有一种精灵；多视图无相机语义。
- **组件**：只有 2 个类型；**无运行时按类型增删查的脚本 API**；无 system/调度。
- **持久化**：只有 JSON→struct；无 binary codec、无 backend 抽象、无引用/稳定 ID。
- **handle**：世代槽表有了；但**分类分配器/arena/pool、分配者释放**未落地（docs/07）。
- **多实例**：`mq_reflect` 全局 + `mq_run_scene` 单次运行 → **无法真正多实例并存**。

## 4. 代码层面具体问题（抽样）

- `Scene` 用 `unordered_map<int,Entity>` + blob；**无 archetype/SoA**（与 docs/07 远）。
- `cfg_field` 耦合 `scn::Scene` 具体字段。
- `Engine::main_loop` 有 **60s 硬上限**、无真实窗口循环/事件（SDL2 未接）。
- 测试只验"能跑"；**无确定性/回放/多实例/契约**测试。
- 模块间用 C++ 类型直连（`maque::render`、`maque::persist` 等），**没有一个真 `.so` 边界**。

## 5. 根因

一路以"纵向切片优先"，且**越过了地基的硬约定**（`.so` / C ABI / 多实例 / 绑定生成），
先做了"能看见结果"的 WebGPU 球。于是：**demo 好看，但与主干（浏览器/插件/确定性/可观测/控制面）脱节**。

## 6. 纠正计划（按优先级）

### P0 · 把地基纠正回来（**先做，否则越走越偏**）
1. **反射去全局**：`mq_reflect` 注册表移入 **per-instance context**（Engine 持有）→ 满足 ADR-0014。
2. **真插件边界**：选 1–2 个边界（**renderer** 或 **scene**）做成独立 `.so` + C ABI 版本化 vtable + registry，
   用 `maque::module` 加载 → 证明确实能 dlopen/卸载/热重载。
3. **宿主 API 生成化**：把 `log/cfg/entity_*` 等移入 `api_list`（内建 API 清单），由 codegen 生成绑定。
4. **渲染接口 C ABI 化**：`Renderer` → 版本化 C vtable；`DrawItem` 保持中立。
5. **引擎去游戏化**：渲染提取不硬编码 `Sprite`；改由**组件→绘制**的注册式提取（引擎不认具体组件）。

### P1 · 补齐 AI 五指标（引擎的"卖点"）
- **A3 确定性**：输入录制/回放 + 世界快照 + 每帧 checksum（**自主调试的根**）。
- **A2 可观测**：结构化日志 + 指标 + 崩溃上下文（含回放输入）。
- **A4 控制面**：最小 JSON-RPC（CDP 风格）+ MCP。
- **A1 自省**：反射 JSON 导出 + 查询，接入控制面。

### P2 · 引擎能力
- 场景双视图 / Prefab / 生命周期；资产管线（`ai`）+ VFS 扩充；executor/async；SDL2 接入 runtime；物理（Rapier）。

### P3 · 平台
- WASM/浏览器目标。

## 7. 立即建议

**停止堆 demo 功能，先做 P0**：反射去全局 + 一个真 `.so` 插件边界 + 宿主 API 生成 + 渲染接口 C ABI 化 + 引擎去游戏化。
这五项做完，架构才真正落在设计主线上；否则后续每个功能都会继续加重偏离。
